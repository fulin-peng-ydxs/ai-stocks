# 前端页面自适应布局规范（AI 实现约束）

> 本文是 ai-stocks 前端布局的**硬性约束文档**，面向 AI/开发在新建或改造任意页面时直接遵循。
> 技术栈：Vue 3 + Element Plus，契约样式落在 `frontend/src/styles/global.css`（`.v-page / .v-grow / .v-scroll`），外壳 `App.vue` 的 `.main` 已 `overflow:hidden` + flex 填充。
> 关联记忆：`layout-no-page-scroll`、`list-interaction-standards`、`popup-stays-in-page`。

---

## 0. 铁律（任何页面不得违反）

1. **整页/视口永不滚动**。`html/body/#app/.main` 都不出现滚动条；超高内容一律由页内"成长区"内部消化。
2. **每个滚动区有且仅有一个主滚动轴**。避免无意义的嵌套双滚动（唯一可接受的例外见 §1 兜底阶梯第 3 级的降级形态）。
3. **禁止视口硬编码高度**。不写 `height:calc(100vh - Npx)` / 固定 px 撑高；高度一律由 flex 链路自适应传导（硬编码是历史 bug 根源）。
4. **状态切换不抖动**。loading / empty / error / 正常态占据同一尺寸的盒子，不引起布局位移。
5. **操作区固定、内容区自适应**。操作区（标题/筛选/操作栏/分页）按内容取高、不被挤压；剩余空间全部给主内容区。

---

## 1. 核心模型：两层 + 兜底阶梯

### 第一层：页面外壳（永不滚动）
- 最多两个区：① 固定「操作区」；② 「主内容区」填满剩余空间。
- 操作区出现或变高（如多选后冒出批量操作栏、筛选条展开），主内容区自动缩小 → 内部滚动，整页不滚。
- **例外**：无明确"操作→内容"上下级关系的页面（各区平级，如数据采集/工作台多面板），跳过这层拆分，整个 body 直接按第二层处理。

### 第二层：主内容区（允许内部滚动）
每个组件先声明两个尺寸：
- **理想高宽**：内容舒展时的目标尺寸。
- **业务最低高宽**：低于它就影响使用的下限（见 §3 目录）。

放置规则（按内容多少递进）：
1. 单组件 → 填满整个区。
2. 多组件 → 以"每个 ≥ 自己最低尺寸"为约束排布。
3. **放得下**（各最低尺寸之和 ≤ 可用空间）→ 富余空间交给"主列表/表格/主图"去 grow，固定块保持自然高。
4. **放不下** → 走兜底阶梯。

### 兜底阶梯（按顺序取第一个可行项，不可跳级）
1. **组件内部滚动**（首选）：列表/表格 `height:100%` 表体内滚 + 表头吸顶；"固定分析块 + 一个主列表"组合直接用这条。
2. **重排为多列 / 综合排布**（条件触发，详见 §5）：仅当 (a) 视口有富余宽度 + (b) 拆列后每个组件仍满足最低宽度 + (c) 组件是无强阅读顺序的平级块。本质"拿宽度换高度"。
3. **主内容区整体滚动**（最后兜底）：以上都放不下时，区域整体 `overflow:auto`，绝不裁切。

> ⚠️ **单个体量很大的列表/表格不要重排**——重排省不了它本身的高度，直接走第 1 步内部滚动；"挪椅子"解决不了"东西本来就多"。

## 2. 决策流程（AI 实现时按此走）

```
1) 这一屏有没有"操作→内容"的上下级关系？
   有 → 顶部固定操作区，下方主内容区填满（第一层）。
   没有 → 整个 body 当主内容区。
2) 主内容区里数清"组件"个数与各自的【业务最低高宽】（查 §3）。
3) 各最低尺寸之和 ≤ 可用空间？
   是 → 富余空间分给主列表/主图 grow；固定块保持自然高。完成。
   否 → 进兜底阶梯：
        a. 有"固定块 + 主列表/表格"？→ 列表内部滚动（表头吸顶）。多半到此结束。
        b. 仍放不下 & 满足 §5 三条件？→ 重排多列。
        c. 仍放不下？→ 主内容区整体 overflow:auto。
4) 校验：每个滚动区仅一个主滚动轴；无整页滚动；状态态不抖动（§7）。逐条过 §9 红线 + §10 自检。
```

## 3. 常见业务组件：最低尺寸与自适应行为目录

| 组件 | 业务最低尺寸 | 自适应行为 | 滚动归属 |
|---|---|---|---|
| **数据表格**（分页列表） | 表头 + ≈6–8 行 + 分页条（约 `min-height:300px`） | 占满成长区；`height="100%"` 表体内滚、**表头吸顶**；分页条固定底部不随表体滚 | 表体纵向内滚 |
| **宽表格**（列多） | 关键列可读宽度 | 优先**冻结首列/操作列**，列区横向内滚；不要让整页横滚 | 表体横向内滚 + 纵向内滚 |
| **筛选/搜索栏** | 单行；多条件可换行 | 固定在操作区；条件多时支持"展开/收起更多"，收起态只占一行 | 不滚 |
| **批量操作栏** | 一行 | 仅在选中时出现；出现时挤压主内容区→内部滚动，整页不滚 | 不滚 |
| **表单（创建/编辑）** | 一组字段可见 | 长表单字段区内部滚动；**底部操作按钮固定吸底**，标题固定吸顶 | 字段区纵向内滚 |
| **KPI/指标卡片网格** | 单卡可读（≈高 80–110px） | 响应式网格 `auto-fit/minmax`，宽屏多列、窄屏少列；自然高 | 随所在区 |
| **图表** | 可读最低高（折线≈260px、迷你图≈120px） | 取自然高或固定宽高比；**必须有 min-height** 否则被压扁不可读 | 不滚（随区滚） |
| **主从（列表+详情）** | 左列表 ≈280px 宽、右详情 ≈420px 宽 | 左右两栏各自独立纵向滚动；窄屏退化为"列表↔详情"二级页 | 两栏各自内滚 |
| **树形导航/目录** | 可见若干层级 | 固定宽度面板，内部纵向滚动；可折叠收起 | 面板内滚 |
| **标签页 Tabs** | tab 条一行 | tab 条固定吸顶；**每个 tab 的内容区是一个新的第二层**，独立套用本规范 | 内容区内滚 |
| **折叠面板 Collapse** | 标题行 | 展开内容增高 → 由所在成长区滚动吸收；不得撑破整页 | 随区滚 |
| **步骤向导 Steps** | 步骤条一行 | 步骤条固定吸顶 + 内容区内滚 + 底部"上一步/下一步"固定吸底 | 内容区内滚 |
| **看板 Kanban** | 列宽 ≈260–320px | 列容器横向滚动；**每列内部纵向滚动**（列头固定） | 横向滚 + 列内纵滚 |
| **抽屉 Drawer / 弹窗 Dialog** | 见 §4-H | 覆盖层不撑动页面；内部 header/footer 固定、body 内滚；不超出视口 | body 内滚 |
| **详情页** | 关键信息首屏可见 | 顶部摘要/操作吸顶 + 下方分区内容整体滚动；可选右侧栏 | 内容区内滚 |
| **时间线 / Feed** | 若干条可见 | 纵向内部滚动；分页或无限加载 | 纵向内滚 |

## 4. 常见页面原型与推荐布局

- **A. 列表页（最高频）**：`筛选栏(固定) + 工具/批量栏(固定) + 表格(grow·表体内滚·表头吸顶) + 分页(固定)`。对应 `.v-page` 根 + 表格卡挂 `.v-grow`。
- **B. 主从页**：`工具栏(固定) + [左列表 | 右详情] 两栏各自内滚`。窄屏（<1024）退化为列表页 → 点击进详情。
- **C. 仪表盘/概览**：`KPI 卡片网格 + 图表网格`，响应式 grid 重排；整体放不下 → 区域整体滚动（§5）。
- **D. 表单/编辑页**：`标题(吸顶) + 字段区(内滚) + 操作按钮(吸底)`。分组多时用锚点/分段。
- **E. 详情页**：`摘要+操作(吸顶) + 分区内容(内滚)`，可加右侧信息栏。
- **F. 分析工作台（如回测）**：`操作/参数区(固定) + 混合成长区`。混合成长区 = 上半固定分析块（绩效卡/图/小表，`flex:0 0 auto` 自然高）+ 底部主表格（`flex:1` + 业务最低高 + 表体内滚）；容器 `overflow:auto` 兜底。**参见 `BacktestView.vue` 的 `.results`**。
- **G. 向导页**：`步骤条(吸顶) + 内容(内滚) + 导航按钮(吸底)`。
- **H. 弹窗/抽屉内布局**：`header(固定) + body(overflow:auto 内滚) + footer 按钮(固定)`；最大高度受限于视口（如 `max-height:85vh`），内容超高时只 body 滚，不顶穿视口。遵循 `popup-stays-in-page`：弹出层不溢出到左侧菜单。
  - ⚠️ **teleport + scoped 样式的坑（务必注意）**：`el-dialog/el-drawer` 默认 teleport 到 `<body>`，弹层根元素**不会带上组件的 `data-v-xxx` 作用域属性**。因此 `scoped` 块里写 `.my-drawer :deep(.el-drawer__body){…}` 这类「以自定义类为前缀」的规则**永不匹配**（弹层根没有 `data-v` → `.my-drawer[data-v-x]` 选不中），表现为「改了没反应、body 仍是默认 `display:block`」，且常因 Element Plus 自带 `overflow:auto` 而不报错、肉眼难察。
    - **正解**：给弹层传一个**唯一自定义类**（如 `class="log-drawer"`），把针对**组件库内部元素**（`.el-drawer__body`/`.el-dialog__body` 等）的规则放进**非 `scoped`** 的 `<style>` 块：`.log-drawer .el-drawer__body{ display:flex; flex-direction:column; height:100%; min-height:0 }`。类名唯一 → 不污染全局。
    - **注意区分**：写在默认插槽里的**自己的元素**（如 `.log-meta`/`.log-body`）由父组件渲染，**会带作用域属性**，scoped 规则正常生效；只有「组件库自己生成的元素」够不到。要让 body 内「meta 固定 + 日志区填满内滚」成立，必须先让 `.el-drawer__body` 变成 flex 列（上面的非 scoped 规则），否则插槽里子元素的 `flex:1` 因父级是 `block` 而失效。

## 5. 重排多列（响应式综合排布）规则

**何时用**：兜底阶梯第 2 级，且**同时满足三条件**——
1. 视口有富余宽度（宽屏）；
2. 拆成多列后**每个组件仍满足最低宽度**（列多的表、会被压扁的图就别拆）；
3. 组件是**无强阅读顺序的平级块**（有 top→bottom 因果/叙事顺序的不拆）。

**何时不用**：单个大列表/表格（重排无效）；有强阅读顺序；任一组件会跌破最低宽度。

**推荐断点**（可按页面微调，优先用容器查询，其次媒体查询）：
- `< 1024px`：单列堆叠（移动/窄屏）。
- `1024–1440px`：两列。
- `> 1440px`：可三列（仅卡片/图表这类等价平级块）。

**实现**：CSS Grid `grid-template-columns: repeat(auto-fit, minmax(<min宽>, 1fr))` 或断点切换列数；窄屏自动回落单列。不要用绝对定位/手算坐标拼多列。

## 6. 滚动与吸顶规则

- **滚动归属唯一**：一个可视区域只有一个主滚动条；嵌套滚动仅允许"§1 阶梯第 3 级降级形态"（外区滚动 + 内表仍内滚），此时内表最低高须≥可正常用（≈6–8 行）。
- **吸顶/吸底**：表头、分区标题、表单底部操作栏、tab 条、步骤条应固定，不随内容滚走。
- **横向滚动**：仅用于宽表格（优先冻结列）和看板；其余场景不得出现横向滚动条。
- **滚动容器留白**：滚动区右侧预留滚动条宽度（如 `padding-right:2px`），避免内容跳动。

---

## 7. 状态占位与无布局抖动

- loading / empty / error / 正常态**占据同一尺寸盒子**，切换不引起跳动；表格 loading 用遮罩而非替换高度。
- 空态（`el-empty`）放在成长区内居中，不改变整体高度结构。
- 异步内容到达前预留骨架/占位高度，避免"内容一来就跳一下"。

## 8. 技术契约（本项目落地写法）

- **页面根**挂 `.v-page`：`height:100% + display:flex + flex-direction:column + overflow:hidden`；直接子元素默认按内容高 = 固定区。
- **列表/表格成长区**挂 `.v-grow`：`flex:1 1 auto + min-height:0`；内部 `el-table` 用 `height="100%"`（**禁止** `calc(100vh - Npx)`）。
  - ⚠️ **`.v-grow` 只给"单表格卡"用**。它在 global.css 里会给**每个直接子 `.el-card` 和内部 `.el-table` 强加 `flex:1 1 auto`**（为"表格撑满高度 + 表体内滚"设计）。
- **长内容成长区**挂 `.v-scroll`：`flex:1 1 auto + min-height:0 + overflow:auto`。它**不拉伸子元素**，子项按自然高从上往下排、整体滚动。
- **混合成长区**（固定块 + 一张主列表/主表共存）：容器 `overflow:auto + display:flex + flex-direction:column`；固定块 `flex:0 0 auto` 取自然高；主表卡 `flex:1 1 auto` + 业务最低高（如 `min-height:320px`）+ 内部 `el-table height="100%"` 表体内滚。够放→主表 grow 填满+内滚；不够→容器整体滚动不裁切。已在 `BacktestView.vue` `.results` 与 `OverviewView.vue` `.overview-scroll` 落地。
  - ✅ **三选一判定（关键，按"有没有单一主表"分流）**：
    1. 成长区**就是一张要撑满的表**（前面无大块固定内容）→ `.v-grow`（表卡 `height="100%"` 表体内滚）。
    2. 成长区是**固定分析块 + 一张主表/主列表**（KPI/分析卡/资产表 + 一张分页表，如数据概览）→ **混合成长区**（上一条写法），**不是** `.v-scroll`。主表必须 `min-height + 表体内滚`，否则分页选 50/100 会把页面向下撑、主表被挤到不足最低高。
    3. 成长区是**纯长内容、无单一主表**（说明卡流、表单、多个等价小块）→ `.v-scroll` 整体滚动即可。
  - ⚠️ 别把场景 2 当场景 3 用 `.v-scroll`（整体滚动是兜底阶梯第 3 步、最后兜底，不是首选）；也别把场景 2/3 误挂 `.v-grow`——`.v-grow` 会给**每个直接子 `.el-card`/`.el-table` 强加 `flex:1 1 auto`**，把多卡片一起拉伸、留空白、分页顶底。自定义 `overflow:auto` 盖不住 `.v-grow` 的拉伸。
- **固定区**（标题/筛选/操作栏/分页）无需额外类；操作区显式 `flex:0 0 auto` 更稳。
- 所有 flex 链路上的滚动祖先记得 `min-height:0`，否则 flex 子项无法收缩导致溢出。

## 9. 反模式清单（红线，出现即不合格）

- ❌ 整页/视口出现滚动条（doc/main 滚动）。
- ❌ `height:calc(100vh - Npx)` 或任何视口硬编码撑高。
- ❌ 同一区域出现两条都需要拖动的滚动条（非降级场景）。
- ❌ 表格用整页滚动代替表体内滚、表头不吸顶。
- ❌ 把单个大表格"重排成两列"试图省高度。
- ❌ 多卡片内容误挂 `.v-grow`——卡片/表被 `flex:1` 拉伸、表体留空白、分页顶到底（见 §8 三选一判定）。
- ❌ "固定块 + 一张主表"场景用 `.v-scroll` 整体滚动代替混合成长区——主表失去 `min-height`/表体内滚，分页选 50/100 时页面被向下撑（整体滚动是兜底第 3 步，非首选；见 §8 场景 2）。
- ❌ 弹窗/抽屉内容顶穿视口或把页面撑出滚动条。
- ❌ 在 `scoped` 块里用「自定义类前缀」给 teleport 弹层的库内部元素（`.el-drawer__body`/`.el-dialog__body`）写样式——作用域属性不到弹层根，规则静默失效（见 §4-H，应放非 scoped 块）。
- ❌ loading/empty 切换导致布局跳动。
- ❌ 把列多的宽表硬塞进窄列，列被压到不可读。
- ❌ flex 链路缺 `min-height:0` 导致溢出而非内滚。

## 10. 交付前自检清单（AI 逐条核对）

- [ ] 1100×620 等小屏下，整页（doc/main）不出现滚动条。
- [ ] 操作区固定、不被内容挤压；主内容区填满剩余。
- [ ] 每个滚动区只有一个主滚动轴；表头/操作栏正确吸顶吸底。
- [ ] 表格走表体内滚 + 表头吸顶，分页固定底部。
- [ ] 兜底按"内部滚动 → 满足条件才重排 → 整区滚动"的顺序，没有跳级。
- [ ] 重排多列的三条件都满足；窄屏正确回落单列。
- [ ] 无 `calc(100vh-…)` 硬编码；flex 链路 `min-height:0` 齐全。
- [ ] loading/empty/error 与正常态同尺寸，无抖动。
- [ ] 弹窗/抽屉内部 header/footer 固定、body 内滚、不顶穿视口。
- [ ] 针对 teleport 弹层库内部元素的样式放在**非 scoped** 块（唯一自定义类前缀），并已实际打开弹层确认规则生效（非仅看代码）。
- [ ] 改动 `frontend/src` 后已执行 `npm run build`（见 `feedback_build_after_change`）。
