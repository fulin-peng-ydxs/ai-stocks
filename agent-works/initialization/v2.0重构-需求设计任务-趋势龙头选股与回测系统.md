## 0. 已确认的关键决策

| 编号 | 决策点 | 结论 |
|---|---|---|
| D1 | 技术指标存储 | **删除 `indicator` 预计算值表**，指标全部动态实时计算；单次运行内做**内存缓存**复用，平衡性能。 |
| D2 | 股东数据 | **本期暂不纳入**（股东数 / 股东数变化）。注册表预留扩展点，接入数据源后登记即可。 |
| D3 | 评分模型 | **阈值打分 + 动态权重**：每个指标产出 0~100 达标分（布尔=0/100；数值=分段阈值映射），各指标百分比权重总和=100%，调一个其余按比例自动重分配；综合分=Σ(达标分×权重%) 降序排名。 |
| D4 | 回测卖出逻辑 | **卖出指标组合命中为主 + 可选止盈/止损/最大持仓兜底**。 |
| D5 | 个股查询信号 | 展示 **"当前选定买卖方案"在该股上的买卖信号**（不再是硬编码买点/风险）。 |
| D6 | 观察池 | **废除**（页面、表、流程、API 全部移除）。 |
| D7 | 每日榜单 | 保留排行，**移除买点列、风险标记列**，改为"按选定评分方案排序"。 |

## 第一部分 · 需求

### 1. 背景与目标

v1.0 已完成数据底座、指标引擎、筛选/评分/榜单、回测、买点/风险/观察池全链路（已封档）。
实际使用反馈：**太虚（功能堆砌价值不清）、太杂（模块重叠）、太死（指标/买卖/评分全硬编码，改个参数要动代码）**。

v2.0 不做新增大功能，而是 **重构收敛**，核心三点：

1. **统一基座**：技术指标成为唯一的"原子定义"，买卖、评分、筛选都从它组合而来。
2. **配置化**：买卖怎么买怎么卖、评分用哪些指标多少权重，全部在页面配置、可存方案，不动代码。
3. **闭环化**：数据问题在"数据管理"页面解决；筛选→买卖方案→回测→评分验证形成可操作闭环。

### 2. 模块总览（6 模块）

| 模块 | 动作 | 一句话职责 |
|---|---|---|
| 数据管理 | **重构** | 数据采集闭环：状态/手动同步/补数/质检/修复，页面解决一切数据问题 |
| 配置管理 | **新增** | 三大定义管理：技术指标、买卖指标、评分规则 |
| 策略筛选 | **重构** | 可视化构建 + 表达式融合，指标来自配置，支持动态参数与方案保存 |
| 回测验证 | **重构** | 策略回测（筛选方案+买卖方案）/ 评分验证（评分方案有效性） |
| 个股查询 | **保留+适配** | 行情/指标/"当前买卖方案"信号 |
| 每日榜单 | **保留+精简** | 评分规则排行，移除买点与风险 |
| ~~观察池~~ | **废除** | — |

### 3. 功能需求明细

#### 3.1 数据管理（采集闭环）
- FR-DM-1 数据概览：最新交易日、覆盖股票数、日线行数、缺口提示、质检问题数。
- FR-DM-2 **手动触发同步**：增量 / 全量更新，**异步任务 + 进度条**（现状只能命令行 `python -m backend.cli update`）。
- FR-DM-3 **缺口补数**：检测指定股票/区间缺失并一键补拉。
- FR-DM-4 **质检与修复**：质检问题列表 + 针对单条问题的"重拉 / 重算"操作；并补 API 暴露已实现的 `DataVerifier`（交叉校验体检），页面可一键触发体检（v1.0 仅 CLI / pipeline `verify=True` 默认关）。
- FR-DM-5 数据源状态：akshare / baostock 连通性与基本配额提示。
- FR-DM-6 采集日志：保留时间线展示。
- FR-DM-7 **定时采集管理**：现有 APScheduler 每交易日 18:00 跑 DailyPipeline（含数据采集），默认关闭且随 Web 进程启动。页面提供 开/关、执行时间设置、下次触发时间、最近执行结果 的查看与控制。

#### 3.2 配置管理（新增，三大定义）
- FR-CFG-1 **技术指标**：注册表浏览（名称/类型/可配参数/方向/说明）；支持配置默认参数；预留自定义/扩展。
- FR-CFG-2 **买卖指标**：买入条件 + 卖出条件（技术指标 AND/OR 组合）+ 可选兜底（止盈/止损/最大持仓）；**买卖成对，保存为一个方案**；可增删改查、版本化。
- FR-CFG-3 **评分规则**：选若干技术指标，每个配阈值打分规则与权重百分比（总和 100%，动态再平衡）；保存为方案；可设默认方案供每日榜单使用。

#### 3.3 策略筛选
- FR-SCR-1 字段来源改为读取技术指标注册表（动态，去掉硬编码 13 字段），下拉/标签**显示中文名称**（注册表 `name_cn`）。
- FR-SCR-2 支持指标动态传参（如 MA(N)、HHV 窗口可调）。
- FR-SCR-3 **完全融合为一套统一条件构建器，无"可视化/表达式"模式切换**：一棵 AND/OR 条件树，每个叶子节点可就地选择「指标条件（中文指标 + 比较符 + 值/参数）」或「表达式」，二者同树共存、底层同一份 AST。
- FR-SCR-4 方案保存复用 `screen_profile`；运行返回命中票池 + 评分。

#### 3.4 回测验证
- FR-BT-1 **策略回测**：选 筛选方案 + 买卖方案 + 本金/Top N，输出净值曲线、绩效指标、逐笔成交（卖出原因显示命中的卖出指标/兜底）。
- FR-BT-2 **评分验证**：选 评分方案 + 持有期/收益阈值，输出分层命中率矩阵与超额命中率（验证"高分组更易涨"）。
- FR-BT-3 历史记录命名：`{方案名}·{时间段}·{类型}`，列表一眼看清方案与类型。

#### 3.5 个股查询
- FR-STK-1 行情 K 线（保留）。
- FR-STK-2 指标快照改为读注册表（动态）。
- FR-STK-3 信号展示改为"当前选定买卖方案"在该股上的买/卖点标记（D5）。
- FR-STK-4 **股票分组（篮子）**：列表多选（跨分页/跨搜索累积）→ 存为新分组 / 加入已有分组（分组名 + 建组日期 + 说明）；选中分组只查该组股票，展示「加入日期 / 最近涨幅」及**整组等权涨幅**；各股以**加入日**为涨幅基准；分组可改名/删除/增删成员。
- FR-STK-5 **个股详情通用导航**：上一个 / 下一个 + 可搜索成员直选，遍历"当前集合"（分组成员 / 列表勾选 / 查询结果），集合持久化（刷新不丢）。
- FR-STK-6 **列表基础交互**：按交易日展示当日涨跌幅（选日自动查询）；板块含 主板/创业板/科创板/ST/退市，非退市板块默认排除退市，可勾选「排除 ST」（ST/退市板块下隐藏该项）；状态列显示 正常/ST/退市；**服务端排序**（涨跌幅默认正序、NULL 末尾，跨全量而非当前页；名称/行业/代码可排序）。

#### 3.6 每日榜单
- FR-BD-1 按选定评分方案排序，顶部可切换评分方案。
- FR-BD-2 移除买点列、风险标记列；保留 综合分、评级、分项达标分展示。

#### 3.7 废除观察池
- FR-WL-1 删除页面、菜单、`watchlist_history` 表、`update_watchlist()`、pipeline 第 4 步、`/api/watchlist` 及前端调用。

## 第二部分 · 设计

### 4. 架构变化总览

```
                ┌─────────────────────────────┐
                │   技术指标注册表 (新基座)     │  ← 动态计算，无值表
                │   MA/HHV/市值/量/涨幅/RS...   │
                └───────┬─────────┬────────────┘
        ┌───────────────┼─────────┼───────────────┐
        ▼               ▼         ▼               ▼
   策略筛选        买卖指标方案  评分规则方案     个股查询
   (AST 组合)      (买AST+卖AST) (指标+权重)     (信号/快照)
        │               │         │
        └───────┬───────┘         │
                ▼                  ▼
            策略回测           评分验证 / 每日榜单
```

- **删除** `indicators/engine.py` 的"全市场预计算落库"职责，保留 `operators.py`/`compute.py` 的算子能力，改造为**按需计算 + 缓存**。
- 复用现有 `screening/`（AST + 表达式引擎质量好），扩展到买卖场景。

### 5. 技术指标：定义/管理（实际实现）

- **删除 `indicator` 值表**；指标全部动态实时计算（`IndicatorEngine`，向量化全市场 + 单次运行内存缓存）。
- **指标定义表 `indicator_def`（非值表）**：统一管理内置 + 自定义指标的"定义"。每条登记
  `key / name_cn / dtype(bool|number) / kind(builtin|expr) / expression(表达式模板) / params(参数schema) / categories(多分类JSON) / direction / enabled / is_builtin / desc`。前端下拉/标签均显示 `name_cn`。

**两类计算路径（关键）**
- **内置·向量化列(kind=builtin)**：`compute_market_indicators` 一次性算全市场固定列（快，~8s 全市场、缓存后≈0），参数由全局配置固定。
- **表达式型(kind=expr)**：保存带 `{参数}` 占位的 DSL（复用 `screening/expression.py` 沙箱：`MA/HHV/LLV/REF/COUNT/SUM/ABS` + `C/O/H/L/V/TURN`），用时渲染参数→**逐股点时求值**（每个约 2-3s/全市场）。
- **结论：参数能否放开 = 性能取舍，不是做不到。** 任何窗口/阈值类指标都可做成 expr 暴露参数（代价是逐股略慢）。

**参数化核对结论（实测）**
- 真正受限只有 **RS 相对强度**：它是**全市场横截面排名**，逐股引擎算不了 → 窗口为全局配置、不支持逐方案传参（这是唯一真正的"截面/向量化"限制）。
- 已修正历史问题：`ma/hhv`(曾假参数报错)、`pct_change/vol_change_pct`(曾幽灵不可用) 均改 expr、参数真生效；`rs_pct` 去掉假参数；`total_mv` 数据未入库 → 禁用。

**可传参指标（expr，参数实测生效）**：日均线 `ma(period)`、N日最高 `hhv(window)`、N日涨幅 `pct_change(n)`、成交量变化幅度 `vol_change_pct(window)`、MA乖离率 `ma_bias(n)`、贴近均线 `near_ma(n,tol)`、跌破均线 `below_ma(n)`、站上均线 `above_ma(n)`、平台突破 `platform_break(n)`、放量突破 `vol_break(n,x)`、创N日新高 `new_high(n)`、均线向上 `ma_up(n,k)`、连续上涨/下跌 `consec_up/down(n)`。

**常用固定均线（无参，直接用）**：`ma5 / ma10 / ma20 / ma30 / ma50`（expr `MA(C,N)`，5/10/20 命中向量化列免算）。

**无参内置（合理）**：多头排列、各期新高布尔(120/1y/2y)、换手健康/换手率、距两年高、流通市值、成交量、站上年线、MA20/60向上、及固定版 `放量突破(固定20×2)`、`平台突破(固定60)`。

**预留/禁用**：总市值(数据未入库)、股东数/股东数变化(D2)、距除权日(待接入)。

**多分类标签（categories，可多选 + 自定义命名）**
- 预设角度：趋势 / 动量 / 量能 / 位置 / 均线 / 突破 / 估值 / 换手 / 形态 / 强度 / 新高 / 事件 / 筹码（一个指标可属多类）。
- 用户可在「技术指标」页为任意指标增删分类、或直接输入新分类名（存库覆盖预设，`set_categories`）。

**「技术指标」管理页能力**：搜索(名称/标识/说明/分类)、排序(名称/类型/来源/有无参数)、分类列内联多选编辑、内置只读+启停、自定义新建(表达式+参数+说明+分类)/删除。

> 性能注记：单日筛选/榜单可接受；**多年全市场回测**用动态指标偏重且单连接串行会阻塞他人（已记 R1，归 M2.5 处理：窗口化预计算 / 独立只读连接 / 区间上限）。

### 6. 买卖指标方案

- 新表 `trade_profile`（买卖**成对**存一条）：
  - `id, name, version, buy_ast(JSON), sell_ast(JSON), backstop(JSON: take_profit/stop_loss/max_hold_days 可空), is_preset, created_at, updated_at`
  - 版本表 `trade_profile_version`。
- `buy_ast` / `sell_ast` 复用 `screening/condition.py` 的 AST 结构与 `expression.py` 引擎。
- 回测中：
  - 买入信号 = `buy_ast` 在 T 日命中（配合筛选方案的票池取交集，或筛选方案作为票池来源）。
  - 卖出信号 = `sell_ast` 命中 **或** 触发 backstop 兜底（止盈/止损/到期），先到先卖（D4）。
- 重构/废弃 `signals/buypoint.py`、`signals/risk.py` 的硬编码逻辑（能力并入 AST/注册表）。

### 7. 评分规则（阈值打分 + 动态权重，D3）

- 改造 `score_model` → `score_profile`（+ `score_profile_version`）：
  ```json
  {
    "name": "我的趋势分",
    "items": [
      {"indicator": "rs_pct", "params": {"window": 20},
       "weight": 0.4,
       "scoring": {"type": "band", "bands": [[90,100,100],[80,90,75],[60,80,50],[0,60,0]]}},
      {"indicator": "bull_arrange", "params": {},
       "weight": 0.3,
       "scoring": {"type": "bool"}},                       // 满足=100 / 否=0
      {"indicator": "dist_to_high", "params": {"window": 480},
       "weight": 0.3,
       "scoring": {"type": "linear", "min": 0.30, "max": 0.0}}  // 越近满分(lower_better)
    ]
  }
  ```
- **达标分映射**（每指标产出 0~100）：
  - `bool`：满足 100 / 否 0。
  - `band`：分段阈值，落在哪段给哪分（你可配）。
  - `linear`：在 [min达标, max满分] 间线性映射到 [0,100]，按方向裁剪。
- **权重约束**：`Σ weight = 1.0`。前端滑杆调一个，其余按比例**自动再平衡**到总和 100%。
- 综合分 = `Σ(达标分_i × weight_i)`，全市场降序 → 每日榜单 / 回测评分验证共用。

### 8. 策略筛选（融合为一套）
- **单一条件树构建器**，无模式切换：树节点为 AND/OR 分组，叶子节点二选一——
  - 「指标条件」：中文指标(name_cn) + 参数输入 + 比较符 + 阈值；
  - 「表达式」：自由表达式（DSL 沙箱）。
  - 两类叶子在同一棵树里混用，底层统一序列化为现有 `screen_profile` 的 AST（`col` / `expr` 叶子）。
- 运行：`ScreenEngine.run_ast(ast, run_date, universe)`（保留），叶子字段解析改走注册表实时计算。

### 9. 回测验证（重构）

| 类型(新命名) | 输入 | 输出 |
|---|---|---|
| **策略回测** | 筛选方案 + 买卖方案 + 本金 + Top N + 区间 | 净值曲线(组合 vs 基准)、绩效卡(总收益/年化/回撤/夏普/卡玛/胜率…)、逐笔成交(卖出原因=命中的卖出指标或兜底) |
| **评分验证** | 评分方案 + 持有期(1/5/10/20) + 收益阈值 | 分层命中率矩阵 + 超额命中率(高分组 vs 基线) |

- `backtest_run.kind` 取值改为 `strategy` / `score_check`；新增 `trade_profile_id`、`score_profile_id` 关联列。
- **去重/复用（M2.5 增补）**：`backtest_run` 增 `signature`（全条件指纹：日期+三方案及各自版本+所有数值参数）+ 三方案 `*_version` 列。运行前 `POST /api/backtest/prepare` 查同签名历史；命中则前端弹框"加载历史 / 重新回测（覆盖）"——**每个条件组合的历史记录唯一**（重跑覆盖旧记录）。
- **评分验证落库（推翻"即跑即看不入历史"）**：`score_check` 同样落库进历史、可加载、参与去重。历史下拉**按 kind 分别加载**（策略与评分验证不混展）。
- 历史命名：`评分方案(版本)-筛选方案(版本)-买卖方案(版本)·年份`（评分验证仅评分方案部分；空方案占位"全市场/旧固定模型/旧式卖出"）。
- **交易回放增强（M2.5 增补）**：① 买入档为"-"（综合分未达观察阈值仍因排名买入）→ 显示 `无评级·XX分`（`backtest_trade.entry_score`）；② 卖树**部分命中**时卖出原因展示**具体命中指标 tag**（`backtest_trade.exit_detail`），全命中=「卖出信号」；③ "查看当日榜单"用本次回测所选 `score_profile` 打分（`/board/compute` 接 `score_profile_id`），与 `entry_rank` 同口径，高亮买入票并自动滚动、不在 Top50 给提示。
- **稳健性测试（并入策略回测的高级选项）**：复用已实现的 `backtest/robustness.py`，提供"参数敏感性扫描 + 样本内外切分"开关；运行后展示参数-绩效曲线与样本内/外对照，证明结果非过拟合。补 API `POST /api/backtest/robust`（即跑即看，不污染历史），前端在策略回测结果区加"稳健性"折叠面板。
- **行业集中度约束（真正实现）**：`settings.industry_max_pct` 当前定义未生效；本期在回测引擎买入环节落实——单行业持仓市值占比超过上限时跳过该票，约束可在回测输入覆盖。

#### 10.1 评分快照层（随 M2.6 一起做）
评分目前各入口（每日榜单 / 评分方案试运行 / 回测排名 `entry_rank` / 评分验证）**全部实时算**。建快照层惰性物化，统一各入口口径，避免重复计算。
- 新表 `score_snapshot`：主键 `(trade_date, profile_id, profile_version, code)`，存 `total_score / grade / rank`；子项分数按需重算不全存。
- 新表 `score_snapshot_meta`：主键 `(trade_date, profile_id, profile_version)`，存 `computed_at / stale(BOOLEAN) / n_codes`。**失效只动这张小表**（每天每方案一行），不碰百万行明细。
- **惰性物化**：某 (日期+方案版本) 首次被任意入口请求时整天打分一次落库 + 写 meta(stale=false)，之后命中即用；无需定时。`profile_version` 入键 → 改方案=新版本=自然无缓存=下次读时重算。
- **失效（惰性标记，不立即重算 —— 关键设计）**：触发器命中时**只把 meta 标 stale=true**（极便宜），**绝不立即重算**（大回补可能波及上百天，同步重算会卡死）。**读取时判定**：`get(date, profile, version)` → meta 不存在 或 `stale=true` → 当场重算该天该方案、覆盖明细、meta 置 false 后返回；否则直接用缓存。
  - 触发器1 **行情数据变更**：update/backfill/recompute 写完某些 `trade_date` 的 daily_bar/daily_metrics/复权因子后 → `UPDATE score_snapshot_meta SET stale=true WHERE trade_date IN (受影响日期)`（全部方案版本）。
  - 触发器2 **评分方案规则变更**：`score_profile` 保存产生新 version → 新键无缓存，天然惰性重算；旧版本快照保留不动（历史回测引用旧版本仍有效）。
- **数据量**（实测）：全市场 ~5,200 只 × ~243 交易日 ≈ 125 万行/年/方案版本；DuckDB 列存压缩 ≈ 15–40 MB/年/方案版本。
- 口径一致性：本层须与回测 `_decision_data` 同口径（`wide_snapshot` + 排除 ST + `ScoreProfileModel`）。已先行修复 `/board/compute` 接 `score_profile_id`，使"查看当日榜单"与回测 `entry_rank` 一致（详见变更记录）。

## 第五部分 · 风险与待确认

- R1 **回测性能 / 单连接串行**：~~并发请求卡死~~（M2.4 根治：`unregister` 补锁 + `temp_view` 唯一名）。**M2.5 已实测并决策**：全年策略回测约 45–64s；期间轻请求(/health、/stocks)平均 ~150ms、偶发最大 ~2.5s（仅某条大 SQL 持锁那一下，RLock 只在 SQL 执行期持有、pandas 计算在锁外）——单用户本地**可接受,不卡死**。故**放弃只读连接池/每线程游标**（ROI 低 + DuckDB 读写连接混用风险）。改做**低风险增益：共享 IndicatorEngine**——策略回测与分层分析复用同一区间快照缓存，区间指标只算一遍，全年回测 64s→45s（约 −30%，日志确认"指标动态计算"2 次→1 次）。如后续回测仍嫌慢，再评估"仅回测期窗口化预计算"。
- R2 **历史数据迁移**：删除 `indicator`/`watchlist_history`/`score_model` 前，确认无需保留历史值（评分/筛选结果可重算）。
- R3 **阈值默认值**：各数值指标的 band/linear 默认阈值需一份合理初值（参考 v1.0 评分逻辑）。
- Q-待确认 数值指标"阈值→分数"映射的默认值清单，开工前可由需求方微调（不影响架构）。
