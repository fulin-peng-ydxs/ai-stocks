## 1. 设计目标与原则

| 原则 | 含义 | 落地方式 |
|------|------|---------|
| **正确性优先** | 量化系统一旦有未来函数/幸存者偏差，结论全废 | 时点隔离的统一数据访问层 + 自检清单（§18） |
| **可复现** | 同输入同参数，结果完全一致 | 无随机；所有参数显式配置并随结果落库 |
| **可配置** | 改阈值/权重/参数不改代码 | 配置中心 + 筛选方案/评分模型存库 |
| **可解释** | 每个分数、每次命中都能溯源 | 落库分项分、命中明细、指标快照 |
| **分层解耦** | 数据/指标/筛选/评分/回测/接口各司其职 | 见 §3 分层；上层依赖下层，单向 |
| **单机轻量** | 单用户本地，零运维 | DuckDB 嵌入式、无需独立 DB 服务 |
| **数据源可插拔** | AKShare/baostock/Tushare 可切换互补 | 统一 `DataSource` 抽象接口 |

### 2.2 数据库为什么选 DuckDB（关键决策）
本系统是典型 **OLAP / 分析型** 负载：批量写入（每日一次）、海量读取与聚合（全市场 5000 股 × 5 年 ≈ 600 万行/年级别，多年千万行；回测要反复跨日跨股聚合）。

| 候选 | 适配度 | 说明 |
|------|--------|------|
| **DuckDB** ✅ 推荐 | 高 | 列存、向量化执行，分析聚合极快；嵌入式零运维（单文件）；与 pandas/Arrow 零拷贝互通，`SELECT` 直接出 DataFrame；单写多读，完美契合"每日批量写 + 大量分析读" |
| SQLite | 中 | 零配置但行存，千万行分析聚合慢；可作"配置/结果"轻量库，但行情分析不理想 |
| PostgreSQL/TimescaleDB | 中 | 强大但需独立服务、运维成本，单用户本地过重 |
| 纯 Parquet | 中 | 列存好，但缺事务/索引，需配查询引擎（正好 DuckDB 能直读 Parquet） |

**结论**：统一用 **DuckDB** 存全部数据（行情、指标、配置、结果）。若行情原始数据想进一步冷热分离，可把不复权日线落 **Parquet 按年分区**，DuckDB 建外部视图直读——此为可选优化，MVP 直接用 DuckDB 表即可。

> 备选：若你更想要一个"看得见的关系库"，可把"配置/结果类"小表放 SQLite，行情放 DuckDB。但为简化，本设计**单 DuckDB 文件**搞定全部。

### 2.3 指标计算为什么不用 TA-Lib
本系统 MVP 指标（MA、HHV、REF、COUNT、换手、新高、多头排列）全部是 **pandas/numpy 几行就能向量化实现**的简单算子，且 pandas 的 `rolling` 天然只看过去（防未来函数）。**TA-Lib 需要装 C 库（mac 上常踩坑），MVP 不引入**；未来若要 MACD/KDJ/布林等复杂指标，再按需引入 `pandas-ta`（纯 Python）或 TA-Lib。

### 2.4 回测引擎为什么自研
开源库（backtrader 事件驱动、vectorbt 向量化）都能用，但本系统的**真实性约束高度领域化**（一字板不能买、停牌不能卖、点时universe含退市股、信号 T 日生成 T+1 成交）。这些约束在自研引擎里**更容易写对、更容易审计、更容易写单测**。故：
- **信号质量分析（涨幅命中率）** → 纯 pandas 向量化（快，验证选股信号本身）。
- **完整策略回测（建仓/持仓/跌破 MA20 卖出/成本）** → **自研事件驱动引擎**（逐日推进，约束可控）。
- 备选：高级用户可后期接 vectorbt 加速参数扫描。

### 3.2 依赖方向
**严格单向向下**：前端→API→Service→领域层→数据访问层→存储/采集。领域层之间也分层：回测/评分依赖筛选与指标，指标依赖数据访问层。**任何"读历史数据"都必须经过数据访问层的点时安全接口**（§6.1），不允许领域层直接裸查库——这是防未来函数的架构性保证。

### 3.3 数据流（每日 EOD 主流程）
```
收盘后定时触发
  → 采集层增量拉取（AKShare 日线/指标/指数 + baostock 补退市/复权）
  → 数据质量校验（缺失/异常/复权/涨跌停/停牌标记）
  → 写入 DuckDB（幂等 upsert）
  → 指标引擎全市场逐股算指标 → 写 indicator 表
  → 对当日跑预设筛选方案 → 命中票池
  → 评分模型打分排序 → 写 score_result
  → 买点/风险标注
  → 生成当日榜单（Top N）+ 更新观察池
  → 前端可查
```

## 4. 数据库设计（DuckDB）

> 约定：日期统一 `DATE` 类型；金额单位元；价格存**不复权**原值 + 复权因子，复权价在指标层按需计算（保证口径统一、可切前/后复权）。所有写入幂等（按主键 upsert）。

### 4.3 配置与方案

**`screen_profile` 筛选方案**

| 字段 | 类型 | 说明 |

## 6. 核心算法设计（重点 ⚠️）

> 本章是整个系统**正确性的命脉**。三大杀手：未来函数、幸存者偏差、回测失真。

### 6.1 点时安全数据访问层（防未来函数的总闸门）
**设计**：所有"取历史数据"必须经 `MarketRepository`，且接口带 `as_of` 语义——给定基准日 T，只能返回 ≤ T 的数据。

```python
class MarketRepository:
    def get_bars(self, code, end_date, lookback=None, adjust="qfq") -> DataFrame:
        # 只返回 trade_date <= end_date 的行；复权在此层完成
        ...
    def get_universe_asof(self, date, filters) -> list[str]:
        # 点时股票池：list_date <= date 且 (delist_date is null or delist_date > date)
        # 再叠加 ST/次新/停牌/市值过滤
        ...
    def get_indicators_asof(self, date, codes) -> DataFrame:
        # 取 date 当日指标（指标本身计算时已只用 ≤date 数据）
        ...
```

**两条铁律**：
1. **指标计算**：所有 rolling 用 pandas `.rolling(N)`（天然后向），绝不 `shift(-k)`（未来）。`REF(X,N)=X.shift(N)`（取过去，正）。
2. **回测时序**：T 日收盘后用 ≤T 数据选股 → **T+1 开盘成交**。绝不用 T 日收盘价当成交价配 T 日选股结果（这是最常见的未来函数）。

**复权处理**：DB 存不复权 + adj_factor。前复权价 = 不复权价 × adj_factor / 最新adj_factor。技术指标统一用前复权（§需求 F-IND-02）。回测净值用真实成交价（前复权一致口径）。
> 注（一个常见误解的澄清）：有人担心"前复权会随未来分红重新锚定→引入未来函数"。本系统的布尔/水平比较类信号（新高、均线排列、突破、放量倍数、涨跌幅）都是**全局缩放不变量**——前复权对历史整体乘同一常数，比较的两边同步缩放，布尔结果不变；且**存"不复权+因子"而非存复权价，从根上避免了增量更新时旧复权价过期的问题**。故前/后复权对本系统信号无偏差，设计成立。

### 6.2 点时股票池（防幸存者偏差）
回测在每个调仓日 T 构造 universe：
```sql
SELECT code FROM stock_basic
WHERE list_date <= :T
  AND (delist_date IS NULL OR delist_date > :T)   -- 关键：含当时还在、后来退市的票
```
再叠加过滤：上市≥60交易日（硬剔除次新）、非ST（可配）、非停牌、流通市值区间、剔除一字板（可配）。
> **数据前提**：`stock_basic.delist_date` 必须准确，退市股 `daily_bar` 必须有历史——这正是引入 **baostock 补退市股** 的原因（需求附录 A）。
> **ST 时变陷阱**：ST 状态会随时间变化。理想做法是按"该日历史 ST 状态"过滤（依赖历史名称/风险警示数据）；若数据不可得，退化为"当前 ST 状态"过滤并**在结果中标注此局限**。对趋势龙头策略影响小（ST 极少成趋势龙头），但不可默认无害。

### 6.3 RS 相对强度（横截面、防未来）
RS 是**横截面排名**，需逐日在"当日存活票"内计算：
```
对每个 trade_date：
  ret = close.pct_change over W (如 W=120 日，用 ≤date 数据)   # 各股区间收益
  rs_pct = ret 在当日全市场的百分位排名 × 100
```
注意：百分位的样本是**该日点时 universe**（不含未来上市、含当时存活），否则又引入幸存者偏差。

### 6.4 回测撮合逻辑（防失真）
逐日事件驱动，单日步骤：
```
for T in 交易日序列(回测区间):
    # 1. 卖出检查（先卖后买，释放资金）
    for pos in 持仓:
        if 触发卖出(pos, T):           # 跌破MA20 / 止盈止损 / 到期
            if 可成交(pos.code, T_next):  # 非停牌、非一字跌停
                以 T_next 开盘价卖出，扣双边成本+印花税+滑点
            else: 顺延到下一可交易日
    # 2. 选股（用 ≤T 数据）
    universe = get_universe_asof(T)
    hits = screen(profile, T, universe)
    scored = score(model, T, hits)
    targets = top_n(scored, N) 去掉已持仓
    # 3. 买入（T+1 开盘）
    for c in targets:
        if 持仓数 < N and 可买入(c, T_next):   # 非停牌、非一字涨停
            以 T_next 开盘价买入，等权/按分加权，扣成本+滑点
    # 4. 估值
    记录 当日组合净值、回撤、基准净值
```
**成交约束**（比"一字板"更精确）：
- **买入**：仅当 `T+1 开盘价 < 当日涨停价` 才可成交（开盘即封涨停就买不到，不必非得一字板）。
- **卖出**：仅当 `T+1 开盘价 > 当日跌停价` 才可成交，否则顺延。
- **涨跌停价按板块/ST 计算**：`涨停价 = round(pre_close × (1+limit_pct), 2)`，limit_pct = 主板0.10 / 科创创业0.20 / ST 0.05。
- 停牌 → 不可交易；持仓停牌按停牌前价估值，复牌后处理；退市按退市规则清仓（最后交易日价或按规则计损）。
**交易规则**：买入按 **100 股整手**取整（`floor(目标金额/价格/100)*100`），余资金留存不强行满仓；可配**初始资金**；可选**单行业持仓上限**（趋势龙头常扎堆，防过度集中）。
**成本模型**（可配，方向性）：佣金双边万2.5（最低5元）+ 印花税卖出千1 + 过户费 + 滑点（买入价上浮、卖出价下浮 0.1%~0.3%）。

### 6.5 信号质量分析（验证"涨幅命中率"，与卖出规则解耦）
独立于策略回测的**纯向量化**模块，验证选股信号本身好不好：
```
对所有命中 (code, signal_date)：
  entry = T+1 开盘价(前复权)
  fwd_high = max(high[T+1 .. T+N])         # N∈{5,10,20,60}
  max_fwd_return = fwd_high/entry - 1
  hit = max_fwd_return >= X                  # X∈{10%,20%,30%}
按 score 分档(80/90/95)聚合 → 各档命中率、平均最大浮盈
```
> 这回答"分越高，N 日内摸到 X% 涨幅的概率是否越高"——即需求的**核心概率口径**。注意：用未来 N 日数据是**评估**（理应如此），不是信号生成时的未来函数。

**必须算基准命中率（base rate）**：同时计算"**同期全市场所有票**在 N 日内涨幅≥X% 的无条件命中率"作为基线。各评分分档命中率减去 base rate = **超额命中率**，这才是评分真实能力的度量。否则牛市里随便选都 60% 命中，无从判断模型好坏。同时输出每档样本量，样本过小不采信。
```
base_rate(N,X) = mean( over 全市场所有(code,date): max_fwd_return_N >= X )
分档超额 = hit_rate_grade - base_rate
```

## 7. 指标计算设计

### 7.1 计算流程
```
全量/增量触发
  → 按股取前复权日线序列（足够 lookback，如最长指标 480 日 + buffer）
  → 向量化算各指标列
  → RS 横截面：按日跨股算百分位
  → 写 indicator 宽表（带 param_hash）
```

### 7.2 指标公式映射（pandas）

| 指标 | 实现 |
|------|------|
| MA(N) | `close.rolling(N).mean()` |
| HHV(H,N) | `high.rolling(N).max()` |
| REF(X,N) | `x.shift(N)` |
| COUNT(cond,N) | `cond.rolling(N).sum()` |
| 两年新高 | `close >= high.rolling(480).max()`（不足480日→NULL不适用） |
| 多头排列 | `(ma5>ma10)&(ma10>ma20)&(ma20>ma60)` |
| 均线向上 | `ma20 > ma20.shift(5)` |
| 放量突破 | `volume > volume.rolling(20).mean()*2` |
| 平台突破 | `close > high.rolling(60).max().shift(1)`（**shift(1) 防自指**） |
| 换手健康 | `3 <= turnover_rate <= 20` |
| 流通市值过滤 | `50e8 <= float_mv <= 400e8` |

### 7.3 增量计算
仅对"新增交易日 + 受影响 lookback 窗口"重算；参数变更（param_hash 变）则该参数下全量重算。指标结果缓存于 `indicator` 表，筛选/回测直接读，不重复算。

## 8. 筛选引擎设计

### 8.1 设计要点
筛选条件是**一等公民**：可组合、命名保存、版本化、对任意历史日运行（点时安全）。
**两类叶子并存**（用户诉求）：
- **固定指标叶子（col）**：引用已预算好的指标/行情列（快，向量化截面计算），覆盖常用画像。
- **动态表达式叶子（expr）**：用 DSL 写时序表达式（`COUNT/REF/HHV/MA/算术`），点时现算，覆盖"连续上涨/缩量/三年新高"等自定义条件——无需新增指标列。

### 8.2 条件 AST（存 JSON，混合叶子）
```json
{
  "op": "AND",
  "children": [
    {"type": "col", "field": "is_bull_arrange", "cmp": "==", "value": true},
    {"type": "col", "field": "rs_pct", "cmp": ">=", "value": 95},
    {"type": "col", "field": "float_mv", "cmp": "between", "value": [5e9, 4e10]},
    {"op": "OR", "children": [
      {"type": "col", "field": "is_vol_breakout", "cmp": "==", "value": true},
      {"type": "expr", "expr": "C >= HHV(H, 720)"}
    ]},
    {"type": "expr", "expr": "COUNT(C > REF(C,1), 5) == 5"}
  ]
}
```
- `col` 叶子：`field` 取自 `indicator` / `daily_bar` / `daily_metrics` 列；`cmp` ∈ `== != > >= < <= between`。
- `expr` 叶子：布尔 DSL 表达式（见 §8.5），变量 `C/O/H/L/V/TURN` = 该股**前复权**序列，及已有指标列名。

### 8.3 执行（混合：截面向量化 + 逐股表达式）
给定日期 T 与点时 universe：
1. **col 叶子** → 取 T 日 `indicator`⋈`daily_bar`⋈`daily_metrics` 宽表，一次性算全市场布尔列（快）。
2. **expr 叶子** → 对每只股票取 `get_bars(code, T, qfq)` 序列，在 DSL 沙箱里求值，取 T 日布尔值（逐股，较慢；可缓存高频表达式）。
3. 按 AST 的 AND/OR/NOT 合并两类结果 → 命中票池。
命中明细：记录每个叶子对该股的真假与取值 → 写 `screen_result.matched/snapshot`（可解释）。

**NULL/不适用语义（关键）**：指标/表达式值为 NULL（如次新股两年新高、序列不足窗口）时，叶子**默认判 False**（不命中），可在方案级配"忽略"（视为 True）。pandas 实现先 `.fillna(False)` 再布尔合并，避免三值逻辑误判。

### 8.4 预设方案（内置）
趋势龙头、两年新高、平台突破、多头排列、回踩 MA20 买点。存为 `is_preset=true` 的 `screen_profile`。

### 8.5 表达式 DSL（安全沙箱）
- **变量**：`C/O/H/L`（前复权 开高低收）、`V`（量）、`TURN`（换手率）、以及指标列名（`ma20`/`rs_pct`/`is_bull_arrange`…）。
- **函数**：`MA(x,n) HHV(x,n) LLV(x,n) REF(x,n) COUNT(cond,n) SUM(x,n) ABS(x)`（复用 `indicators.operators`，全后向）。
- **运算**：`+ - * /`、比较 `> >= < <= == !=`、布尔 `AND/OR/NOT`（or `& | ~`）、括号、常量。
- **安全**：用 Python `ast` 解析后**白名单遍历求值**——只允许变量名/函数调用(白名单)/二元/比较/布尔/一元/常量；**禁止属性访问、下标、import、任意调用**，杜绝代码注入。
- **点时安全**：序列来自 `get_bars(code, T)` 仅含 ≤T；`REF` 拒负移；表达式天然不引用未来。
- **类型**：表达式须最终求出**布尔 Series**，取 T 日值为该叶子结果。

### 8.6 表达式性能与缓存
- **现状**：col 叶子截面向量化（全市场单日 ~0.4s）；expr 叶子逐股点时求值（全市场单日 ~13s）。
- **单次运行内已复用**：每股 `get_bars` 只取一次，该股的多个 expr 叶子共享同一序列（不重复取数）。
- **跨运行无缓存**：表达式每次现算、不落库（区别于 `indicator` 表）。交互式单日筛选可接受，**不做过早优化**。
- **真正的性能场景在 M5 回测**：需在数百个历史调仓日反复跑同一筛选，逐日逐股重算代价大。届时优化（任务 **T-M5-10**），三选一：
  1. **全历史预计算**：把回测用到的表达式在全历史算成 `(code,date,命中)` 表（动态表达式临时物化为指标列）——最快。
  2. **全市场序列入内存向量化**：面板化一次算所有日期，免逐股循环。
  3. **缓存 `get_bars`** 跨日期复用，省重复取数。

## 9. 评分模型设计

### 9.1 维度与默认权重（可配）

| 维度 | 权重 | 打分方式 |
|------|------|---------|
| 位置（新高） | 30 | 连续：两年新高=满分；否则按 `1 - dist_to_high_2y` 线性衰减 |
| 均线趋势 | 20 | 布尔组合：多头排列(12)+均线向上(8) |
| 成交量 | 20 | 启动放量(10)+持续放量(10) |
| 换手率 | 10 | 区间：落 3~20% 满分，越界衰减 |
| RS 强度 | 10 | 连续：`rs_pct/100 × 10` |
| 资金流 | 10 | **MVP 置 0** |

### 9.2 资金流缺失时的权重归一
MVP 资金流不做 → 该维度权重 0，其余维度**重新归一化到 100**（避免满分上限变 90）。归一方式可配（重分配 / 保持原值）。默认：重新归一到 100。

### 9.3 输出
`total_score`（0~100）、`sub_scores`（各维度得分，可解释）、`rank`、`grade`（≥80/≥90/≥95，阈值可配）、`risk_flags`（可成交性标记：涨停/跌停/一字板，T-M6 完整风险识别前的部分交付）、`buy_point`（M6 买点识别后填充，当前留空）。

> **榜单排除 ST**：`rank_board` 落库前按 `stock_st_status_daily` 准确点时事实剔除当日 ST；缺失、非权威或刷新未发布时失败关闭。落库采用**整日全量替换**（先 DELETE 当日 `score_result` 再写），避免退榜/被剔除股残留旧行。

### 9.4 有效性约束
评分模型**必须经回测 §10.5 分层验证**：高分档"N 日涨幅≥X% 命中率"显著高于低分档与基准，否则视为无效模型，回炉。

## 10. 回测引擎设计

### 10.1 输入参数（来自 backtest_run.params）
区间、调仓周期、持有期、Top N、**初始资金(默认100万)**、买入价(次日开盘)、卖出规则(默认跌破MA20)、资金分配(等权)、**整手约束(100股)**、**单行业持仓上限(可选)**、成本参数(方向性滑点)、基准(中证500)、信号口径(N/X 多档)。

### 10.2 两条回测路径

| 路径 | 目的 | 实现 |
|------|------|------|
| **A. 信号质量分析** | 验证选股信号（与卖出规则无关） | 向量化前向收益 + 分档命中率（§6.5） |
| **B. 完整策略回测** | 算真实收益曲线 | 事件驱动撮合（§6.4） |

### 10.3 Broker（撮合）职责
持仓管理、可买可卖判定（涨跌停/停牌）、成本计算、资金记账、净值估值。

### 10.4 绩效指标
累计/年化收益、最大回撤+持续期、年化波动、夏普、卡玛、索提诺、胜率、盈亏比、平均持有天数、换手、相对中证500超额。

### 10.5 分层与稳健性
- **分层**：按 grade(80/90/95) 分别统计后续收益、胜率、"N日涨幅≥X%命中率"，**并减去同期全市场 base rate 得超额命中率**（§6.5），附样本量。
- **稳健性**：参数敏感性（均线周期/放量倍数/持有期/TopN 微调）、样本内外切分、对照组（随机选 N 只 / 全市场等权）。

### 10.6 输出落库
`backtest_trade`（逐笔）、`backtest_equity`（曲线）、`backtest_metrics`（指标 + 分档命中率 JSON）。

## 16. 关键技术决策与权衡（汇总）

| 决策 | 选择 | 主要权衡 |
|------|------|---------|
| 数据库 | DuckDB 单文件 | 分析快、零运维 vs 不擅高并发写（本系统不需要） |
| 指标库 | pandas/numpy 自实现 | 零安装坑 vs 复杂指标后期再引 pandas-ta |
| 回测 | 自研事件驱动 + 向量化信号分析 | 约束可控可审计 vs 自己写工作量（用单测兜底） |
| 复权存储 | 存不复权+因子，按需算前复权 | 口径统一可切换 vs 每次算（缓存指标解决） |
| 指标存储 | 宽表 + param_hash | 查询快、可多参数版本 vs 加指标要改表（可演进） |
| 退市股 | baostock 补 | 防幸存者偏差 vs 多一个源（可插拔已支持） |
| 前后端 | 前后端分离，生产由 FastAPI 托管静态 | 开发体验好 + 单进程部署简单 |

## 19. 实现期变更与偏离记录（M0–M1，v0.3，2026-06-01）

> M0–M1 编码实现期，因免费数据源真实能力/稳定性与原设计有出入，做了若干经验证的正确偏离。本节回写设计文档以保持一致；偏离背景与需求侧影响见《需求文档》附录 B。

### 19.1 对 §2 技术选型 / §10 数据源的修正
- **数据源（§2.1、附录隐含的 `stock_zh_a_hist`）**：日线主接口由**东财 `stock_zh_a_hist` 改为新浪 `stock_zh_a_daily`**（东财 push2his 本环境被封）。`DataSource` 抽象 + `get_source()` 工厂已落地，并由 `datasource.primary/fallback` 配置驱动选源（真正可插拔）。退市股/上市退市日/行业由 **baostock** 补。
- **§2.2 DuckDB "单写多读"**：实测 DuckDB 读写连接独占文件锁，**写入期间跨进程连读也会失败**。MVP 单用户规避：回填/写入时不并行开 Web 服务。

### 19.2 对 §4 数据库设计的修正
- **`daily_bar.pre_close`**：原未规定来源；新浪不给前收盘，故由复权因子推算 `pre_close = 前收 × 前因子 / 当日因子`，正确处理除权除息/高送转日（否则涨跌停误判）。
- **`daily_bar.limit_status`**：按 `stock_st_status_daily` 逐日准确 ST 事实与中央市场规则计算；主板 ST 在 2026-07-06 前后分别用 5%/10%，创业板、科创板用 20%。`daily_bar.is_st` 仅作事实表物化投影。
- **`daily_metrics.float_mv`**：用新浪**每日 `outstanding_share`（时变）**× 收盘自算（比"最新股本"更准）。`total_mv`/`total_share` 免费源缺，暂空。
- **`index_bar.index_code`**：统一**加交易所后缀**（`000905.SH`），杜绝与深市个股 000xxx 代码冲突。基准 000985 中证全指暂缺（免费源取不到）。

### 19.3 对 §6.2 ST 时变 / §6.4 撮合的落地
- ST 时变局限按 §6.2 预案"退化为当前 ST 状态过滤并标注"执行；并进一步明确：**limit_status 不应用 ST 5%**（见 19.2）。

### 19.6 M2 指标引擎实现要点
- 落地为三层：`operators`（通达信式算子，pandas 后向实现）→ `compute`（单股全指标 + param_hash）→ `IndicatorEngine`（全市场编排 + 横截面 RS）。
- 全市场 5392 只、534 万行指标，**纯本地约 2 分钟**算完（无网络）；RS 按交易日截面百分位、分布均匀。
- 指标基于**前复权**价；防未来函数单测（AST 扫描禁 `shift(负)` + 算子/平台突破/新高NULL）。

### 19.9 M5 回测引擎实现要点 + 关键正确性约定（v0.6，2026-06-07）

模块：`backend/backtest/{forward,signal,broker,engine,metrics,precompute}.py` + `services/backtest_service.py` + `api/backtest.py` + 前端 `BacktestView.vue`/`EquityChart.vue`。

- **复权基准的关键抉择（防失真核心）**：
  - **前向收益 / 信号质量**用 **hfq（后复权=原价×adj_factor）**——`fwd_high/entry` 的比值消去任意公共基准（qfq 的 `/base_factor` 项），故 hfq 比值 == 真实复权收益，且因子历史已知 → **无未来函数**。
  - **策略回测记账**统一 hfq（单调、无需逐日 rebase），净值/收益率在 hfq 基准下正确。
  - **涨跌停可成交性**判定用 **原始价**（涨停价 `round(pre_close×(1±pct),2)` 是对真实成交价四舍五入到分；hfq 缩放会破坏 round）。即"判定用原始价、成交估值用 hfq"。
- **撮合硬约束**（`broker.py`）：买入仅当 `T+1 开盘 < 涨停价`、卖出仅当 `T+1 开盘 > 跌停价`；pct 按板块（主板0.10/科创创业0.20）+ ST 0.05；停牌（执行日无 bar）→ 不可成交、顺延；整手 floor + 现金约束 + 方向性滑点 + 佣金/印花(仅卖)/过户费。
- **事件驱动**（`engine.py`）：信号日 T 决策（数据≤T）、**执行日 T+1 开盘成交**；先卖后买；持仓停牌→不可卖、按最后可得 hfq close 估值；区间末/退市→按最后价强平不悬空；可选止盈/止损/到期/单行业上限；universe 由 score 截面派生（含当时存活后退市票，不因缺市值丢票）。
- **调仓日 vs 卖出规则（两条独立的轴，不冲突）**：**卖出每日评估**（跌破均线为基准 + 止盈/止损/到期可选叠加，任一触发即次日开盘卖），不受调仓周期限制；**买入仅在调仓日**（`rebalance_days`，默认每日）且持仓 < TopN 时**填空位**——调仓**不主动换仓**（持仓只靠卖出规则退出，不因跌出 TopN 被动卖）。守卫：**当日卖出的票当日不再买回**（`sold_today`，防同日同价"卖了又买"双向交成本的 churn；次日重新满足条件可再买）。`rebalance_days>1` 时止损腾出的空位要等下个调仓日才补（现金拖累，属预期行为）。
- **信号质量 + base rate**（`signal.py`，SDD §6.5）：区间逐日全市场打分→分档，join 前向收益；base rate=全已评分票无条件命中率；各档超额=命中率−base，附样本量与 `reliable`。
- **T-M5-10 expr 批量预计算**（`precompute.py`，SDD §8.6）：把 AST 的 expr 叶子在**全历史一次性**算成 `(code,date)->bool`（O(股) 次，替代 O(股×日) 次序列重取）；正确性靠"expr 多为尺度不变相对条件"——用统一 qfq 基准整段算与逐日 rebase 结果一致；**已与 `ScreenEngine.run_hits` 逐日精确对账**（修复 datetime64 键不匹配 bug + 回归单测）。
- **MVP 同步执行**：本地单用户 + DuckDB 单写锁，回测 HTTP 端点同步返回（区间数月约 10 秒级）；异步提交+进度轮询规划 M7（与数据更新端点一致）。
- **绩效短区间警示**：年化/卡玛对极短区间会被放大（`(1/years)` 指数），前端已标注"仅长周期可信"。
- **实证结论**：评分有温和正向预测力（各档超额命中率为正），但朴素"逐日调仓+跌破MA20卖"策略 2024 全年大亏——卖出/调仓规则与含微盘 universe 是亏损主因，为 M6 与策略调参指明方向。

- **一键日常流程**（`services/pipeline.py` `DailyPipeline`，T-M7-1）：更新→指标→打分榜单(含买点/风险 with_signals)→观察池→预设筛选→(可选)体检；每步 `step()` 包计时+异常捕获、留痕(名称/状态/秒/摘要)，关键链路任一步失败即中止返回已完成部分（可观测、幂等可重跑）。CLI `daily [--skip-update][--no-presets][--verify]`。
- **定时调度**（`scheduler/scheduler.py`，T-M7-2）：APScheduler `BackgroundScheduler`，`config.scheduler.enabled`(默认关) 控制，cron 每日 `daily_cron_hour:minute`；**非交易日查 `trade_calendar` 跳过**；与 serve 同进程复用 DuckDB 连接(RLock 串行写)；异常仅记日志不崩调度。
- **配置即时生效**（`api/config.py`，T-M7-3，A-09）：GET `/api/config` + POST `/api/config/reload`。**刻意采用"编辑 YAML + 重载"而非 Web 表单回写**——`settings.yaml` 内成段中文注释是重要文档，程序化 `yaml.dump` 会清掉；前端数据管理页展示关键可调项 + 一键重载。
- **导出**（`utils/csv.ts`，T-M7-5）：通用 CSV（UTF-8 BOM 防 Excel 乱码、自动转义）；榜单/筛选/回测逐笔均可导出。
- **README**（T-M7-10）：简介/功能/技术栈/目录/快速开始/CLI/正确性约定/测试/已知限制。
- **稳健性测试**（`backtest/robustness.py`，T-M7-4）：参数敏感性扫描 + 样本内外切分（对照=同期基准超额）；CLI `robust`。实测揭示典型过拟合（样本内 +59%/夏普5.66 → 样本外 −29%/夏普−7.1），top_n 10/20 稳定。
- **质检全市场扫描**（`data_report._scan_adj_jump`，T-M7-6 补 T-M1-8）：向量化全市场前复权相邻日跳变 >50% → `data_quality_issue`（实测 87 行）；缺失/停牌缺口属正常，由 coverage 汇总不逐条记 issue。
- **日更并发提速**（`IngestionService.update(concurrency=N)`，T-M7-7）：线程池 + **每线程独立 DataSource（限流按线程隔离）、写入 RLock 串行**（数据零影响）；`datasource.update_concurrency` 默认 1（串行最稳）。⚠️ 提并发即提总请求速率，注意源封禁。
- **数据缺口**（T-M7-8）：ST 入库按 Baostock 逐日 `isST` 写唯一事实并同步投影；CDR/估值沿用 baostock/valuation 兜底。
- **指标增量**（`IndicatorEngine.compute_all(incremental=True)`，T-M7-9）：跳过已算到末日的股票、窗口重算只 upsert 新行、RS 只补新日期；daily 默认增量（数据已最新时指标步 0.2s vs 全量 107s），删行重算与全量精确一致。
- **§18 自检清单复核**：逐条通过（除"分档严格单调"为实测保留意见，已记录）。
- **K 线历史买点标注**（T-M4-5）：`/stocks/{code}/signal` 增 `buypoint_markers`（`buypoint_markers()` 全序列跑 `BuyPointDetector`），个股详情 K 线叠加蓝▲买点（复用 `CandleChart.markers`）。

## 20. 数据质量校验体系（分层设计，供长期维护）

> 目的：把"防脏数据入库、字段完整性、价格正确性、问题留痕"拆成职责清晰、可独立调用、可被编排层复用的四层。新增数据需求时，**优先改 L2 契约清单**即可获得自动覆盖。

### 20.1 入库路径（全量 backfill / 增量 update 共用 `ingest_one_daily`）
```
DataSource.get_daily_bar(取数)
  → ① sanitize_bars()   【L1 入库闸门·自动·每批】
        弃 close 空/≤0；零值 OHL 用 close 回填；零成交日 amount/换手填 0；清洗统计打 WARN
  → ② add_markers()     算 limit_status / is_one_word / is_st（板块口径，回测撮合前提）
  → upsert daily_bar（幂等）+ daily_metrics（float_mv=close×流通股本）
回填收尾：
  · 全量 backfill(codes=None) → 自动 _post_ingest_validate()（结构+契约，FAIL 告警）
  · 增量 update / 局部回填 → 不自动校验（避免部分加载误报），靠 L1 + 定时/手动 check-data 兜
```

### 20.2 四层职责

| 层 | 模块 / 方法 | 触发 | 职责 |
|----|-----------|------|------|
| **L1 入库闸门** | `dataquality.sanitize_bars` + `add_markers` | 自动（每批入库，全量/增量都跑）| 防脏数据进库 + 打标记 |
| **L2 字段契约** | `data_verify.DataVerifier.check_contract` | 全量回填后自动 + CLI `verify-data` | **声明式**对照 F-DAT-02/§10.2 必填清单断言非空；缺口显式 `gaps` 豁免 |
| **L3 正确性核查** | `check_structure` / `check_prices` + 独立源 `cross_validate` | CLI `verify-data` | 孤儿/键对齐/日历/OHLC序/复权因子/越界 + 本地 vs 实时源比对 |
| **L4 体检 & 留痕** | `data_report.DataIntegrityReport`（覆盖率/停牌推导/退市/`scan_quality_issues`）| CLI `check-data` | 报告 + 写 `data_quality_issue` |

### 20.3 留痕表（供 M3 接口 / M4 Web 页展示）
- `data_update_log`：每次采集成败、范围、行数（含 backfill/update/delisted/valuation 失败）。
- `data_quality_issue`：质量问题（abnormal_change / missing / adj_jump…）。

### 20.4 维护约定
1. **加字段** → 在 `check_contract.required` 加一行即自动校验；拿不到的写进 `gaps`（豁免），**禁止静默 NULL**。
2. 校验方法均**无副作用、可独立调用**，`quiet=True` 供编排层（M7 DailyPipeline）复用。
3. **待完善（已排任务）**：`check_missing`/`check_adj_jump` 全市场扫描接入（T-M7-6）；增量后自动校验 + 每日定时（T-M7-1/2）；质检 API/Web（T-M3-9/T-M4-6）；`abnormal` 单股版与全市场向量化版合并（T-M7-6）。

## 21. 数据生命周期与质量闭环（业务流程 + 代码索引）

> 给"既要一眼看懂整体、又要能在每个节点定位代码"的读者。把系统想象成一个 **股票数据超市**：进货→验货→上架→盘点→记台账。

### 21.1 业务流程图①：进货验货上架（每次更新数据，自动）✅ 已实现
```
   供应商（新浪/baostock/东财）
         │ 进货（拉一批数据）
         ▼
   ┌──────── 验货关卡（自动，全量/增量都过）────────┐
   │ ① 烂货扔掉    价格空/≤0 的行 → 丢弃              │
   │ ② 小瑕疵修补   开高低缺失 → 用收盘价回填          │
   │               （标记修补行：不臆造一字板+记台账）│
   │ ③ 停牌日填0    无成交 → 成交额/换手记 0           │
   │ ④ 贴标签      涨停/跌停/一字板/ST                │
   └────────────────────┬───────────────────────────┘
                        ▼
            上架入库（幂等不重复、断了能续）
                        ▼
   大进货(全量回填) → 收尾自动盘点(结构+字段契约) + 异常喊话
   小进货(增量)     → 暂不自动盘点（缺口，见 §21.4）
```

### 21.2 业务流程图②：关机重开"追平"（目标，⚠️ 编排未建=M7）
```
   开机/收盘后触发
        │
        ▼  ① 看落后几天（staleness）
        ▼  ② 刷新股票名单（新上市/退市/行业）
        ▼  ③ 补缺失日线（每股从"已存最新日+1"到今天）
        ▼  ④ 补每日总市值/总股本
        ▼  ⑤ 补新退市股历史
        ▼  ⑥ 自动盘点(体检) → 不达标告警
        ▼  完成
   现状：③④⑤的"动作"零件都有，但①⑥和"自动按顺序跑"未建（M7 DailyPipeline）
```

### 21.3 业务流程图③：问题闭环（⚠️ 目前"开口"，自愈=M7）
```
   发现问题 ──→ 记台账 ──→ 〔人工〕看/修/重跑 ──→ 〔人工〕复检
    ✅(手动     ✅          ❌ 无自动返工          ❌ 无自动复检
     跑体检)   data_quality_issue
   目标(M7)：发现→记台账→自动重试(消费 data_update_log)→自动复检转绿
```

### 21.6 指标可配性与扩展（澄清）
- **参数可配**（不改码，改 `config/settings.yaml`）：均线周期、新高回溯天数、放量倍数、健康换手区间、RS 窗口等 → 改后 `param_hash` 变、自动重算。
