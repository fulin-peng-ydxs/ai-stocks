# C1 决策对比：每日榜单结果归属

归档状态：已归档

> **决议（2026-07-04 用户拍板）：采用方案 A 的「公共榜单特例」。** 预设方案归 default/admin、公共榜单全员共享一份、生产者维持平台作业；个人自建方案仍私有走 `/board/compute`。**通用「资产可见性/自助公开」模型（私有/同租户/全体 + 加载=自己+公开）与新用户预设分发另立独立需求后排，不在阶段四。** 已回写 `plan.md` §1/§3.3/§5/§6.4/§10.3，T3b 解锁。下文对比留作决策依据。

## 一、要决定什么

`score_result`（每日榜单/评分快照）在阶段一被登记为**用户私有资产**（带 `tenant_id`+`owner_user_id`），但 `board.py` 至今固定读 `default/admin` 一份给所有人看。多租户放量前必须定死：**每日榜单是"平台公共只读结果"，还是"每个用户/租户各自私有的结果"。** 这决定普通用户首页有没有内容、跨租户是否串数据、谁来生产榜单。

## 二、现网事实（决策底座，已核代码）

- 榜单写入唯一来自 `ScreenScoreService.rank_board(persist=True)`（[screen_score.py:253](../../../backend/services/screen_score.py)），归属取服务构造时的 `get_current_owner()`（[:34](../../../backend/services/screen_score.py)）。
- **唯一的 persist 生产者是 CLI `rebuild/score` 与调度"评分维护"作业**（[cli.py:275/256](../../../backend/cli.py)），二者都跑在 `system_context()` → **default/admin 归属**。普通用户没有任何自动产出榜单的路径。
- `board.py` 读侧 `_OWN=[DEFAULT_TENANT_ID, DEFAULT_OWNER_USER_ID]`（[board.py:18](../../../backend/api/board.py)）。`/board/compute` 为即时计算 `persist=False`（[board.py:117](../../../backend/api/board.py)），不落库、不涉归属存储。
- **结论：现网已经是"公共榜单"的形态**，只是用 admin 归属当公共槽实现，从未真正跑过"人手一份私有榜单"。

## 三、两个选项对比

| 维度 | 方案 A：平台公共只读榜单（推荐） | 方案 B：用户/租户私有榜单 |
| --- | --- | --- |
| 语义 | 每日榜单是平台统一产出的公共研究结果，全体登录用户看同一份 | 每个用户（或每租户）看自己算的榜单 |
| `score_result` 归属定位 | 显式改判为**全局共享只读 reference**（类比行情，不带归属过滤） | 维持用户私有资产，读写按 `get_current_owner()` |
| `board.py` 读侧改动 | 去掉 `_OWN` 过滤，读平台公共槽（约定一个 `PLATFORM` 归属或独立公共表键） | `_OWN` 改为从上下文取当前用户归属 |
| 生产者 | 保持现状：调度"评分维护"/CLI 以固定平台归属产出一份 | **需为每个用户建立产出路径**——用户 `score:run` 自算，或登录/首访惰性算 |
| 新用户空榜单 | **无此问题**，公共榜单一直在 | **严重**：新用户从未 `score:run` → 榜单页空白，须补"空态引导"或"首访惰性全市场打分"（全市场打分昂贵） |
| 性能/成本 | 一份，最省；无按用户重复全市场打分 | 每用户一份全市场评分，存储与算力 ×N；惰性算分拖慢首屏 |
| R9 隔离验收 | 榜单**不做**归属过滤（公共读）；须与私有资产隔离用例明确分开，避免口径混用 | 榜单纳入私有隔离，跨用户/跨租户不可见，与 profiles/groups 同一套用例 |
| `score:run` 定位 | 用户 `score:run` 属"个人试算/自定义方案打分"，写**个人**归属，**不影响公共榜单**；公共榜单只认平台作业 | `score:run` 就是"生产我的榜单"，写个人归属并被 `/board` 读到 |
| 权限码 | `board:view` = 公共读（基线或研究默认码均可）；`board:compute`/`score:run` 仍个人 | `board:view` 读个人榜单；空态即"去算一次" |
| 改动面 | 小：`board.py` 读侧 + `score_result` 定位声明 + 生产者归属固定 + 公共读测试 | 大：读侧归属 + 每用户生产路径 + 空态/惰性算分 + 跨账号隔离用例 + 性能兜底 |
| 主要风险 | "公共槽"用 admin 归属实现要写清楚，别和私有资产隔离铁律打架（须显式标注"有意不带归属"，同 `mark_stale_*`/`stats()` 的先例） | 成本与首屏体验；新用户空白；全市场按用户重复打分的资源放大 |

## 四、推荐

**方案 A（平台公共只读榜单）**，理由：

1. **贴合现网事实**：现在就是 admin 归属产出、全员共享读，A 只是把这一既成事实"扶正"为显式公共 reference，改动最小、风险最低。
2. **成本可控**：避免每用户全市场重复打分与惰性算分拖慢首屏。
3. **业务语义正确**：趋势龙头榜单是平台统一口径的研究结论，本就该全站一致，而非人手一版。
4. 个性化需求由 `score:run` + 用户自建评分方案覆盖（写个人归属、走 `/board/compute` 即时看），与公共榜单**正交并存**，不牺牲灵活性。

采纳 A 时，务必在 CLAUDE.md「资产归属与隔离」补一条：**`score_result` 公共榜单读有意不带归属**（与 `indicator_def`/`mark_stale_*` 同类"有意全局"先例并列），防后续 AI 按私有资产铁律"纠正"回归属过滤。
