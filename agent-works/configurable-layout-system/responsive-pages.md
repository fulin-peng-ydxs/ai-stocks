# 响应式页面检查

本文件维护各页面当前可用的布局验收证据及覆盖缺口，用于选择后续复测范围。设计要求见 [DESIGN.md §8](../../DESIGN.md#8-responsive-behavior)，组件适配策略见 [响应式组件触发清单](responsive-components.md)，实施与验收流程见 [页面模板](page-template.md)。字体、颜色和动效规则统一查阅 DESIGN，不在此重复定义。

## 证据口径

- **全站基线：2026-10-07。** 表中页面均有入口布局检查记录，后续只对列明的页面和状态做局部复核；较早的通过记录不代表当前版本所有业务状态已重新验证。
- **最近局部复核：2026-10-17。** 该日期只代表注明范围的实际复核；未登记的日期、主题或状态不补写为已通过。
- 标准浏览器视口：V1＝1100×620、V2＝1366×768、V3＝1440×900。基线与最近局部复核均使用自动界面比例约106%；这些是浏览器视口，布局画布由应用缩放折算，不作为组件断点值。
- 实测入口为专用5181内置浏览器；业务页使用 `debug_normal`，系统/数据页及最近局部复核使用 `debug_system`。仅查看页面和操作界面状态，未为验收创建正式规则或发起采集、筛选、回测等业务写任务。
- “入口通过”只覆盖表中已观察状态的主操作可达、溢出和滚动；“局部通过”仅覆盖注明的复核项。单测和源码扫描另行提供证据，不能代替浏览器结论。

## 覆盖边界与维护

- 当前以桌面工作台为验收目标。入口记录不覆盖所有断点两侧、缩放比例、业务状态、权限组合或手机页面；表内缺口在对应能力改动时按风险补测。
- 快速跨页曾观察到 `PageDrawer` 缺少页面容器并回退body的告警，尚未在对应抽屉链路闭环复核；已有通过记录不包含该问题已解决的结论。
- 新增页面登记独立行；后续改动直接更新受影响行的日期、视口、状态、结论和缺口；仅整理文档不刷新实测日期。未经复测的范围继续标明，不复制“通过”，不将组件单测或静态检查填成浏览器实测。
- 此处只维护当前验收矩阵和覆盖边界，不追加提交历史、修复过程、字体/色值/动画配方或每轮测试数量；历史细节通过Git追溯。
- 从 `frontend` 目录执行 `npm test -- src/layout/__tests__/responsive-inventory.spec.ts`，检查页面登记完整性，以及组件文件/尺寸查询与清单的一致性。该测试只检查登记，不能证明页面视觉或业务链路通过；需要复测时按页面模板和项目规则使用内置浏览器。
