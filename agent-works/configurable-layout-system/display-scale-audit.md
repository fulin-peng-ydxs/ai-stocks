# 响应式显示比例审查与修复

## 范围与结论

审查起点为 `d3629b8`、`796baf5`，并追查当前前端所有尺寸媒体查询、视口单位、DOM 坐标读写、拖拽、滚动、Teleport、图表尺寸监听，以及实际消费的 Element Plus 控件。

应用根统一使用参与布局与原生命中测试的 CSS `zoom`；禁止使用整页 `transform` 或重复叠加倒数宽高补偿。第三方控件内部坐标、尺寸断点和默认弹窗视口单位必须共同服从这一坐标契约，不能仅凭应用工具函数的单测判定适配完整。

## 依赖与复用

- 复用 `useDisplayScale`、`displayScaleGeometry`、现有图表和表格组件，不在页面重写第三方鼠标事件。
- 新增 `useLayoutViewport` 作为 JS 布局视口入口；CSS 通过具名容器共享同一尺寸事实。
- `frontend/patches/element-plus+2.14.1.patch` 维护第三方补丁，同时覆盖 ESM/CJS。`element-plus` 锁定为当前安装版本 `2.14.1`，增加 `patch-package` 安装补丁，版本不符或补丁失配时中断安装。
- 补丁内的坐标 helper 在依赖内部复用，应用自己的几何工具不反向依赖第三方私有模块；两个运行边界分别由组件交互测试与应用几何测试验证。
- 本次属于共享机制修复，不新增页面原型、slot、权限、系统组件种类或配置字段。同步 DESIGN、页面模板维护矩阵、README 安装说明及 AGENTS 依赖版本。
- 全量检查发现的 `StockGroupBatchActions` 漏登记与榜单测试漏 Mock 分组请求已补齐；没有为适配测试改动榜单业务逻辑。

## 实测记录

- 80% 下，200px 列宽向右拖动 32 个屏幕像素：修复前变成 192px，修复后为 240px。
- 1440×900 登录页：150% 时根布局宽 960px，进入单列；80% 时布局宽 1800px，恢复双列。单列超高内容由登录区自身滚动承接。
- 150% 独立抽屉：在 1280×720 视口中，视觉高度为 720px；内部下拉面板保持 scale=1 并对齐触发器。
- 150% 独立弹窗：默认上边距从错误的 162px 校准为 108px（720px 视口的 15%）；日期面板保持自身 100% 比例。
- 600×720 窗口、150%：440px 档抽屉限制为视觉 600×720，边界为 x=0~600；弹窗左右边界为 x=24~576，没有超出视口。
- 80% K线工作区：中央光标命中样本序列中央日期 `2026-08-13`；分隔线向上拖动 40 个屏幕像素，实测准确移动 40px。
- 最后一轮弹窗/日期面板复核没有新增控制台 warning/error。临时复核页仅用于装配真实组件，结束后删除。
