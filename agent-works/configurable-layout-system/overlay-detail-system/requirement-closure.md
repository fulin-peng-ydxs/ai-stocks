# 弹窗、抽屉与详情统一闭环

## 初步需求理解

项目需要把“查看或编辑数据时选择弹窗还是抽屉”的文字约定升级为统一前端能力，并治理现有页面中直接使用 `el-dialog`、私有详情网格和任意宽度造成的体验分叉。

## 业务目标

- 用户在不同页面打开确认、短编辑、完整详情和长流程时获得一致且可预期的承载方式。
- 开发者只能通过受控组件和语义尺寸接入弹层，新增代码不能继续绕过统一规范。
- 迁移不改变现有接口、权限、数据归属和业务结果。

## 用户与场景

所有登录用户继续按原权限查看或编辑其可访问的数据；系统管理员、租户管理员和普通业务用户的权限边界不因本次界面治理改变。典型场景包括危险操作确认、少字段创建或编辑、完整业务详情查看、多分组编辑、日志和历史记录查看，以及复杂图表或表格工作台。

## 完整业务闭环

1. 用户从当前页面触发查看、创建、编辑、确认或长流程操作。
2. 系统按任务语义选择唯一承载方式：危险确认使用确认框，少字段单分组任务使用统一弹窗，完整详情和复杂编辑使用统一详情抽屉，持续性复杂工作使用独立页面或明确的全屏模式。
3. 弹层在当前 `LayoutHost` 的 `#overlays` 内打开；用户原列表、筛选、分页和滚动现场不被破坏。
4. 加载、空数据、失败、无权限、只读、编辑、提交中和保存失败均使用统一状态与反馈。
5. 保存成功后关闭或回到只读详情并刷新来源数据；失败时保留当前输入；取消或关闭不提交修改。
6. 关闭详情后用户回到原页面现场，能够继续原任务。

## 功能点清单

- 建立统一弹窗外壳，约束语义尺寸、挂载、标题、正文、footer、关闭和全屏例外。
- 基于现有 `PageDrawer` 建立详情抽屉外壳，统一标题、状态、正文和操作区。
- 提供可组合的详情分区与键值字段组件，统一字段布局、空值、长文本和窄容器退化；业务字段和领域操作仍由消费页面提供。
- 保留 `PageSettingsDrawer` 的独立设置职责，不与业务详情抽屉合并。
- 迁移现有直接 `el-dialog` 和重复详情结构；无法直接归入短弹窗或详情抽屉的复杂场景改为明确全屏模式或独立页面承载。
- 更新 `DESIGN.md`、页面模板、真实复用组件清单和契约测试，禁止页面新增裸 `el-dialog`、裸 `el-drawer`、任意弹窗宽度及重复详情外壳。

## 页面闭环草案

- 确认框：只承载破坏性、高影响或不可逆决策，动作名称必须明确对象。
- 统一弹窗：承载少字段、单分组、一次完成后关闭的创建或编辑任务；提交中阻止重复操作，失败保留表单。
- 统一详情抽屉：承载完整对象查看、多分组编辑、历史、日志和长内容；只读与编辑模式共享同一详情结构，正文内滚，关键操作稳定。
- 独立页面或全屏模式：承载复杂表格、图表回放、持续比较和多区域联动，不用无限加宽普通弹窗规避选型。

## 状态与失败处理

- 加载态保持弹层结构稳定；空态说明对象不存在或暂无内容；读取失败提供重试；无权限明确说明不可操作且不伪装为空态。
- 查看期间数据失效时保留弹层并提示刷新或关闭；编辑期间保存失败保留草稿；保存成功后刷新调用方数据。
- 关闭未保存编辑时，按影响程度复用项目既有离开确认机制；纯查看直接关闭。

## 范围划分

### 必须实现

- 统一选型规则、弹窗外壳、详情抽屉、详情分区与字段展示能力。
- 存量弹窗和重复详情结构迁移。
- 语义尺寸、状态、响应式、挂载和 footer 规范。
- DESIGN、页面模板、组件清单、组件测试和扫描契约同步。

### 建议实现

- 系统组件页的组件详情抽屉自身改为统一详情组件，作为真实运行实例；不为仅负责 Vue 复用、没有布局配置语义的 `AppDialog` / `AppDetailDrawer` 虚构系统组件 kind。
- 对存量全屏或超宽弹窗逐项标注例外原因：本次纳入。

### 暂不实现

- 不修改后端接口、权限、数据结构和业务状态机。
- 不建设通过配置动态生成任意详情页的万能 schema 引擎。
- 不要求移动端专用页面；继续遵循当前桌面工作台的容器响应式契约。

## 推断依据与确认结论

- 项目已有 `PageDrawer`、`PageSettingsDrawer`、`AppStateBlock` 和 `LayoutHost #overlays`，应扩展而非另建第二套抽屉体系。
- 当前存在多处直接 `el-dialog`、`el-descriptions` 和页面私有详情样式，已形成同一变化原因，满足抽取复用单元的条件。
- 用户已确认统一并直接进入开发，默认覆盖全部可识别存量入口，不保留仅文档约束、代码继续绕过的过渡终态。
