# 列表高级搜索闭环设计

归档状态：已归档

确认状态：用户于 2026-10-03 确认本方案，包括“页面设置抽屉配置两个常显条件、高级搜索在页面内展开”和“整页工作上下文固定展示，不占两个常显名额”。本文保存已确认的闭环设计，尚未进入代码实现，不代表已实现或验证通过。

统一行为：同一个列表有 ≥3 个可收纳的搜索条件时，默认展示两个，其余放入页面内的“高级搜索”折叠区；通过现有页面设置抽屉选择常显条件。高级搜索在筛选条下方展开，使用户调整条件时仍能看到列表结果。

## 1. 哪些控件参与收纳

按“独立列表的筛选区”计算，不按整页控件总数计算。同页两个列表、不同页签的列表分别配置。

| 控件类型 | 是否计入门槛、参与收纳 |
| --- | --- |
| 关键词、状态、类型、普通日期筛选、多选条件 | 是 |
| 日期范围、数值范围 | 一个完整条件，不能拆开收纳 |
| 两个语义独立的勾选条件 | 分别计数 |
| 分页、排序、刷新、新建、导出、批量操作 | 否 |
| 决定整页工作对象的方案、分组、研究日期等上下文 | 固定展示，不占两个名额 |
| 回测运行参数、策略条件编辑器 | 不属于列表搜索，保持原有操作方式 |

这一区分与项目实际有关：[个股查询](../../../frontend/src/views/StocksView.vue)同时存在范围切换、日期和普通筛选；[履约历史](../../../frontend/src/views/trade-discipline/components/TradeDisciplineHistory.vue)包含日期范围及多个筛选项。不能只数输入框，否则会把业务上下文藏起来，或把日期范围拆成两项。具体字段是否属于整页上下文，按其真实业务作用判断，不能仅凭“日期”等字段名称判断。

- 0～2 个条件：全部展示，不出现高级搜索入口。
- ≥3 个条件：默认常显两个，其余全部进入高级搜索。
- 计数以当前身份、当前业务模式实际适用的条件为准；暂时加载失败的控件仍计数，避免界面跳动。
- 每个列表明确初始常显的两个条件，优先高频条件；有关键词搜索的列表，通常优先保留关键词。

## 2. 页面交互：展开后与列表保持联系

以“状态、关键词”常显为例，收起状态示意如下。示意中的“×”表示删除动作，实际界面使用项目既有图标组件。

```text
[状态：全部] [关键词____________]  高级搜索（2）  重置筛选  [排序]

高级条件：类型＝定时任务 ×   执行结果＝失败 ×

──────────────── 列表结果 ────────────────
```

点击“高级搜索”后，在同一筛选容器内展开：

```text
[状态：全部] [关键词____________]  收起高级搜索（2）  重置筛选  [排序]

[类型：定时任务] [执行结果：失败] [日期范围____________]

──────────────── 列表结果 ────────────────
```

这里的 `（2）` 表示高级区中当前有两个生效的限制条件，不是高级区总共有两个控件。没有生效条件时不显示数字。

- 展开、收起只改变展示，不发起查询、不清空条件、不改变页码。
- 修改条件沿用项目现有自动查询：选择后查询，关键词防抖，条件变化回到第 1 页；不新增“查询/确定”按钮。
- 展开时只显示其余条件，不重复常显控件，避免同一个字段出现两个输入入口。
- 当前页面内保持用户手动展开状态；普通重新进入页面默认收起。从详情返回列表时，可以随已有返回现场恢复展开状态。
- 查询中允许继续输入，只接收最新条件对应的有效响应。
- 高级区展开后不能把列表完全挤出可操作区域；长条件区需要受控滚动，窄屏按单列排布，保持标签与控件完整可见。
- 支持键盘展开、收起；收起时如果焦点在高级区内部，应回到展开按钮，避免焦点丢失。

现有 [DESIGN.md](../../../DESIGN.md)要求“条件 → 文本搜索 → 命令 → 排序”。引入分区后，常显区与高级区分别遵循条件排列规则，排序继续固定在所属工具栏末尾；开发时须同步规范与交互契约。

## 3. 隐藏条件必须能被感知

高级搜索默认收起后，需要避免列表被隐藏条件限制而用户不知情。以下行为本次纳入：

- 收起时，只要高级区存在生效条件，就显示简洁的条件摘要；默认配置带来的生效条件也必须显示。
- 多选字段按一个条件计数，摘要显示“类型：A、B 等 3 项”；日期范围也是一个条件。
- 点击摘要正文，展开高级区并定位到对应控件。
- 点击摘要删除按钮，清除该字段限制并自动查询；有必填约束的字段不提供清除按钮。
- 摘要较多时，收纳为有限行数，并提供“其余 N 项”入口，点击展开高级区。
- 生效条件数量与“是否偏离默认值”分开判断。例如默认已经勾选“忽略 ST”，即便“重置筛选”禁用，也需要提示这一隐藏限制。
- 零结果时展示当前筛选影响，提供适用的“重置筛选”以及高级搜索入口；不自动清空用户条件。

连板天梯整条筛选操作栏独立放在页面操作区、主从工作台上方，排序保持右对齐；展开区域顶部独立显示“高级条件”辅助标题，下方排列筛选控件；标题、收起态高级条件摘要与控件行使用一致的横向内边距。

## 4. 设置抽屉：配置展示位置

入口沿用：`页面设置 → 组件设置 → 对应列表筛选区 → 常显搜索条件`。

用复选框配置（2026-10-04 按用户反馈调整）：

```text
常显搜索条件
☑ 状态   ☑ 关键词   ☐ 角色
已选 2 项；替换时先取消一项
```

- 最多勾选两项，已选满时禁用未选项，先取消再勾选替换项。
- 未选满只保留抽屉草稿，提示“已选 N/2 项，选满后自动保存”；页面继续使用原组合，不保存不完整配置。关闭抽屉或恢复默认时丢弃草稿。
- 两项仅决定成员，不提供自由排序；页面仍按统一的条件类型顺序展示。
- 保存后当前页立即调整展示，保留所有条件值、列表结果、排序和页码，不额外查询。
- 配置只影响当前租户下当前用户的当前列表；同页多个列表独立保存，使用明确的列表名称区分。
- 沿用现有页面设置的保存机制，保存成功后跨会话生效；保存失败明确提示，保留待保存选择供重试，不能显示为已保存。
- 不单设常显条件恢复按钮；统一使用抽屉底部现有“恢复默认”恢复整页设置。
- 已配置字段被删除或不再适用时，保留仍有效的选择，并按页面默认顺序补足两个；可用条件不足三个时直接全部展示。
- 没有用户配置权限时，仍按页面默认组合使用高级搜索，只是不开放个性化修改。

本次固定常显两个、默认收起，不增加“常显数量”“默认展开”“自定义门槛”等额外设置。展示偏好与默认查询值分开，普通筛选操作不得改写长期偏好。

## 5. 操作边界与异常处理

| 操作 | 改变什么 | 不应产生的副作用 |
| --- | --- | --- |
| 收起高级搜索 | 条件控件的可见性 | 不清空条件、不查询 |
| 重置筛选 | 常显区与高级区的全部筛选值恢复该列表默认，并合并查询一次 | 不修改常显配置、不重置排序、不改变展开状态 |
| 抽屉恢复默认 | 整页设置覆盖（含常显条件），并清除未完成选择草稿 | 沿用整页恢复语义，不提供额外的单项恢复按钮 |

高级区中的校验错误不能随收起消失。例如日期范围不合法，应阻止无效请求、显示错误；存在未解决的输入错误时，收起入口应提示先处理，并定位问题字段。

列表查询失败时，保留当前输入与展开状态，在列表区域提供重试；条件选项加载失败时，在对应字段提供重试，不将加载失败当作“没有该字段”。

## 6. 完整场景走读

用户打开履约历史，默认看到“日期范围、股票”，高级搜索收起。此组合用于场景说明，各列表的初始组合按高频业务需要确定。

1. 点击高级搜索，选择“结果＝违规”，列表自动查询并回到第 1 页。
2. 收起高级搜索，页面保留“结果＝违规”的摘要，按钮显示一个生效条件。
3. 用户打开页面设置，把常显的“股票”替换成“结果”；保存成功后，“结果＝违规”移动到常显区，股票进入高级区，查询结果保持不变。
4. 用户修改常显的结果条件，列表自动更新；普通筛选操作不会改写长期展示偏好。
5. 点击“重置筛选”，两个区域一起恢复默认，只查询一次，常显组合仍是用户保存的组合。
6. 下次进入该列表，恢复已保存的常显组合，高级搜索默认收起；详情返回则优先恢复已有列表现场。

保存失败停在设置环节，可以重试；查询失败停在结果环节，可以修改条件或重试，两者反馈独立。

## 7. 全页面接入范围与确认结果

本次覆盖所有符合门槛的独立列表筛选区，包括系统管理列表、数据管理列表、业务历史列表和工作台内的结果列表，不能只覆盖顶层路由页面。静态展示表、编辑表单和执行参数区不套用这项规则。

本需求触发页面设计闭环和组件／布局维护矩阵更新。后续开发应统一复用筛选收纳能力，同步页面登记、设置消费、设计规范及对应交互契约；重点验证“收起不丢值、换常显不查询、重置只查询一次、配置隔离和失败重试”。本次已核对相关源码与设计规范，尚未执行实现后的交互验证。

已确认的关键选择：

1. 页面设置抽屉配置两个常显条件，高级搜索在页面内展开。
2. 整页工作上下文固定展示，不占两个常显名额，例如评分方案或决定整个工作台的研究日期，避免隐藏理解当前结果所必需的信息。

本方案无遗留阻塞确认项。各列表的字段分类、初始常显组合及实际接入清单仍需在后续需求细化或开发计划中结合页面逐一盘点，不将场景示例当作所有页面的默认配置。本文为已确认闭环设计，不自动扩展为正式 PRD 或开发授权。
