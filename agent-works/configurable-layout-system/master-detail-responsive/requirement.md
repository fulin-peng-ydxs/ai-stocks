# 主从工作台响应与尺寸比例档案需求

## 已确认目标

- 个股查询、每日榜单、板块行情、连板天梯统一复用同一套主从工作台响应原则，不再由页面分别实现窄屏逻辑。
- 宽视口按工作区容器宽度连续计算左右比例；工作区宽度不超过 720px 时退化为列表单区，选择对象后在统一全屏抽屉中展示分析区。
- 用户拖动分隔条后点击“使用页面当前比例”，同时保存当前工作区布局宽度与当前比例，形成当前页面、当前用户的尺寸比例档案。
- 一个页面允许保存多个尺寸比例档案；运行时只在当前工作区宽度与档案宽度相差不超过 15% 时采用档案，多个候选取相对宽度差最小者，没有候选时回退默认比例。
- 再次保存时，若与已有档案宽度相差不超过 5%，更新该档案；否则新增档案。

## 使用闭环

1. 用户从任一行情主从页面进入页面。
2. 系统测量主从工作区自身的布局宽度 `clientWidth`；不使用物理屏幕分辨率、设备型号、`devicePixelRatio`、浏览器外框尺寸或高度。
3. 工作区宽度大于 720px 时，系统从当前页面的个人尺寸比例档案中选择 15% 范围内最接近的档案；无匹配档案时按个人默认、页面/预设默认、系统 45% 的顺序回退。
4. 最终比例继续受列表至少 360px、分隔条 12px、分析区至少 240px 的内容安全约束。
5. 用户可拖动或用键盘调整当前会话比例；未保存的调整只影响当前会话。
6. 用户在页面设置中点击“使用页面当前比例”后，系统按 5% 近似宽度规则更新或新增档案；设置项保持默认占比、数值控件和主色采用按钮的紧凑结构，不直接展示档案与匹配算法。
7. 工作区宽度不超过 720px 时不应用比例档案，页面只展示列表；选择对象后打开共享分析抽屉，关闭抽屉回到原列表位置。

## 状态与优先级

- 运行时优先级：内容安全约束 > 当前尺寸匹配的用户档案 > 用户默认比例 > 页面/预设比例 > 系统默认 45%。
- 历史 `masterWidth` 只允许兼容读取和旧客户端校验，不参与当前布局计算，也不自动转换为尺寸档案。
- 页面间共享算法、组件、配置结构和交互；档案按页面分别保存，避免不同表格与分析内容相互覆盖个人选择。
- 尺寸连续变化时按相对宽度差确定最近档案，等距时以较小档案宽度稳定决胜；拖动分隔条本身不得触发档案自动保存。

## 权限、异常与范围

- 档案沿用现有布局用户配置权限和租户/用户归属，只允许当前用户维护自己的页面档案。
- 后端不可达或配置非法时忽略档案并使用默认算法，不阻断页面数据展示。
- 本次必须实现四个行情主从页面统一响应、尺寸档案保存/匹配/回退、历史配置兼容、紧凑设置入口和相关测试/规范同步。
- 本次不按物理显示器 ID、设备名称或分辨率枚举建立档案，不自动修改浏览器缩放，不把页面间的个人比例强制统一。

## 验收闭环

- 四个页面在相同工作区宽度下表现一致；720px 以下均为列表单区并可从选择动作进入分析抽屉。
- 保存两个不同工作区宽度的比例后，分别回到对应宽度会选择距离最近且在 15% 范围内的档案；超出全部范围时回退默认比例。
- 5% 内重复保存只更新档案，不产生重复项。
- 普通宽屏仍按比例连续计算，360px/240px 安全边界、拖动、键盘、双击复位与应用级视觉缩放坐标换算保持有效。
