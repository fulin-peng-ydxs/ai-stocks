# 操作行共同尺寸改造计划

状态：已按确认方案实施；定向测试、代表性浏览器复核与最终生产构建通过。核查日期：2026-10-24。

## 文档边界

本文记录操作行等高机制的已确认方案、迁移范围、实施顺序和验收结果。已生效的设计契约以根目录 [DESIGN.md](../../../DESIGN.md) 为准；通用接入流程和维护矩阵见 [页面模板](../page-template.md)，实际响应式策略和验收证据分别维护在 [组件清单](../responsive-components.md)、[页面检查](../responsive-pages.md)。实施时同步规则正文，不在本文并行维护一套长期设计规范。

## 1. 实施前核查

| 对象 | 已接入密度的部分 | 当前缺口 |
|---|---|---|
| `LayoutHost` / `global.css` | 常规控件高度为紧凑 28px、标准 32px、宽松 36px；行间距为 6px、8px、12px | 页面提供了变量，但没有定义每组操作行的共同尺寸边界 |
| `AppControlRow` | 控件间距读取页面密度，默认居中、自然换行 | 没有尺寸属性、共同高度上下文或最小高度；实际高度由子项撑开 |
| `AppTabToolbar` | 工具栏最小高度读取密度；操作区复用 `AppControlRow` | 外壳最小高度不能保证内部控件等高 |
| `AppAdvancedSearch` | 内部滚动布局的间距读取密度 | 使用 `AppScrollArea` 的 flex 内容布局，没有实际复用 `AppControlRow`；DESIGN 清单的现有描述需要校准 |
| 按钮、输入、选择器、日期、分段、图标命令 | 大部分已使用同一组尺寸变量；部分库控件另有最小高度和内距适配 | 控件独立选择 size，行内可以混入不同高度；表单和业务封装也可能改变继承结果 |
| 现有检查 | 检查共享组件的变量映射；检查分段的工具栏 size 与局部 CSS 覆盖 | 没有完整检查整行内不同类型控件的尺寸冲突，也没有证明每条操作行的实际几何一致 |

已有相关问题示例：

- 采集任务中心和日志工具栏逐个给选择器、按钮传 `small`，常规工具栏不能共同随密度变化。
- 回测的参数行位于默认 `large` 的 `AppForm` 内；稳健性区域另有逐控件 `small`，迁移需要先确认区域属于表单参数还是普通工具栏。
- `AppSearchInput` 默认主动传 `size="default"`；`PageSegmented` / `AppFilterSelect` 使用 `useFormSize()`；`AppIconButton` 通过独立尺寸变量消费密度。不能假设这些封装的继承方式已经相同。
- 顶栏、页头动作区、资产搜索和图表头部仍有专用 flex 布局，不能只扫描通用行标签。

## 2. 改造目标与边界

推荐目标：操作行提供一份共同的控件高度，所有参与该行的常规控件消费同一来源。页面只声明行的尺寸意图，不再逐个补 size 或写高度补偿。

统一的是控件的可见外框高度，不是内部文字行高、分段选中块高度或所有后代元素高度。

参与对象：

- 常规命令按钮，包括实色、描边、plain 和 loading 状态。
- 单行输入、数字输入、搜索输入、单选/多选下拉、日期及日期范围选择。
- 带底板分段、下划线分段、水平按钮式单选/复选。
- 与常规命令同级的独立图标操作。
- 上述控件的领域封装，例如交易日、方案、股票/板块选择器。

不直接拉伸的对象：

- 标签、状态点、说明、帮助、开关、普通复选框、关闭/清空入口和纯文字链接。
- 表格行操作、导航、登录页专用切换、多行文本域、上传区和多行选择卡片。
- 弹出面板内部候选项、日历单元格、抽屉内容及其独立编辑表单。

附属入口继续按既有角色规范呈现；不能用“例外”把普通独立按钮伪装为微型操作。领域复合控件按真实结构逐项归类，不按文件名前缀整组放行。

本次不调整字号、语义色、权限、业务状态、搜索触发方式、后端接口、数据结构或用户配置存储。工作区已有的视觉环境两组 `large` 分段调整保留；该场景是独立整行设置，不回退到工具栏默认尺寸。

## 3. 推荐机制

### 3.1 行尺寸优先，默认继承现有上下文

建议给 `AppControlRow` 增加可选 `size`，复用 `default | small | large`，不增加新的数值档位。

| 声明 | 建议语义 |
|---|---|
| 省略 size | 先继承最近的操作行；没有操作行时继承表单项、表单和全局尺寸，均没有时跟随页面密度 |
| `size="default"` | 明确跟随所在页面密度，不强制为标准 32px |
| `size="small"` | 整组使用已有 28px 档位；只用于明确的局部尺寸层级，不能作为常规工具栏默认值 |
| `size="large"` | 整组使用已有 36px 档位 |

操作行内部，参与控件的高度以行尺寸为准；原有单控件 size 冲突应在迁移和检查中报出，不让独立 size 静默破坏整行等高。行外控件保持现行的显式尺寸和表单继承规则。

`AppTabToolbar` 透传同一尺寸意图；`AppAdvancedSearch` 在现有稳定布局节点上建立同一种尺寸作用域，避免通过另包一层或按展开状态切换父节点而重建输入。

### 3.2 一套作用域，覆盖自有和组件库控件

推荐采用“共享行尺寸解析 + 局部 CSS 高度变量 + 公共控件适配”的方式：

1. 用一个内部尺寸模块为三类行容器提供共同的继承规则，数值仍引用 `global.css` 现有 token。
2. 行生成具名的局部共同高度变量，例如 `--app-control-row-height`；不得将它写到根节点或拿它覆盖页面密度本身。
3. 自有封装在公共实现中消费该变量；原生 Element Plus 按钮、输入、日期等在共享适配层消费，不要求业务页换成另一套基础组件。
4. 适配同时处理 `height`、`min-height`、库尺寸类、纵向 padding 与盒模型，避免变量正确但实际外框仍不齐。
5. 文字、图标、说明继续使用既有角色 token；共同高度不等于所有内部字号、图形或文字行高相同。

不单独依赖 `ElConfigProvider size`：已安装 Element Plus 的 `useFormSize()` 优先读取控件属性、表单项和表单，最后才读取全局尺寸，单放 ConfigProvider 无法覆盖所有继承冲突。

也不使用 `.row * { height: ... }`，不在生产运行时测量最高控件后反向设置全组高度，不新增全局 ResizeObserver 或持续 DOM 扫描。

### 3.3 行容器保持自然高度

- 行可设置基于共同控件高度的 `min-height`，不设置固定 `height`。
- 保留 flex 换行、页面密度间距、自然宽度和现有左右对齐。
- 窄容器换为两排后，总高度自然增加，每排参与控件保持共同高度。
- `AppControlItem` 仍把标签、帮助和控件作为整体换行；长说明、错误和工具栏反馈允许独立占行。
- 不为了等高裁掉错误、收缩输入文字、压缩操作命中区或隐藏核心操作。

### 3.4 上下文边界与隔离

- 普通包装层、插槽和 `AppControlItem` 不截断行尺寸继承。
- 嵌套操作行默认继承父行，显式声明尺寸时建立新的独立行。
- 新的一级 `AppForm` 建立自己的编辑尺寸上下文，避免由某个紧凑工具行打开的编辑区也被缩小；表单内新操作行默认继承表单尺寸。
- `AppDialog`、`PageDrawer` 等独立浮层须切断调用方的行尺寸上下文；浮层自身的表单或操作行重新解析尺寸。
- 同时检查 Vue provide/inject 与 CSS 继承；Teleport 的逻辑父子关系和实际 DOM 父子关系不同，不能只重置其中一层。
- 不改变全局视觉环境、用户中心与页面浮层已有的密度归属。

## 4. 迁移范围与顺序

| 批次 | 范围 | 处理重点 |
|---|---|---|
| A | `AppControlRow`、`AppControlItem`、`AppTabToolbar`、`AppAdvancedSearch` | 建立统一尺寸作用域，保留稳定节点、对齐和换行 |
| B | `global.css`、`PageSegmented`、`AppSelect`、`AppFilterSelect`、`AppSearchInput`、`AppIconButton`，以及输入/数字/日期/单选/复选适配 | 覆盖各类实际外框和表单继承；校准角色例外 |
| C | 个股、每日榜单、板块、连板、采集、数据概览/质量、用户/租户/审计、交易纪律历史等现有查询/操作行 | 逐条删除常规控件的尺寸补偿；核对组合控件是否消费共同高度 |
| D | 回测参数、稳健性区域、配置面板和布局管理工具 | 区分表单大号与普通工具栏；不机械把子控件 small 上移成整行 small |
| E | 资产搜索、图表头部、页头命令区等私有 flex 行 | 能直接复用 `AppControlRow` 的迁移；确有专用结构的保留结构但消费同一内部尺寸作用域，登记原因 |

实施前给所有候选行逐条归类：统一行、保留专用结构但接入作用域、非适用角色。首轮不以类名包含 toolbar 就直接改，也不只迁移 AST 已统计到的标签。

每批完成后检查联动能力：搜索值和触发次数、常显/高级条件切换、输入草稿、动态显隐、loading/disabled、弹层打开关闭、缓存页面返回与布局切换。

## 5. 实施阶段与完成条件

### 阶段一：确认契约并补齐迁移清单

- 确认第 2、3 节的参与范围、尺寸优先级和作用域隔离。
- 在本目录沿用本计划记录实施清单，不额外创建平行设计规范。
- 按真实调用位置核实所有通用和私有操作行；标记动态 size、局部 CSS 和领域封装。

完成条件：每条候选行都有迁移或排除结论，尺寸继承规则不存在未说明的冲突。

### 阶段二：实现公共机制和组件组合验证

- 落地共享尺寸作用域与公共适配。
- 先用真实控件组合验证，再迁移业务页面；不只断言 CSS 字符串。
- 优先解决 AppForm、控件库尺寸类、嵌套行和浮层隔离，避免迁移后才发现机制无法覆盖。

完成条件：普通行、表单内行、显式行尺寸、嵌套行及独立浮层的预期高度均成立。

### 阶段三：按批次迁移并建立防回归检查

- 按 A—E 的职责完成公共接入和业务迁移，清理过时补偿。
- 增加统一消费检查入口，沿用现有脚本门禁形式；模板用 Vue AST、样式用 PostCSS，不仅靠正则匹配组件名。
- 检查行内常规控件的独立 size 冲突、动态绑定、匿名内联高度，以及对参与控件外框/内部 wrapper 的局部高度覆盖。
- 静态无法判定的动态尺寸必须有具名接入或明确组件验证；不能将无法识别当作通过，也不承诺静态分析可证明任意运行时布局。
- 复用并扩展已有 `control-presentation` 与分段消费检查；共享同一检查实现，避免测试和构建各写一套判据。
- 附属角色例外精确到角色和接入位置；禁止按整页或组件目录宽泛豁免。

完成条件：候选行全部归类并迁移，已知尺寸冲突清零；有能复现原始问题的失败夹具证明门禁有效。

### 阶段四：实际几何验收与规范同步

- 按第 6 节完成最小充分的组合和真实页面验证，发现问题后在对应层修复。
- 实现稳定后统一运行一次生产构建；本改造会触及全局控件样式与构建门禁，满足构建准入条件。
- 同步有效设计规则、接入说明、维护矩阵和实际验收证据。

完成条件：行为、实际外框、响应式与隔离均通过；未验证范围明确保留，不将测试或构建通过扩大为全站页面验收通过。

## 6. 验证设计

### 定向测试

- 行尺寸解析：省略/default/small/large、三档页面密度、表单项/表单、父行继承、显式新行和动态切换。
- 真实组件组合：分段、输入、数字、搜索、单/多选、日期/范围、命令、水平按钮选择和普通图标命令。
- 状态和隔离：禁用、加载、动态显示；新建编辑表单；工具行打开 Drawer/Dialog 后编辑控件不受行高度污染。
- 稳定性：切尺寸不重建输入；高级搜索重排/收展保留实例、值、焦点路径和原有查询语义。
- 门禁边界：局部 wrapper 覆盖、内联/绑定高度、静态/动态 size、合法附属入口、多行组件以及嵌套行。
- 维护已有 `AppTabToolbar`、`AppAdvancedSearch`、表单、分段、选择器、按钮和浮层的相关定向回归；不默认运行全量测试。

### 内置浏览器实测

| 维度 | 代表性覆盖 | 通过条件 |
|---|---|---|
| 密度 | 紧凑 / 标准 / 宽松 | 默认操作行的常规控件实际外框分别共同使用 28 / 32 / 36px |
| 表单与行尺寸 | 一级表单、显式 small/large、嵌套行 | 共同高度符合解析规则，单个控件不能悄悄偏离 |
| 视口 | 项目关键桌面 V1=1100×620、V2=1366×768、V3=1440×900；代表性行再覆盖实际换行临界点 | 全部候选入口依然可达，无整页横向溢出，换行后行容器自然增高 |
| 内容与状态 | 长选项、多选摘要、加载、禁用、错误提示、动态图表工具 | 不以裁切、隐藏或压缩文字换取等高，反馈完整可见 |
| 主题与比例 | 明暗主题；100% 及一个非 100% 界面比例 | 外框、文字和焦点无裁切；不把缩放导致的小数像素误判为设计尺寸变化 |
| 上下文边界 | 行内打开编辑弹窗/抽屉，返回缓存页面 | 独立表单维持自身尺寸，关闭/返回后原行输入和布局保留 |

测量固定到控件实际外框，不比较分段内部选中块和输入外壳。使用项目已有缩放换算能力归一到设计 CSS 像素，同组高度差容差不超过 1px；同时观察可见边框、文字垂直对齐、焦点和操作可达性。测量只用于验收，不进入生产布局逻辑。

代表性业务入口至少包括：个股高级搜索、板块筛选、采集任务/日志工具栏、回测表单与稳健性、一个系统查询页和资产搜索抽屉。按真实差异分配视口与状态，不对每个页面重复笛卡尔积测试。

默认使用专用 5181 内置浏览器，不新增或默认运行 Playwright E2E。验证不发起采集、筛选、回测等真实写任务；恢复调试账号的临时尺寸、主题和视口。后端保持现有运行状态；若后续确需运行涉及 DuckDB 的后端测试，另按项目停服与恢复规则执行。

## 8. 风险与交付门槛

- 全局适配可能误作用于表格、弹层、说明和多行控件：必须限定行作用域及参与角色，先做组合验证再迁移。
- 双重继承可能造成“行说 small，库控件仍从 AppForm 得到 large”：必须同时解决共享高度和现有尺寸类的影响，不能只包 ConfigProvider。
- 高级搜索节点迁移可能丢失输入/远程选择状态：保留 keyed 父节点，验证展开、重排和恢复。
- 机械放大所有工具栏会重演视觉环境问题：常规行跟随密度，独立主要设置和附属入口按已确认角色区分。
- 构建与静态检查无法证明真实边框齐平：必须有最终源码对应的浏览器几何与操作证据。

## 10. 实施归类与验收结果

| 候选位置 | 处理结论 |
|---|---|
| 原有通用行、Tab 操作栏、高级搜索 | 共用 `controlRowSizing.ts`；高级搜索保留原稳定节点和 keyed 字段，不额外包裹或重建输入 |
| 行情/策略/训练/数据管理/布局管理/系统管理的页头命令组 | 复用 `AppControlRow`；删除参与控件单独尺寸，保留左右布局与权限事件 |
| 市场分析控制、工作区及详情分区操作插槽、详情抽屉头部、资产搜索 | 共享操作行；门禁跟踪具名操作插槽，不把正文编辑字段误当操作行 |
| 回测参数与执行组、稳健性、配置编辑动作、交易纪律填报/修订动作 | 新行继承所属表单或页面；不机械把原来的逐控件 small 搬到整组 |
| 图表头部 | 保留 header 和已有专用结构，接入同一尺寸解析及 CSS 作用域；两类详情图表的同级图标命令同步清理单独档位 |
| 训练配置的主要执行入口 | 整组显式 large，保留既有主操作层级；不把独立主要执行入口降成普通工具栏 |
| 全局交易纪律快捷卡片规则动作 | 作为紧凑附属操作组整行 small；普通文字入口维持其角色 |
| 表格行操作、反馈重试/状态动作、导航顶栏、关闭/清空、登录、设置项附属入口、图标面板计数与文字清除 | 保留各自角色；AppDataTable/AppRowActions 隔离行尺寸。多行条件编辑器、卡片及参数矩阵不按普通工具行拉伸 |
| 市场列表动作包装 | 已位于 AppWorkspacePane 操作插槽中，自动消费最近行，无需再建重复容器 |

新增模板 AST/PostCSS 门禁与失败夹具，拦截逐控件 size、内联/绑定高度、未知样式包与私有 wrapper 高度。公共控件适配统一覆盖原生库、自有分段/选择和图标命令；数字输入右侧加减按钮按实际外框分半。继承边界同时处理 Teleport 的 Vue 逻辑树和 DOM 的 CSS 树。

浏览器使用 5181 内置浏览器，debug_normal 验证普通行情/回测，debug_system 验证系统入口。实际结果：

- 个股高级搜索与图表控制在紧凑/标准/宽松下共同为 28/32/36px；回测参数和执行组继承表单 36px。
- 板块筛选、采集任务与日志、用户查询均为共同 32px；用户新建弹窗内部仍为自身表单 36px；资产浏览抽屉的分段与搜索为 32px。未保存新用户，未启动采集或回测。
- 系统组件样板覆盖普通/多选下拉（长候选与 +N）、输入、范围日期、数字、两类分段、按钮式单选/多选、普通/loading 命令和图标命令；三档共同尺寸及 V1/V2/V3 均实测，归一化同组高度差不超过 0.01px。低高度自然换行，内容通过抽屉正文滚动可达。
- 动态切换尺寸保留输入值；Tab 从输入进入选择器；禁用与四项字段错误可见，错误不裁切；明暗主题、100% 与自动 94% 比例抽样复核。恢复调试账号原夜间/自适应、页面标准密度与默认视口。

定向组件/消费方测试覆盖高级搜索稳定性、表单与浮层隔离、现有业务回归、样式契约及门禁反例，已全部通过。最终 `npm run build` 通过全部门禁、类型检查与打包；仅保留既有的大包体积提示。此结果不代表全站每页、所有权限/业务状态、远程失败或所有浮层候选完成浏览器验收；其余迁移消费点由源码核查、相关定向测试和最终构建覆盖。没有新增长期 Playwright E2E；本轮不涉及后端与数据库变更。项目契约和页面模板已同步，未发现需要写入全局技能的通用新规则。
