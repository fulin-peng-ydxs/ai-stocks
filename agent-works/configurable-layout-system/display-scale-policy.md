# 界面比例与自动缩放策略

预设管理中的“自动缩放激进程度”写入 `responsiveDefaults.autoScaleResponsiveExponent`，默认 `0.10`，范围 `0～1`，输入步长 `0.01`。指数越大，偏离参考面积时的缩放越明显；零值让自动比例保持 100%。

计算为 `round(100 × (屏幕可用 CSS 面积 / (2560 × 1440)) ^ 指数)`，结果限制在 90%～110%。自动模式与自定义模式独立；自定义滑块按当前显示器可用 CSS 宽高自动保存个人比例档案，不随预设变化。1920×1080 可用面积在默认指数下为 94%，2560×1440 为 100%，3360×1890 为 106%。

## 自定义尺寸档案

- 用户调整自定义比例时保存 `{width, height, percent}`；尺寸来源与自动模式相同，不使用物理像素、DPR、设备名称或浏览器窗口尺寸。
- 当前宽高均在档案 `±15%` 内时采用综合相对距离最近的档案；`5%` 内重复调整更新原档案，无匹配时回退最近一次自定义比例。
- 从自动切到自定义时继承当前自动比例并保存当前尺寸档案；恢复 100% 同样更新当前尺寸档案。
- 档案随既有 `display-scale` 全局用户偏好同步到 PostgreSQL；旧偏好没有档案时保持原 `customPercent` 行为，不新增表、接口或可见档案管理区。

## 配置闭环

- 预设编辑回显、保存、导入导出沿用布局预设配置对象及现有权限。
- 后端只接受范围内有限数值，拒绝布尔值、字符串、空值、越界和非有限数值。
- 运行时按当前外观预设读取策略，切换、同 key 更新和停用回退均同步重算；未选择的预设不影响当前比例。
- 历史配置缺项和非法缓存回退 `0.10`，不覆盖数据库中的既有配置。
- 登录公开配置明确允许该单一字段，仍排除其他响应式、页面和组件配置。首屏从现有预设缓存恢复，初始化缩放时消费已恢复策略。
- 配置继续存于预设 JSON，不新增表、字段、菜单、权限或接口，无需执行 SQL 迁移。

## 复用判断

- 同类实现：预设管理现有组件默认策略、`useLayoutPreset` 运行时覆盖、`useDisplayScale` 自动比例。
- 复用：`el-input-number`、`HelpHint`、预设 API、导入导出与本地预设目录缓存；不新增页面、组件种类或独立偏好存储。
- 共享默认值、范围和防御归一化置于纯策略模块 `displayScalePolicy.ts`，供内置预设、编辑器、运行时与缩放计算复用，避免静态预设反向加载有状态 composable。
- 同步 DESIGN 与页面模板的全局界面比例维护矩阵；已有页面结构和原型不变。

## 验证与自审

- 前端定向验证：自动比例、非法值回退、手动模式隔离、自定义尺寸档案匹配/更新/跨屏回退、预设切换/更新/停用、首屏缓存恢复、原预设契约与管理表单保存。
- 后端纯函数与 Mock 公开配置验证：合法值往返、非法值拒绝、旧配置兼容及公开字段白名单。不调用数据库，不停服。
- 自审覆盖登录前后配置一致性、零值不得被默认值覆盖、手动偏好与尺寸档案隔离、旧配置兼容和现有权限链路。
- 本轮不声称已用真实账号保存平台预设；实际配置写入由用户在预设管理选择目标预设完成。
