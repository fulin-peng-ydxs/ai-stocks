## 核心技术

### 个股列表：服务端排序 + 分页
列表查询全部在 SQL 层完成筛选、排序、分页，不在前端排全量（`backend/api/stocks.py:23` `list_stocks`）。
- 排序字段走白名单映射防注入：`_STOCK_SORT_COLS`（`stocks.py:20`）只放行 `pct_chg / name / industry / code`，其余回落 `pct_chg`；`sort_order` 仅 `asc/desc`。排序统一 `... NULLS LAST, sb.code ASC`（`stocks.py:58`），停牌（当日无行情）的 NULL 涨跌幅恒排末尾，并以 code 作稳定次序键。
- 当日涨跌幅按交易日 `LEFT JOIN daily_bar` 现算 `(close/pre_close-1)*100`（`stocks.py:62`），`trade_date` 缺省取 `max(trade_date)`。
- 退市/ST 口径：`board='退市'` 只看 `delist_date IS NOT NULL`，其余板块一律 `delist_date IS NULL` 排除退市；`board='ST'` 与 `exclude_st` 均读取查询日 `stock_st_status_daily` 的准确点时事实，缺失或刷新批次未发布时拒绝返回残缺结果。
- 行业/概念筛选统一使用同花顺 `board_dict + board_member` 累计归属，选项由 `GET /stocks/membership-options` 按行业、概念稳定返回，列表与分组接口共同消费 `membership_board_code`。指定历史交易日时排除 `first_seen_date` 明确晚于该日的关系；存量空日期视为历史已存在。该口径不同于列表“行业”列的证监会行业分类。
- 只有认证上下文具备 `stock-group:view`（或 system）时才构造 `StockGroupRepo` 并批量调用 `groups_for_codes`；无权限时统一返回空 `groups`，不读取分组资产，也不会因仓库构造而创建默认分组。前端同时隐藏分组列、分组视图和对应页面设置元数据。
- 股票当前页在最终分页行形成后，以响应 `trade_date` 一次批量读取 `stock_board_correlation_state + stock_board_correlation + board_dict` 并附加可选 `related_boards`；分组页先从 PG 取资产、再从 DuckDB 取行情，最终只对当前页按各行 `last_date` 批量合并摘要，禁止跨库 JOIN。业务日期与摘要 `as_of_date` 不一致时行业/概念为空并标记 `as_of_mismatch`，不会用最新冠军装饰历史行。
- 普通列表与分组列表均返回所选交易日的 `is_st + st_as_of_date`，名称后统一显示显式 `ST` 标签；名称列隐藏时标签跟随代码。板块筛选已选择 `ST`、列表上下文已明确全部为 ST 时隐藏重复行内标签，切换到其他筛选后恢复。分组筛选与行内展示消费同一份点时事实，不再只保留内部 `_is_st` 后把展示字段剔除。状态列只表达上市/退市等存续状态，避免与名称旁 ST 标签重复。

### 行情、指标、报价与买卖评估分层

详情页把受保护数据拆为四个独立请求通道，每个通道都有独立 `AbortController` 和递增序号；切股、KeepAlive 停用和卸载会取消在途请求，迟到响应不能覆盖当前股票：

- **复权行情**：`GET /stocks/{code}/bars?adjust=...&lookback=...` 经 `MarketRepository.get_bars` 输出 K线和量能所需的 `pre_close/amount/turnover_rate`；详情显式传 `include_market_values=true`，只对本次返回的 1..6000 根日线日期一次批量读取 `daily_metrics.total_mv/float_mv`，以元返回原始市值，不受价格复权影响。其它消费者不传该参数时保持原响应字段。范围切换重拉行情与指标，复权切换只重拉行情。
- **指标序列**：`GET /stocks/{code}/indicators?lookback=1..6000&fields=...&period=...` 始终保留 `trade_date` 并返回实际周期与复权口径，未知字段在计算前拒绝，NaN/无穷/可空布尔序列化为 `null`。日 K 仍提供详情快照字段和五个 MACD 原子；周/月/年 K 只开放已有周期计算能力的 MACD 五原子。个股 MACD 统一使用前复权历史，前端仅按周期末交易日对齐，不实现第二套公式；日 K 末行同时供“最新指标快照”。
- **最新行情摘要**：独立调用 `GET /stocks/{code}/quote-summary`，对齐该股最新行情日读取原始价格、逐日市值与准确 ST 状态，补充最新股本和量比；当前没有稳定市盈率事实，返回 `null`。失败只降级摘要，不清空已加载图表。
- **买卖评估**：只有同时具备 `trade-profile:view` 与 `stocks:trade-eval` 权限时才加载可见方案并请求 `trade-eval`；方案列表失败或评估失败不阻断行情与指标。

行情 403 是详情页主权限边界：立即清除行情、指标、报价和评估派生数据并取消其它通道，后续 pending/普通失败均不重新展示旧数据，只有新的行情成功响应才解除 permission 状态。MACD 指标请求普通失败则只让 MACD 面板进入局部错误态，K线与量能继续可用。

### 买卖信号：由当前买卖方案推导
个股详情的买卖信号不是固定引擎，而是用「当前选定的买卖指标方案」在该股当日快照上现算（`GET /stocks/{code}/trade-eval`，`stocks.py:156`）：
- 前端选择值透传列表返回的 opaque `profile_ref`；后端由 `TradeProfileRepo.get_visible(profile_ref_or_id)` 解析真实 owner，支持 owner 旧裸 ID、同租户和公开方案，不可见 private 方案统一按不存在处理。
- 取得买/卖条件树后，用 `IndicatorEngine.wide_snapshot` 取单股当日截面，`attach_columns` 预补条件树用到的全部指标列（`collect_indicators`）。
- `eval_conditions` 递归按 AND/OR 合并叶子比较得买入/卖出命中布尔（`trade_profile.py:43`）；`_describe_tree`（`stocks.py:123`）把条件树拍平为每个叶子的中文标签 + 该股是否成立明细，供详情页逐条展示。
- 点时安全：只用 `≤ 当日` 数据，方案所用指标均非横截面，单股快照求值即正确。
- 旧的 `GET /stocks/{code}/signal`（`stocks.py:105`）仍在，按 `ScreenScoreService.compute_signals` 给出 `buy_point` 文案 + `risk_flags` + K线买点标记，与方案评估互补。

### K线、量能与 MACD 三图工作区

- `StockChartWorkspace` 用三个独立 ECharts 实例组成纵向工作区，同一组件实例使用唯一 group 联动光标、日期和缩放；多个 KeepAlive 个股标签不会串联或互相 disconnect。
- 图表一固定为 K线；图表二、三可选量能、MACD 或隐藏，选择已占用类型时自动交换。隐藏会释放面板和分隔线，不保留空白。
- 默认组合为 K 线/量能/MACD，比例 60/20/20。主区拖动或键盘调整只修改当前会话；只有设置抽屉编辑默认值，或用户显式执行“设为默认”时才写入远端偏好，远端失败沿用 localStorage fallback。
- 常规个股和板块行情支持日 K、自然周 K、自然月 K 和自然年 K。K 线、MA 与 VMA 在共享前端周期序列上展示；MACD 由后端先用截止日以前的完整历史按自然周期取末个交易日，再复用唯一的 12/26/9 EMA 与交叉原子定义，最后裁剪输出范围。周期柱以末个交易日为日期，开盘取首日、收盘取末日、高低取极值，前收取首日有效值，成交量/额/换手率累计且全缺失时保持空值；当前未完成周期保留，历史不足或周期末收盘缺失时指标保持空值。周期切换期间旧指标不得对齐到新 K 线。训练和回测仍固定日 K，非日 K 不下钻分时。
- K 线标题首行以共享文字页签承载周期切换，同时展示日期和图表操作入口；标题不重复当前周期，MA 固定在第二行并计入工作区最小高度。低频操作统一进入只覆盖当前工作区的 `StockChartOperationsDrawer`，由默认配置派生的操作只改变页面会话并按需重拉行情，不反写默认值。测算结果复用行情摘要模型：存在常驻摘要区时追加独立分区，否则追加到 K 线 tooltip，图内仅保留选点操作指引。切换周期保留操作模式，但清空光标、选点和区间并恢复完整缩放，测算交易日数取底层实际交易日数量。K 线浮层与详情头部的列宽以最新 K 线和当前可视窗口的格式化结果推导并预留少量字符容量；移动光标时保持宽度，调整窗口后重新计算，窗口外历史与均线热身数据不参与历史容量汇总。详情通过工作区 `quoteWindowChange` 接收窗口行情与测算样本，再加入市值、股本、量比和估值字段，统一消费 `stockQuoteSummaryWidths()`。详情市值随光标日期联动，日线取当天，周/月/年线取该根最后实际交易日，不累计、不向前填充缺口，也不以最新股本乘复权价估算。无光标时回到最新行情摘要；股本始终显示 `stock_basic` 最新采集值；字段名保持总股本/流通股，通过字段名旁的共享 `HelpHint` 说明图标在悬浮或键盘聚焦时说明其不随 K 线日期变化，不作为历史股本事实。历史估值没有逐日事实时显示 `—`。历史成交额、换手率、前收盘等空值同样保持为空，不回退最新行情。单位按每次生成摘要时的实际数值换算，宽度仅在数据或可视窗口变化时汇总，移动光标不发起请求。
- 每幅图有名称和随共享光标更新的指标摘要；MACD 含正负柱、DIFF、DEA、零轴和金叉/死叉标签。信号标签只保留连接事件点的短三角指针，不显示贯穿面板的长引导线或独立圆形锚点。
- 画布取色复用 `--market-up-color` / `--market-down-color` 和预设主题修订版本；明暗、预设 key 或同 key 后端 token 覆盖变化都会重绘现有实例。

### 查询页共享行情分析工作台

- `StocksView` 与 `BoardView` 共同消费 `MarketMasterDetailWorkspace` 和 `StockAnalysisPanel`，统一列表收起、当前观察、最多 6 只对比队列、走势对比与 K 线模式，消费页不复制图表状态机。
- `useStockAnalysisSelection` 管理当前观察和对比队列；`useStockAnalysisSession` 将远端默认值单向投影为页面会话态，`stocks` 与 `board` 按页面键隔离。
- 走势对比固定读前复权股票行情，通过 `GET /stocks/benchmarks/{index_code}/bars` 取显式市场交易日，停牌日延用最后有效收盘。对比指数时统一从首个共同有效日期起算并据此计算超额，个别序列上市较晚只缩短基准期、不否决整体；纯股票间对比时各序列从自身首个有效值起算、上市前留空，不因个别序列缺起点而否决整体。日历失败或为空时进入可重试错误态，重试只重拉日历；单只股票失败时保留已成功曲线，重试只请求失败股票。

### 分组篮子：跨页多选累积与导航
- 选择购物车（`StocksView.vue:216` `cart`）在前端维护，按 code 去重，跨分页/跨搜索/跨普通查询与分组视图累积，切换上下文（切分组）才清空（`StocksView.vue:142`）。表头全选只对「当前页」做并/差集（`toggleAllCur`，`StocksView.vue:232`）。
- 进入详情时把「当前集合」写入 `stockSet` store（`stores/stockSet.ts`，localStorage 持久化）：来源可为分组成员、列表当前页或勾选集。集合记录有序 `items`、`query`（可续拉）、`total`、`loadedPages`、`pageSize`。
- 上一只/下一只导航（`StockDetailView.vue:73` `gotoNeighbor`）：先取集合内相邻 code；到达已加载边界且 `query` 存在时，按 `loadSetPage` 续拉上/下一页并合并（`appendPage` 按页号决定 unshift/push），实现跨页连续翻看。连点用 AbortController 取消在途 + 140ms 防抖只发最终一次（`StockDetailView.vue:137,183`）。

## 业务架构

### 三块功能
1. 个股查询与行情分析（`StocksView.vue`）：按交易日/上市板块/ST/退市/同花顺行业或概念归属/关键词筛选，服务端排序分页；选中股票后在双栏工作台切换多股走势对比或 K 线分析。
2. 个股详情（`StockDetailView.vue`）：K线/量能/MACD 三图工作区 + 最新指标快照 + 当前可见买卖方案在该股的买入/卖出信号与逐条成立明细 + 分组归属编辑 + 集合内上一只/下一只导航。
3. 股票分组（`StocksView.vue` 分组视图 + `stock_groups.py`）：用户手动圈定的股票篮子，含成员加入日期与自加入日起的等权平均涨幅；全市场与分组通过筛选栏首项切换并共用交易日、关键词和板块条件，当前分组在紧凑上下文栏内切换和维护。

### 与其它模块的关系
- 指标模块：详情快照、指标序列、买卖条件求值都依赖 `IndicatorEngine`（实时计算，无指标表）；条件树与评分共用 `resolve_indicator`。
- 买卖方案模块：详情信号直接消费 `trade_profile`（买/卖条件树 + 兜底止盈止损/最大持仓），方案列表由 `tradeProfile` API 提供，默认选首个方案。
- 数据管理模块：列表涨跌幅、K线、分组涨幅均读 `daily_bar`；前复权口径统一 `close*COALESCE(adj_factor_clean, adj_factor)`（`stock_group.py:240,252`）。
- 默认自选分组：只有具备分组权限的业务链路才构造 `StockGroupRepo`；仓库按 `tenant_id + owner_user_id` 确保每个归属者存在 `grp_default_{owner_user_id}`，固定为“自选”和项目默认色，不可改名/改色/删除。

### 涉及表
- `stock_group`（`storage/pg_ddl.py`；`ddl.py` 为迁移保留的旧 DuckDB 定义）：分组元信息 id/name/group_date/description/color/is_default。
- `stock_group_member`（`ddl.py:317`）：主键 `(group_id, code)`，`add_date` 为该股加入日期即涨幅基准，`note` 备注。
- 读：`stock_basic`（板块/退市/名称）、`daily_bar`（行情/复权）。

### 主要 API
- 个股：`GET /stocks`、`/stocks/membership-options`、`/stocks/{code}/bars`、`/stocks/benchmarks/{index_code}/bars`、`/stocks/{code}/indicators`、`/stocks/{code}/trade-eval`、`/stocks/{code}/signal`。
- 分组：`GET/POST /stock-groups`、`GET/PATCH/DELETE /stock-groups/{gid}`、`POST/DELETE /stock-groups/{gid}/members`、`PATCH /stock-groups/{gid}/members/{code}`（改单股加入日）。

## 页面使用说明书

个股与分组模块解决两件事：一是查单只股票当前和历史状态，二是把一批股票保存成可持续跟踪的篮子。

### 1. 个股查询列表

| 控件/列 | 作用 | 说明 |
|---------|------|------|
| 交易日 | 决定涨跌幅和行情截面 | 默认最新交易日 |
| 板块筛选 | 主板/创业板/科创板/ST/退市等 | 退市股单独入口，便于历史复盘 |
| 所属行业/概念 | 单选同花顺行业或概念板块 | 行业、概念合并在一个可搜索下拉中，普通列表与分组共同生效 |
| 关键词 | 按代码或名称搜索 | 服务端筛选 |
| 排序 | 涨跌幅、名称、行业、代码 | 服务端排序，停牌 NULL 排后 |
| 全市场 / 分组 | 切换全市场查询与分组成员列表 | 与板块行情的范围切换交互一致，切换后筛选栏保持不变 |
| 所属分组 | 显示该股票已加入哪些篮子 | 分组名可直接点击进入对应分组，且阻止触发行详情跳转 |
| 勾选框 | 加入当前选择购物车 | 支持跨页累积 |
| 行情分析区 | 对当前观察与对比队列做走势对比或 K 线分析 | 可收起左侧列表；交易日和单股失败均可局部重试 |

**使用路径**：筛选条件缩小范围 → 按涨跌幅或行业排序 → 跨页勾选 → 存为新分组或加入已有分组 → 点击股票进入详情。

### 2. 个股详情页

| 区块 | 展示内容 | 业务用途 |
|------|----------|----------|
| 三图工作区 | 复权 K线、量能、MACD；共享日期、光标和缩放 | 同时复盘价格、成交量和趋势动量 |
| 图表设置与高度 | 图表二/三选择量能、MACD或隐藏；拖动/键盘调整相对高度 | 按用户和有序组合恢复阅读习惯 |
| 最新指标快照 | 均线、强弱、趋势、量能等 | 判断该股处于什么状态 |
| 买卖方案信号 | 当前方案买入/卖出是否触发 | 解释方案在单股上的结果 |
| 条件明细 | 每条条件的当前值与命中状态 | 排查为什么触发/没触发 |
| 分组归属 | 加入/移出分组，维护备注 | 跟踪人工股票池 |
| 上一只/下一只 | 在当前集合中连续翻看 | 适合复盘榜单、筛选结果或分组 |

**详情页和配置管理的关系**：详情页信号来自当前选中的买卖方案，不是固定文案。切换方案或交易日会重新计算条件树，因此它可以用来调试买卖方案。

### 3. 股票分组

| 功能 | 说明 |
|------|------|
| 默认自选 | 系统初始化固定存在，不可删除 |
| 新建分组 | 名称、日期、颜色、说明、成员 |
| 加入已有分组 | 可指定加入日期，作为组内收益基准 |
| 分组详情 | 查看成员、自加入日起涨幅、组内平均涨幅；交易日决定行情与收益截止日，关键词和板块继续复用顶部筛选栏 |
| 组内维护 | 移出成员、编辑备注、调整加入日 |
| 分组切换与维护 | 点击紧凑栏中的分组名下拉切换；编辑和删除固定在栏右侧，默认自选不可删除 |

**分组闭环**：


### 4. 与其它模块的关联关系

| 模块 | 关联方式 |
|------|----------|
| 数据管理 | 提供 K线、涨跌幅、市值、退市状态；数据缺口会直接反映在详情页 |
| 配置管理 | 买卖方案决定详情页信号；指标注册表决定快照字段 |
| 每日榜单 | 榜单股票可进入详情复盘，也可手动沉淀进分组 |
| 策略筛选 | 筛选命中股票可进入详情或转入人工分组 |
| 回测验证 | 逐笔成交股票可回详情页复盘买卖点是否合理 |

### 5. 使用注意事项

| 注意项 | 说明 |
|--------|------|
| 跨页选择 | 表头全选只作用当前页，购物车负责跨页累积 |
| 集合导航 | 详情页上一只/下一只基于进入详情时的集合快照 |
| 加入日期 | 分组涨幅从加入日基准价开始算，加入日不同涨幅不同 |
| 退市股 | 退市股可查历史，但不会进入普通在市板块 |
| 信号为空 | 可能是数据不足、指标无法计算或方案条件未满足，需要看条件明细和数据质量 |

## 业务流程

### 查个股详情看信号
1. 个股查询页选交易日/板块/关键词，服务端返回当页列表（含涨跌幅、所属分组）。
2. 点击某行进入详情：写入「当前集合」（含本页查询快照），跳 `/stocks/{code}`。
3. 详情页分通道并发拉复权行情、指标序列和原始最新报价；默认三图按交易日对齐，MACD 局部失败不影响 K线/量能。
4. 同时具备 `trade-profile:view` 与 `stocks:trade-eval` 时加载可见买卖方案并透传 opaque `profile_ref` 做评估；切换方案即重算信号。用上一只/下一只在集合内连续翻看，到边界自动续拉下一页。
5. 图表二/三默认类型和默认高度由设置抽屉或显式“设为默认”保存；主区拖动和键盘调整只在当前会话生效。

### 建 / 用股票分组
1. 普通查询中跨页/跨搜索勾选股票，累积进底部购物车。
2. 「存为新分组」（填名称/建组日期/颜色/说明，成员加入日默认=建组日期）或「加入已有分组」（指定加入日为涨幅基准，已在组内者保留原加入日）。
3. 通过筛选栏首项切到分组：紧凑上下文栏显示当前分组及整组等权平均涨幅，成员表继续复用顶部交易日、关键词和板块筛选，并按服务端分页/排序展示加入日期、自加入日起截止所选交易日的涨幅和截至日。
4. 组内可勾选成员「从本组移出」、编辑分组元信息、删除分组（默认自选除外）；点成员进详情后以该组为集合导航。

## 风险事项

| 等级 | 风险点 | 影响 | 建议 |
|------|--------|------|------|
| <span style="color:#dc2626">●</span> 高 | 分组涨幅逐成员查 SQL（`stock_group.py:229`） | 超大分组打开耗时随成员数线性放大 | 大分组控制规模；后续批量化基准价查询 |
| <span style="color:#f59e0b">●</span> 中 | 分组详情搜索/排序/分页在 Python 内存层完成 | 成员极多时需全量物化再切片 | 大分组避免复杂排序；后续下推 SQL |
| <span style="color:#f59e0b">●</span> 中 | `add_members` 返回 added 计数含已存在成员（`stock_group.py:124`） | 前端提示数量可能偏大 | 返回实际插入数，或提示"已提交成员数" |
| <span style="color:#16a34a">●</span> 低 | `stockSet` 依赖 localStorage 快照 | 多标签页变更后相邻导航不会同步 | 需要最新集合时从列表重新进入详情 |
| <span style="color:#16a34a">●</span> 低 | `trade-eval` 指标无法计算时返回 400 | 详情页买卖评估进入局部错误态，但图表仍可用 | 检查方案引用指标、数据质量和条件明细后单独重试评估 |
