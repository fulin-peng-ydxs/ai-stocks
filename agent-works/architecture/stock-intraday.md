# 个股日 K 下钻分时

## 功能边界

个股详情页和共享 `StockAnalysisPanel` 的 K 线模式允许点击日 K 蜡烛，按需打开对应交易日的分时弹窗。共享分析面板覆盖个股查询、每日榜单和连板天梯；板块行情、盘感训练和回测交易回放不启用下钻。

弹窗只有两个联动绘图区：上图为每分钟收盘价、当日累计均价和昨收参考线，下图为分钟成交量。价格左轴显示价格、右轴按昨收显示涨跌幅，量能数值轴使用左侧；午休时段不补点，图表连接源端实际返回的相邻分钟。系统仍是 EOD 产品，弹窗不轮询、不产生盘中日 K。

## 数据口径与接口

`GET /api/stocks/{code}/intraday?trade_date=YYYY-MM-DD` 复用 `stocks:view` 权限，返回 `frequency=1m` 及 `ready|partial|out_of_range|no_data` 业务状态。分钟点包含 `time/open/high/low/close/volume/amount/average_price`：

- 价格线使用分钟 `close`；`volume` 在接口、缓存和页面中固定为手（1 手 = 100 股），新浪源由股除以 100，东财源原值即为手；
- 累计均价由服务端按当日累计成交额除以 `累计手数 × 100` 计算，不使用未来分钟；
- 量柱统一按上一分钟收盘判断涨跌，首点按昨收判断，无参考时保持中性；东财开盘占位 0 归一为 NULL，不伪造开盘价；
- 昨收读取本地 `daily_bar.pre_close`；分钟价格始终不复权；
- 分钟点缺失时不补价格、不补成交量，保留真实点并返回 `partial`；
- 未采集归档的日期统一返回 `no_data`，查询不按近期源窗口限制历史日期，也不调用源站；`out_of_range` 仅保留兼容旧接口，前端与未采集空态统一承接；
- 查询只从 DuckDB/归档缓存读取，Redis 故障降级读取数据库；读取异常在弹窗内处理，不触发全局错误提示。页面只说明未采集或采集不完整，采集边界、原因、进度及质量统一由数据管理模块解释。

主源为新浪 1 分钟近期窗口，固定请求 1970 个分钟点；主源对目标日缺失、不完整或请求失败时取东财 1 分钟接口兜底，东财实际仅覆盖最近 5 个交易日。两个源都使用 `intraday.request_timeout_sec`，并在适配层完成手/元单位归一。Baostock 最小粒度为 5 分钟，不参与此功能，避免同一弹窗出现混合粒度。

源端实际省略的分钟仍按缺口记录，不因点数稳定而放宽完整性：新浪可能直接不返回 14:58、14:59，窗口最早交易日也可能被 1970 点上限截断；这些日期继续尝试备用源，不能补造分钟或跨源拼接。

## Redis 缓存与源站保护

已收盘分钟只由数据管理的独立 `intraday_ingest` 任务写入 DuckDB 的 `stock_intraday_bar`，逐股逐日覆盖与缓存修订保存在 `stock_intraday_coverage`，独立监控起点保存在 `stock_intraday_monitor`，长期保留。查询先定向读取该股该日覆盖修订，再读取该版本的 Redis 归档缓存；未命中或 Redis 故障时读取 DuckDB 分钟事实，回填失败不影响返回。`archived`、`archive_start/end` 表示归档状态和边界；旧 `supported_start/end` 兼容保留但固定返回 NULL，源端采集窗口仅在数据管理解释。

Redis 行情缓存仅来自已落库事实，按“股票 + 日期 + 修订”保存，TTL 默认 43200 秒；修订变化后不会再命中旧事实，不依赖旧 key 删除成功。未采集日期不会读取任何旧源窗口缓存，不访问外部源，也不创建采集任务；部分归档原样返回 `partial`，补齐由数据管理采集/修复完成。

取源逻辑集中在 `IntradaySourceService`，供数据管理采集、修复和显式源探活复用。每股近期候选仅存于本次采集内存，不读写 Redis 源窗口；增量跳过已完整归档，重采主动取源。行情写任务复用全局单写互斥，所有源请求额外共享 Redis 源站锁，全局串行、相邻启动至少间隔 2 秒；单次超时 15 秒，每源仅退避重试 1 次。锁释放使用随机令牌 compare-and-delete，锁等待、限流和退避均支持取消。Redis 还保存限流时间和失败保护状态；Redis 故障时采集不绕过源站保护，已入库查询继续可用。

东财连续 3 次取源失败（每次已耗尽有限重试）后暂时熔断，冷却复用 `intraday.negative_ttl_sec`，默认 60 秒。计数和到期时间存 Redis，跨股票、任务、进程重启共享，使用 Redis 时钟并在全局源锁内检查和更新。到期只允许一次恢复请求；失败立即重新熔断，连通后清零，正常空响应也只证明接口连通，不证明有数据、停牌或完整。采集、定向修复和显式源探活均遵守相同保护。熔断期间不等待冷却、不请求东财，继续保存新浪整日候选；失败原因明确记录为暂时熔断，股票保留续跑资格，质量缺口仍由实际事实复检。日志记录熔断、到期探测及恢复，不逐股重复发送网络错误。

相关配置位于 `config/settings.yaml` 的 `intraday` 段，不进入管理页面；`enabled` 仅控制采集，关闭后仍可查询归档。不得修改 Redis 全局淘汰策略。后端运行日志保留源名称、行数、耗时和失败类型；PG 任务日志按逐股记录范围、完整跳过/待取源日数、主备源请求/有限重试、有效点及目标日完整数、落库结果和复检阶段。请求前和取源结束立即刷新，进度提交时同步刷新；服务端与页面均只保留最近 2000 条，不写逐分钟明细；修复前旧日志的 None/? 计数在页面明确显示为未记录，不猜测历史数量。续跑按任务检查点解释已完成/总数及失败重试数量，计数缺失时明确说明，不能展示 None 或问号占位。

## 独立采集、覆盖与质量

- 手动入口为“数据采集 → 分时采集”，默认全市场，也可指定股票。mode=update 为近期增量补采，mode=refetch 必须带 date_start，可选 date_end。任务、日志、取消与续跑复用 PG async_task；行情写任务全局互斥。任务调度支持相同参数、时间/依赖触发及重试，新建分时调度默认关闭，不自动建立或启用调度。
- 使用 eod_dates 的北京时间 15:30 统一边界，目标上界同时受本地已收盘日线约束。任务首跑冻结股票池、监控起点和日期上界，续跑不漂移。首次从当前源端可采集窗口的首个交易日起步，按股票将起点独立固定在 stock_intraday_monitor；空响应、技术失败或仅重采子区间都不能前移起点。旧归档按最早覆盖日迁移且不覆盖已固定起点。质量检查按起点与交易日历推导至本地最新已收盘日线的应有日期，按上市/退市/明确停牌事实排除；即使某日没有个股日线或逐日覆盖记录也不能默认为停牌或漏过整日缺失。不要求起点前的十年分钟历史。
- 每股请求一次近期窗口，归档时排除未收盘日期。候选由采集任务在收盘后直接取得；已有完整归档增量跳过，显式重采才刷新。按目标日期和完整性决定是否取备用源；每个交易日只选择一个整日候选，完整优先，其次有效预期分钟数、总有效点数，同等覆盖优先新浪。不以空、失败或较差候选替换已有较好事实，不跨源拼接分钟。
- 分钟价格原始不复权；量为手、额为元，开盘占位为 NULL。价格非法、负/非有限量额拒用，非交易时段过滤，重复分钟保留最后记录并保存诊断。按实际分钟计算累计均价，不补午休或缺失分钟。
- 单股失败不阻断其他股票，成功部分保留；结果分别报告新增、更新、完整跳过、部分覆盖、缺失和技术失败。技术失败使任务失败并保留逐股 checkpoint；取消等待当前请求安全返回，退避、限流和锁等待可取消。
- 历史与最新整日缺失统一为 intraday_gap，不另增历史缺失类型；intraday_gap、intraday_partial、intraday_invalid 进入独立“分时”质量层，不影响日线 L1-L4 评分。质量扫描、采集收尾、定向修复复检、结构体检共用契约；只在实际问题消失后关闭台账。已有归档即使仍完整，发现物理分钟丢失也必须重新报出。
- 超出现有源窗口的缺口保持待处理并说明原因，修复任务不发无效请求；空响应和请求失败不确认停牌。人工忽略/恢复监控沿用现有逐日问题规则。概览、逐股覆盖和数据目录同时展示监控范围及覆盖，不能用单股最新日期宣布全市场鲜活。
- 采集及调度共用 IntradayTaskScopeFields 与 intradayIngest.ts，无新增导航页、布局原型、系统组件种类或组件配置字段；权限继续使用 stocks:view 和既有系统数据管理权限。
- DDL 统一登记、目录中文元数据和显式鲜活度/质量策略随表接入；升级审核文件为 agent-works/stock-data-ingestion/intraday-persistence/schema.sql。回退旧代码时保留三张分时事实/监控表，避免删除不可再取得的历史分钟。

## 前端组件契约

`StockChartWorkspace` 的 `enableIntradayDrilldown` 默认关闭；开启后只处理 `candlestick` 系列单击并发出 `barClick(tradeDate)`。`StockIntradayDialog` 统一负责请求、取消、迟到响应隔离和业务状态，`StockIntradayChart` 统一生成双 grid ECharts 配置。两个入口通过 `useStockIntradayDrilldown` 共享打开、重复点击和切股关闭状态，不复制请求逻辑。

图表消费 `useStockChartTheme`：价格为主题主色，均价复用 MA5 身份色，昨收为中性虚线并只标 `0%`，量柱使用金融涨跌 token。价格纵轴以昨收为正中心按当日最大偏离上下对称展开，保证基准线始终可见；达到常见涨跌停边界时不再添加额外纵向留白。上下绘图区统一预留 64px 左右轴边界，保证价格和量能时间轴垂直对齐；日 K 工作区和分时共同消费 `app-stock-chart-frame` 外框、`StockChartPanelHeader` 标题栏、`StockChartLegend` 图例项，日线与分钟量柱共同消费 `buildStockVolumeBarSeries()`。上图显示“分时”及价格/均价图例，下图显示“量能”并使用共享双边分隔形态，禁止在 ECharts 画布或消费页另画标题、图例标识、边框或分隔线。两图按实际画布高度计算紧凑布局，底部时间轴固定展示 `09:30`、`11:30`、`15:00`，不把午休结束时间并入中间标签。弹窗顶部行情摘要消费 `StockQuoteSummary`：最新价作为无标签、适度强调的独立列，其余字段按每列最多三项紧凑排列，并与 K 线浮层共享 `StockQuoteSummaryModel`；旧 `.app-metric-*` 等宽指标网格已废弃。底部可见缩放条和画布内缩放同步价格/量能两图，尺寸或主题重绘时保留当前缩放范围。`partial` 在图表上方复用 `AppStatusNotice` 显示横向警告；范围、空数据和错误复用 `AppStateBlock`。关闭弹窗、切股、换日或重复点击都会取消/隔离旧请求，旧响应不得覆盖当前状态。

价格和量能绘图区均隐藏左右数值轴边框，水平网格线与日 K 统一为实线，只有昨收基准线保留虚线。

## 验证与运维

后端定向测试覆盖源字段归一、不复权参数、查询不取源/不写库、累计均价、数据库缓存命中与修订、无视旧源窗口缓存、失败保护、跨股票全局串行、Redis 故障下查询降级/采集关闭失败和 API 权限/503 映射。前端定向测试覆盖蜡烛事件、双绘图区/三序列、左右坐标映射、涨跌停边界、主题色、弹窗状态、取消与迟到响应，以及共享分析面板接入。

真实源冒烟只选择本地最新 8 个交易日内的股票日期，并确认持久归档后不依赖在线窗口，清除缓存或 Redis 故障仍能读取。代表性规模验证通过真实服务入口、隔离库及合成源窗口执行，使用 INTRADAY_SCALE_STOCKS=5000 python -m pytest backend/tests/test_intraday_scale.py -q -s；不会联网采集全市场或写入开发库。公开免费接口可能临时限流或调整返回结构；采集失败时通过数据管理任务日志检查源端和 Redis 保护状态，不通过提高并发或绕开保护重试解决。
