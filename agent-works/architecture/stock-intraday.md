# 个股与指数分时归档及日 K 下钻

## 功能边界

本文维护个股与市场指数的分钟采集、归档、质检和修复契约，以及已接入的个股分时展示。任务与质量管理入口见 [data-management.md](data-management.md)，请求配置见 [environment-configuration.md](environment-configuration.md)。指数采集不代表新增独立指数详情页。

个股详情页和共享 `StockAnalysisPanel` 的 K 线模式允许点击日 K 蜡烛，按需打开对应交易日的分时弹窗。共享分析面板覆盖个股查询、每日榜单和连板天梯；板块行情、盘感训练和回测交易回放不启用下钻。

弹窗只有两个联动绘图区：上图为每分钟收盘价、当日累计均价和昨收参考线，下图为分钟成交量。价格左轴显示价格、右轴按昨收显示涨跌幅，量能数值轴使用左侧；午休时段不补点，图表连接源端实际返回的相邻分钟。系统仍是 EOD 产品，弹窗不轮询、不产生盘中日 K。

## 数据口径与接口

`GET /api/stocks/{code}/intraday?trade_date=YYYY-MM-DD` 复用 `stocks:view` 权限，返回 `frequency=1m` 及 `ready|partial|out_of_range|no_data` 业务状态。分钟点包含 `time/open/high/low/close/volume/amount/average_price`：

- 价格线使用分钟 `close`；`volume` 在接口、缓存和页面中固定为手（1 手 = 100 股），新浪及同花顺源由股除以 100，东财源原值即为手；
- 累计均价由服务端按当日累计成交额除以 `累计手数 × 100` 计算，不使用未来分钟；
- 量柱统一按上一分钟收盘判断涨跌，首点按昨收判断，无参考时保持中性；东财开盘占位 0 归一为 NULL，不伪造开盘价；
- 昨收读取本地 `daily_bar.pre_close`；分钟价格始终不复权；
- 分钟点缺失时不补价格、不补成交量，保留真实点并返回 `partial`；
- 未采集归档的日期统一返回 `no_data`，查询不按近期源窗口限制历史日期，也不调用源站；`out_of_range` 仅保留兼容旧接口，前端与未采集空态统一承接；
- 查询只从 DuckDB/归档缓存读取，Redis 故障降级读取数据库；读取异常在弹窗内处理，不触发全局错误提示。页面只说明未采集或采集不完整，采集边界、原因、进度及质量统一由数据管理模块解释。

常规 `intraday_ingest`（近期增量和日期区间重采）按对象选择主源：个股请求新浪 1 分钟近期窗口（1970 点），市场指数请求同花顺年度 1 分钟响应。缺失、不完整进入同一分时质检。仅质检定向修复可使用内部 `allow_fallback=True`：个股按新浪→同花顺→东财，指数按同花顺→新浪→东财；该开关不对外暴露为任务参数。东财实际仅覆盖最近 5 个交易日，开市时包含尚未收盘的当天；修复目标超出该窗口时跳过东财，仍可核验同花顺，不向东财发送无效请求。同花顺使用 `https://d.10jqka.com.cn/v6/line/hs_{code}/60/{year}.js` 的 1 分钟不复权年度响应；按目标年份各请求一次，校验回调中的股票、周期、年份及内容日期，不使用截断首日的 last10000。请求携带浏览器标识与对应股票页的 `Referer`；缺少请求头时可能收到空 404，HTTP 失败不能作为日期不可覆盖的证据。年度路径不表示覆盖全年，不承诺固定两个月；实际首尾、逐日分钟及成功请求年份保存为来源证据。三个源都使用系统生效配置 `datasource.socket_timeout_sec`，并在适配层完成手/元单位归一。Baostock 最小粒度为 5 分钟，不参与此功能，避免同一弹窗出现混合粒度。

个股完整性按必需时点集合判断：09:31–11:30、13:01–14:57 及 15:00，共 238 个成交柱时点。沪深股票 14:57–15:00 为收盘集合竞价，新浪省略没有独立撮合的 14:58、14:59 不构成分钟缺失；源端实际返回这两点或 09:30、13:00 时仍保留。缺少任一必需时点（包括 15:00）继续判为不完整，不能仅凭总点数达标放行，也不能补造分钟或跨源拼接。本次 1970 条请求形成的响应首日截断仍是实际覆盖缺口；该条数不能证明新浪所有接口的历史能力上限。此处完整性仅表示分钟覆盖，不代表分钟量额与日线已核验一致。规则依据：[上交所交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)、[深交所交易时间说明](https://www.szse.cn/www/investor/knowledge/stock/deal/t20191204_572383.html)。


市场指数要求09:31–11:30、13:01–15:00全部240个必需时点；09:30、13:00存在时保留，但不能抵扣其他缺点。指数不继承股票集合竞价豁免、停牌和复权规则。代码显式保留交易所后缀；同花顺沪市指数使用登记的 `1A0001` / `1B0300` / `1B0905` / `1B0688`，深市指数使用 `399001` / `399006`，不得误取同号个股。指数查询不按量额商生成均价点位。

分时 K 线与日线是不同的源端数据链路，覆盖完整不能代替量额一致性核验。例如浦发银行 2026-10-19：新浪原始 1/5/15/30/60 分钟数据的成交量合计均为 54,012,499 股，日线原始量为 54,074,699 股；1 分钟按 5 分钟重新聚合逐桶相等，适配、清洗和候选构建前后均保留 238 点及相同总量。这将差异定位在源站返回之前，而非本系统转换或删行。公开大单明细不是完整逐笔，不能用于认定缺失的是哪几笔成交；不得指定某分钟补入差额、按日量比例放大分钟量，或把来源一致性当作现有三种质量类型已经保证的事实。

## Redis 缓存与源站保护

已收盘分钟只由数据管理的独立 `intraday_ingest` 任务写入 DuckDB 的 `stock_intraday_bar`，逐标的逐日覆盖与缓存修订保存在 `stock_intraday_coverage`，全局边界持久化保存在 `stock_intraday_monitor`，长期保留。查询先定向读取该股该日覆盖修订，再读取该版本的 Redis 归档缓存；未命中或 Redis 故障时读取 DuckDB 分钟事实，回填失败不影响返回。`archived`、`archive_start/end` 表示归档状态和边界；旧 `supported_start/end` 兼容保留但固定返回 NULL，源端采集窗口仅在数据管理解释。

Redis 行情缓存仅来自已落库事实，按“股票 + 日期 + 修订”保存，TTL 默认 43200 秒；修订变化后不会再命中旧事实，不依赖旧 key 删除成功。未采集日期不会读取任何旧源窗口缓存，不访问外部源，也不创建采集任务；部分归档原样返回 `partial`，补齐由数据管理采集/修复完成。

取源逻辑集中在 `IntradaySourceService`，供采集、修复和显式测试复用；每股窗口只保存在本次任务内存，不读写Redis源窗口缓存。常规增量跳过完整归档，重采主动取源；单股窗口不限制跨股票并发。日常采集与质检恢复在任务开始/续跑时读取系统 `datasource.update_concurrency`，不另设分时并发参数；设为1时串行，设为4时最多4股同时取源，实际请求仍受来源频率限制。通过共享有界队列只保留在途股票，工作线程独立取得候选与来源观察，主线程串行保存证据、整日归档、复检和检查点。任务取消停止提交新股票，限流和退避及时退出，等待在途请求安全结束后才进入终态；仅已完成归档收口的股票进入完成检查点。批量分时修复按选定问题冻结股票/日期组，提交网络工作前排除已忽略、已解决及问题检查点已完成的记录，使用同一队列；每股归档后立即沿用定向复检、台账同步与问题检查点收口，再提交该股归档完成检查点；不等待整批取源结束。续跑复用嵌套的归档检查点，先收敛旧版本已归档但台账尚未关闭的股票，避免已完成股票重复取源；归档检查点中的股票若仍有待修日期，须恢复其补采资格，不能把“请求无异常”视为“问题已解决”。

分时取源直接调用公共 `request_policy` 解析参数，不在编排层另组限流、超时、尝试与退避配置。新浪、东财、同花顺及上交所的网络参数消费统一请求策略；各实际来源共享请求起始频率，HTTP等待期间不持有排他锁，增加并发不放大限流值。新浪日线与分时、东财股本估值与分时分别共享来源限额，同花顺个股/指数分钟与板块接口分别保护。Redis故障不绕过源站保护，归档查询仍可降级数据库读取。参数含义、旧板块覆盖继承及生效边界统一见[环境与配置加载](environment-configuration.md#行情请求参数与来源能力)。

采集、定向修复和显式源探活统一使用系统请求配置，不维护来源级熔断或单股失败短缓存；单股失败不抑制其他股票或后续任务的实际请求。旧版本 Redis 中的熔断和失败短缓存键不再读取，按原 TTL 自行到期。每个符合取源条件的来源按系统配置完成有限重试，失败后继续后续可用来源，并保留已取得的整日候选。本次有效整日候选已补齐全部目标日且归档检查通过时，前序来源失败仅保留为请求警告，不将该股计为技术失败或要求重复续跑；目标仍不完整或存在数据异常时保留技术失败及重试资格；全部请求失败的区间重采仍报告失败，不能用旧完整归档冒充本次取源成功。台账与修复日志共用逐来源的具体原因，未解决项列出目标日期、缺失分钟、来源实际范围及请求错误；日志记录股票、目标日期、来源和具体错误；质量缺口仍由实际归档事实复检，失败及空响应不能证明停牌、日期不可覆盖或完整。修复日志逐来源说明候选取源或跳过及具体依据：目标日不在东财范围时列出实际五交易日起止，最近响应无更好候选时列出范围；前序整日候选已完整时说明后续来源无需请求。有响应时同时记录实际首尾和目标日完整数量，不能将候选选择日志当作已发出请求。

分钟窗口与归档缓存配置位于 `config/settings.yaml` 的 `intraday` 段；网络请求参数与数据源能力/健康统一在系统配置「数据治理」维护。`intraday.enabled` 仅控制采集，关闭后仍可查询归档。不得修改 Redis 全局淘汰策略。后端运行日志保留源名称、行数、耗时和失败类型；PG 任务日志按逐股记录范围、完整跳过/待取源日数、主备源请求/有限重试、有效点及目标日完整数、落库结果和复检阶段。请求前和取源结束立即刷新，进度提交时同步刷新；分时恢复子上下文将当前取源信息与已处理/已解决问题数上报外层任务，不能仅写日志而让任务列表停留在启动进度；服务端与页面均只保留最近 2000 条，不写逐分钟明细；修复前旧日志的 None/? 计数在页面明确显示为未记录，不猜测历史数量。续跑按任务检查点解释已完成/总数及失败重试数量，计数缺失时明确说明，不能展示 None 或问号占位。

## 独立采集、覆盖与质量

- 手动入口为“数据采集 → 分时采集”，默认个股＋已配置市场指数，可选仅个股、仅指数以及指定标的。采集与调度共用 `asset_type=all|stock|index`；旧参数未指定时按all解释。mode=update 为近期增量补采，mode=refetch 必须带 date_start，可选 date_end。任务、日志、取消与续跑复用 PG async_task；行情写任务全局互斥。任务调度支持相同参数、时间/依赖触发及重试，新建分时调度默认关闭，不自动建立或启用调度。
- 使用 eod_dates 的北京时间15:30统一边界，目标上界受对应本地日线约束（个股 `daily_bar`，指数 `index_bar`）。首次指数默认从全局起点采集，源响应中更早记录不自动归档；当天源数据未齐时保留整日缺失或分钟不完整，后续增量/修复可补齐，不能把源端未就绪当作完整。
- 全部个股与已配置指数的质检共用全局最早归档交易日。`stock_intraday_monitor` 保存只前移的持久化边界：成功补采到更早交易日后自动前移全部标的范围并同步全局质量台账；空响应、技术失败、较早请求日期均不扩张范围，最早日分钟或覆盖记录丢失也不能使边界后移。旧归档按真实分钟最早日与旧边界取最小值迁移。按日历生成应有日期，个股排除上市前、退市后和明确停牌；指数按已配置范围及本地指数日线起始日期生成，不依赖股票资料。不因某日没有日线/覆盖记录而默认为停牌。任务首跑冻结代码、实际日期与范围，续跑不漂移；人工日期区间重采允许尝试更早历史，但只有真正归档才前移起点。
- 每股各来源取一次窗口，同花顺跨年目标按年份分别取全响应，归档时排除未收盘日期。候选由采集任务在收盘后直接取得；已有完整归档增量跳过，显式重采才刷新。仅质检修复按目标日期和完整性决定是否取备用源；每个交易日只选择一个整日候选，完整优先，其次有效必需分钟数、总有效点数，同等覆盖优先各标的主源（个股新浪、指数同花顺）。不以空、失败或较差候选替换已有较好事实，不跨源拼接分钟。
- 分钟价格原始不复权；量为手、额为元，开盘占位为 NULL。价格非法、负/非有限量额拒用，非交易时段过滤，重复分钟保留最后记录并保存诊断。按实际分钟计算累计均价，不补午休或缺失分钟。
- 单股失败不阻断其他股票，成功部分保留；结果分别报告新增、更新、完整跳过、部分覆盖、缺失和技术失败。技术失败使任务失败并保留逐股 checkpoint；取消等待当前请求安全返回，退避、限流和锁等待可取消。
- 历史与最新整日缺失统一为 intraday_gap，不另增历史缺失类型；intraday_gap、intraday_partial、intraday_invalid 进入独立“分时”质量层（个股与指数共用，质量页按对象筛选；列表、汇总和批量处置使用相同条件），不影响日线 L1-L4 评分。质量扫描、采集收尾、定向修复复检、结构体检共用契约；只在实际问题消失后关闭台账。已有归档即使仍完整，发现物理分钟丢失也必须重新报出。
- 最近八个交易日仅用于首次近期目标规划，不作为历史修复的硬门禁。缺口保持待处理，能否补采由逐股逐来源真实响应证据判断；空响应和请求失败不确认停牌，也不证明历史永久不可得。人工忽略/恢复监控沿用现有逐日问题规则。概览、逐股覆盖和数据目录同时展示监控范围及覆盖，不能用单股最新日期宣布全市场鲜活。
- 采集及调度共用 IntradayTaskScopeFields 与 intradayIngest.ts，无新增导航页、布局原型、系统组件种类或组件配置字段；权限继续使用 stocks:view 和既有系统数据管理权限。
- DDL 统一登记、目录中文元数据和显式鲜活度/质量策略随表接入；升级审核文件为 agent-works/stock-data-ingestion/intraday-persistence/schema.sql。回退旧代码时保留分时事实、监控及来源证据表，避免删除不可再取得的历史分钟。

## 来源证据、修复与存量台账

`stock_intraday_source_state` 以股票、来源为键，保存最近真实请求时间、结果、任务及最近有效响应证据。证据记录完整响应的观察时间、实际首尾分钟、请求条数、原始/有效点数、逐日点数及缺失分钟集合，不能用过滤到目标日期后的候选推断窗口；错误或空响应不覆盖最近有效窗口。来源证据和行情事实分开，较差候选可更新来源观察，但不能覆盖较好归档，也不改变归档修订或伪造成功溯源。

`IntradayEvidence` 为采集、质量扫描、质量列表、单条/批量修复及按类型调度提供同一可修复性判断。只有当前交易会话内、同一接入规则的有效响应达到本次请求条数，且缺失分钟全部早于响应起点，才判为当前来源无法覆盖；响应首日标记 `window_truncated`，更早日期标记 `outside_observed_window`。少量响应、尾部尚未就绪、当日可能补发的缺柱或技术失败都保留重试资格。对于历史已收盘日，若最近有效响应已覆盖至该日收盘，但仍缺少所有待补分钟，或整日必需分钟覆盖不优于已有归档，则当前主源自动重复无收益；可继续尝试有覆盖能力的备用源，或手动重新核验。首日截断与尾段内部缺柱可并存，不能只比较首尾范围。证据过期至下一交易会话、接入规则/请求条数变化时需要重新核验；不是永久禁止获取历史。东财仍受其明确的近五交易日能力限制。同花顺不套用新浪八日或东财五日门槛；只有同会话内成功请求过该年份的实际年度响应未覆盖待补分钟，才跳过普通重复请求，手动重新核验仍可尝试。跨年中部分年份故障时保留其他年份已取得候选，并如实记录失败，不能把成功年份的范围当成失败年份不存在的证据。

质量类型继续保持整日缺失、分钟不完整和数据非法三类；原因、完整性、可修复性分别表达。详情记录实际/必需分钟数、完整缺失分钟及合并时段、来源观察与最近修复结果。首日部分归档不后移监控起点；只有来源返回部分数据不能解释为停牌或真实无成交。旧台账通过共用扫描原位补充诊断，保留 ID、忽略规则与最近修复记录；没有历史请求证据的记录标为待核验，不倒造截断证据。

修复先复检数据库；已消失的问题直接收敛。一个任务冻结问题 ID 并按股票连续分组，同股选中日期共用各来源窗口，同花顺按目标年份分别取源，针对所有选中日期落库复检；仅保留当前股票的复检结果，不持有全市场分钟响应。取消与续跑沿用成功问题 checkpoint，不混入后来新检出的问题。任务结果区分已解决、改善未完整、未改善、当前来源无法覆盖和技术失败；只在实际复检通过后关闭台账，不追加无证据的“疑源端口径”。

普通修复和调度跳过有明确不可覆盖证据的目标，但保持 `open`；任务结果 `retryable=false` 阻止无效的任务自身重试，不改变普通失败依赖。质量页沿用 `AppRowActions`，可修复项“补采复检”，当前无法覆盖项“重新核验”；后者调用同一个受系统权限保护的修复 API，显式传 `recheck_source=true`，仍经异步任务、源站保护和实际复检。列表读取只重新解释已有证据，不发在线请求。

存量诊断可通过既有 `verify` 异步任务的 `scope=intraday` 定向扫描，也可指定 `codes`；只补充质量详情、同步覆盖和收敛真实消失问题，不联网、不改监控起点、不重写分钟。普通全量质检继续包含同一分时扫描，任务汇总同时计入分时问题。

概览复用同一累计覆盖口径，另提供 `bar_rows` 实际分钟行数与 `latest_expected_stocks/latest_complete_stocks` 目标日逐股统计；目标日完整率按后两者计算，不能用全表最大归档日代表全市场达标。指标、逐股覆盖及台账入口的页面承接统一见[数据概览说明](data-management.md#统计内容与操作映射)。

## 前端组件契约

`StockChartWorkspace` 的 `enableIntradayDrilldown` 默认关闭；开启后只处理 `candlestick` 系列单击并发出 `barClick(tradeDate)`。`StockIntradayDialog` 统一负责请求、取消、迟到响应隔离和业务状态，`StockIntradayChart` 统一生成双 grid ECharts 配置。两个入口通过 `useStockIntradayDrilldown` 共享打开、重复点击和切股关闭状态，不复制请求逻辑。

图表消费 `useStockChartTheme`：价格线与价格图例为主题中性主文字色（浅色近黑、暗色近白）；分钟浮层主价格与涨跌幅按相对昨收使用金融涨跌色，平盘或缺少有效昨收时为中性色；均价复用 MA5 身份色，昨收为中性虚线并只标 `0%`，量柱使用金融涨跌 token。价格纵轴以昨收为正中心按当日最大偏离上下对称展开，保证基准线始终可见；达到常见涨跌停边界时不再添加额外纵向留白。上下绘图区统一预留 64px 左右轴边界，保证价格和量能时间轴垂直对齐；日 K 工作区和分时共同消费 `app-stock-chart-frame` 外框、`StockChartPanelHeader` 标题栏、`StockChartLegend` 图例项，日线与分钟量柱共同消费 `buildStockVolumeBarSeries()`。上图显示“分时”及价格/均价图例，下图显示“量能”并使用共享双边分隔形态，禁止在 ECharts 画布或消费页另画标题、图例标识、边框或分隔线。两图按实际画布高度计算紧凑布局，底部时间轴固定展示 `09:30`、`11:30`、`15:00`，不把午休结束时间并入中间标签。弹窗顶部行情摘要消费 `StockQuoteSummary`：最新价作为无标签、适度强调的独立列，其余字段按每列两项紧凑排列，并与 K 线浮层共享 `StockQuoteSummaryModel`；旧 `.app-metric-*` 等宽指标网格已废弃。分钟明细复用 `stockQuoteSummaryHtml()` 和日 K 的缩放浮层外壳，按分钟窗口的字符容量保持列宽稳定；价格光标标签显示两位价格，右侧光标显示相对昨收的两位涨跌幅，量能光标以手格式化。底部可见缩放条和画布内缩放同步价格/量能两图，尺寸或主题重绘时保留当前缩放范围。`partial` 在图表上方复用 `AppStatusNotice` 显示横向警告；范围、空数据和错误复用 `AppStateBlock`。关闭弹窗、切股、换日或重复点击都会取消/隔离旧请求，旧响应不得覆盖当前状态。

价格和量能绘图区均隐藏左右数值轴边框，水平网格线与日 K 统一为实线，只有昨收基准线保留虚线。

## 验证与运维

后端定向测试覆盖源字段归一、不复权参数、查询不取源/不写库、累计均价、数据库缓存命中与修订、无视旧源窗口缓存、失败后立即重试与旧失败缓存兼容、跨股票有界并发与来源共享限流、Redis 故障下查询降级/采集关闭失败和 API 权限/503 映射。前端定向测试覆盖蜡烛事件、双绘图区/三序列、左右坐标映射、涨跌停边界、主题色、弹窗状态、取消与迟到响应，以及共享分析面板接入。

`backend/tests/test_intraday_parallel.py` 通过96股、两交易日的真实任务处理器执行日常采集与批量质检恢复，保留共享限流和候选选择，只替换外部传输；覆盖4路并发、主线程写库、备用源、取消、冻结问题范围及失败续跑，逐股校验价格不串股。该文件还提供显式5000股/10000问题的恢复入口回归（`INTRADAY_SCALE_STOCKS=5000 python -m pytest backend/tests/test_intraday_parallel.py -q`），验证批量范围规划、首股落库后立即关闭问题并更新外层进度，以及旧检查点先本地复检再提交后续请求；仅替换外部传输，隔离库与任务入口保持真实。

真实源冒烟选择本地监控日期，分别验证近期缺分钟、响应首日截断及显式重新核验，并确认持久归档后不依赖在线窗口，清除缓存或 Redis 故障仍能读取。代表性规模验证通过真实服务入口、隔离库及合成源窗口执行，使用 INTRADAY_SCALE_STOCKS=5000 python -m pytest backend/tests/test_intraday_scale.py -q -s；不会联网采集全市场或写入开发库。公开免费接口可能临时限流或调整返回结构；采集失败时通过数据管理任务日志检查源端和 Redis 保护状态，不通过提高并发或绕开保护重试解决。
