# 技术指标规范化与自定义指标闭环

## 1. 初步需求理解

当前技术指标目录同时承载行情基础字段、数值指标、布尔信号、固定参数变体和暂不可用占位项，现有分类仅是多标签，不能表达父子层级。部分名称把周期或方向写死，自定义指标创建又直接暴露 DSL、占位符和不完整的参数表单，导致用户难以判断指标应复用、派生还是新增。

本次目标是先建立稳定的指标治理规范，再据此改造指标目录与自定义指标创建链路；不继续以增加具体指标的方式累积重复定义。

## 2. 业务目标

- 让使用者能判断一个条目是基础字段、数值指标、布尔信号还是参数预设。
- 让同一计算能力只保留一个通用定义，具体周期和阈值通过参数、预设或下游条件表达。
- 让管理员无需理解占位符细节也能安全创建常用指标，同时保留“公式创建”（内部使用安全 DSL）能力。
- 保持历史方案兼容，现有 key 不因规范化直接删除或改写。
- 让创建、验证、保存、启停、编辑、引用检查和失败反馈形成完整闭环。

## 3. 用户角色、权限与使用场景

- 已登录用户：查看启用的指标目录，在筛选、评分和买卖方案中选择指标并配置使用参数。
- system 管理员且具备 `indicator:def-manage`：创建和修改自定义指标，维护分类、启停指标，并在无有效引用时删除自定义指标。
- 系统内置指标不可删除；兼容预设继续保留稳定 key，但在目录中明确显示其所属通用指标与预设参数。

典型场景包括：查找已有能力避免重复创建、从模板创建数值指标、用安全公式创建特殊指标、在方案中调整周期、查看指标被哪些方案引用，以及在定义异常时停用或修正。

## 4. 完整业务闭环

### 主链路

1. 用户进入“配置管理 → 技术指标”，按层级、分类、来源、输出类型或关键字查找指标。
2. 目录明确展示指标层级、来源、计算方式、输出类型、参数、所属通用指标和预设参数。
3. 管理员新建自定义指标时，先选择“模板创建”或“公式创建”；DSL 只作为公式引擎的内部技术名称。
4. 模板模式自动生成表达式与参数；高级模式允许编辑白名单表达式，但必须同步展示参数占位关系。
5. 管理员为每个计算参数填写名称、中文标签、类型、默认值、上下限、单位和说明。
6. 保存前执行参数结构校验、表达式渲染校验和代表性股票/日期试算，展示实际参数、渲染结果、计算值或明确缺数原因。
7. 验证通过后保存并启用，指标进入筛选、评分和买卖方案的可选目录。
8. 下游方案只保存稳定指标 key 与使用参数；阈值、比较符和评分区间仍由各自方案维护。
9. 自定义定义发生变化后，依赖该定义的评分快照按现有指纹机制失效；后续读取按新定义重算。

### 关键支链路

- 编辑：未被引用的自定义指标可修改显示信息、表达式和参数定义；被引用后只允许修改显示信息，计算语义需另存新 key。修改前展示引用影响，语义修改后重新验证。
- 启停：停用后不再允许新方案选择；已有方案和历史回测继续按原定义运行。
- 删除：删除前检查筛选、评分、买卖和回测引用；存在有效引用时阻止删除并展示引用来源。
- 兼容治理：旧固定周期 key 不迁移、不删除，改为“参数预设”展示；新能力优先引用通用指标。
- 回退：未保存时取消不产生变化；保存后可通过修正定义或停用控制影响。指标定义版本历史与一键回滚作为后续能力，不在首期假定已经具备。

### 失败处理

- 表达式非法、使用未知变量或非白名单函数时拒绝保存，并定位错误。
- 占位符缺少参数、参数未被表达式使用、参数重名、类型错误或默认值越界时拒绝保存。
- 试算无数据时区分“历史不足”“字段缺失”“表达式错误”和“结果为空”，不能统一显示为不命中。
- 保存失败时保留表单内容，允许修正后重试。
- 无管理权限时目录保持只读，不展示可执行的管理操作。

## 5. 指标分层与命名规范

### 四层模型

1. **基础字段**：直接来自行情或参考数据，例如开高低收、成交量、成交额、换手率和流通市值。
2. **数值指标**：输出可比较、可评分的通用数值，例如移动平均线、N 日最高/最低价、N 日涨跌幅、区间振幅、均线乖离率、RS 和 MACD 数值。
3. **布尔信号**：由字段或数值指标形成的成立/不成立判断，例如站上均线、均线向上、创新高、放量突破、连续上涨和 MACD 金叉。
4. **参数预设**：通用指标的一组快捷参数，不视为新的原子定义，例如 MA20、240 日新高、20 日 2 倍放量突破。

筛选条件的比较符和阈值、评分映射和权重、买卖方案的 AND/OR 组合均属于下游方案，不属于指标层。

### 命名规则

- 数值指标使用中性名词，不预设结果方向；“N日涨幅”统一展示为“N日涨跌幅”。
- 布尔指标使用明确状态或事件名称；英文 key 推荐使用 `is_`、`has_` 或事件语义，但现有 key 保持兼容。
- 通用指标名称不写死周期和阈值；周期进入计算参数，阈值进入下游条件。
- 新 key 使用稳定、抽象的英文业务语义，不使用 `xxx3`、`xxx20` 等具体参数后缀。
- 来源、业务层级、计算方式和输出类型是四个独立维度，不再用“内置/表达式/布尔”等单一字段替代完整分类。

### 现有变体治理

- MA5、MA10、MA20、MA30、MA60：归属移动平均线预设。
- 半年、一年、两年新高：归属创 N 日新高预设。
- 固定 20 日 2 倍放量突破：归属参数化放量突破预设。
- 固定 60 日平台突破：归属参数化平台突破预设。
- 现有 key 和历史引用保留；目录层改变展示关系，新建方案逐步引导选择通用指标。

## 6. 自定义指标参数规范

参数只决定“指标如何计算”，不承载“结果如何筛选”。每个参数至少包含：

- 参数名：表达式中的英文占位符，例如 `window` 对应 `{window}`。
- 中文标签：页面展示名称，例如“统计周期”。
- 类型：整数或小数。
- 默认值：首次选择指标和保存试算时使用的值。
- 最小值、最大值：限制可输入范围。
- 单位：例如交易日、百分比、倍。
- 参数说明：解释参数改变后对计算口径的影响。

例如“N日区间振幅”定义为数值指标：

```text
表达式：(HHV(H, {window}) / LLV(L, {window}) - 1) * 100
参数：window / 统计周期 / int / 默认20 / 最小2 / 最大250 / 交易日
```

在筛选方案中使用时再配置：

```text
统计周期 = 60个交易日
比较符 = <=
阈值 = 10%
```

`window=60` 决定如何计算，`<=10%` 决定如何使用结果，两者不得混为一个指标定义。

## 7. 完整功能点清单

### 指标目录治理

- 目标：清楚表达四层关系和多个正交属性。
- 入口：配置管理的技术指标页。
- 操作：搜索、筛选、查看通用指标与预设关系、查看参数和说明。
- 反馈：明确显示基础字段、数值指标、布尔信号、参数预设和暂不可用状态。
- 异常：目录加载失败进入可重试错误态，不把失败显示为空目录。

### 引导式自定义指标创建

- 目标：普通管理员无需手写完整 DSL 即可创建常用指标。
- 操作：选择模板或高级模式，配置输出和参数，试算，保存。
- 反馈：实时展示表达式、占位符对应关系、渲染值和试算结果。
- 权限：只允许具备指标定义管理权限的 system 用户执行。
- 异常：校验失败保留输入并定位到具体字段。

### 定义维护与依赖保护

- 目标：避免停用、删除或修改后留下静默断链。
- 操作：编辑、启停、删除前查看影响。
- 反馈：展示引用方案类型、名称和版本；存在引用时阻止删除。
- 回退：首期允许修正或停用；版本历史与一键回滚后续建设。

### 下游统一消费

- 目标：筛选、评分和买卖方案使用同一指标目录和参数说明。
- 操作：选择通用指标或兼容预设，填写计算参数，再配置比较、评分或买卖条件。
- 反馈：参数显示中文标签、单位、默认值和合法范围。
- 异常：历史 key 仍可解析；未知或被删除 key 明确报错，不静默忽略。

## 8. 页面闭环草案

不新增独立页面，更新“配置管理 → 技术指标”及其自定义指标弹窗。

- 指标目录负责查看层级、来源、计算方式、输出类型、参数和父子关系。
- 新建/编辑弹窗负责模板选择、高级表达式、参数定义和试算。
- 筛选、评分、买卖页面继续消费同一目录，并统一展示参数中文名、单位和范围。
- 保存成功后关闭弹窗并刷新目录；保存失败保留当前编辑状态。
- 空状态区分“没有匹配结果”和“目录加载失败”。
- 只读用户可以查看规范与说明，但不能触发创建、编辑、启停或删除。

## 9. 阻塞确认项

已确认：指标体系采用“基础字段 → 数值指标 → 布尔信号 → 参数预设”四层模型；旧 key 保持兼容；MA5、一年新高和固定放量突破等按参数预设治理；新建自定义指标优先沉淀数值原子指标，比较阈值留在下游方案；创建入口采用模板创建与公式创建双模式。

当前没有阻塞闭环保存的确认项。

## 10. 非阻塞确认项

- 首批创建模板固定为区间位置、距 N 日高点和快慢均线差。
- 兼容预设在目录默认折叠，在方案选择器中归入“快捷预设”分组。
- 已被方案引用的自定义指标锁定计算语义，修改口径必须另存为新 key。

## 11. 范围划分

### 必须实现

- 四层指标模型、命名规则和现有指标关系梳理。
- 保持历史 key 与已有方案兼容。
- 区分指标计算参数和下游使用阈值。
- 完整展示参数类型、默认值、上下限、单位与说明，并校验占位符关系。
- 模板创建与公式创建双模式，页面不直接使用 DSL 术语。
- 保存前表达式渲染和代表性数据试算。
- 自定义指标编辑、启停及删除前的引用保护。

### 建议实现

- 常用指标模板：`本次纳入`。
- 参数单位和参数说明：`本次纳入`。
- 通用指标与预设参数关系展示：`本次纳入`。
- 指标定义版本历史和一键回滚：`后续建议`。
- 指标引用次数及引用方案查看：引用保护所需的最小查看能力 `本次纳入`，完整统计 `后续建议`。
- 指标结果分布、缺失率和性能统计：`后续建议`。

### 暂不实现

- 可视化拖拽公式编辑器。
- 用户个人私有指标；指标继续作为平台级定义。
- 任意 Python、SQL 或脚本执行能力。
- 自动迁移或删除历史固定参数 key。

## 12. 推断依据与推断决策

- 当前注册表同时存在 `ma` 与 MA5/MA10/MA20 等条目、`new_high` 与多个固定周期新高条目，证明通用定义与变体尚未显式分层。
- 当前 `category/categories` 是可编辑标签，不能表达父子关系；`kind` 表达计算方式，`dtype` 表达输出类型，均不能替代业务层级。
- 当前参数模型已经包含名称、标签、类型、默认值、上下限，但新建弹窗只展示名称、标签和默认值，因此需要补全而不是另建一套参数机制。
- 当前 DSL 已支持后向的 MA、HHV、LLV、REF、COUNT、SUM 和 ABS，可支撑首批模板；任意脚本执行既无必要也不符合安全边界。
- 现有筛选、评分和买卖方案均以稳定 key 与参数引用指标，因此保留 key、调整目录关系是风险最低的渐进治理方式。

## 13. 后续建议

当前闭环已经具备进入正式需求文档生成的条件。下一步应基于本闭环调研现有页面设计规范、历史方案引用与启停语义，生成正式 `requirement.md`；随后再制定开发计划，不宜直接从闭环文档跳到代码改造。
