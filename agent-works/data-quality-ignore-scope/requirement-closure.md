# 数据质检通用忽略范围闭环

## 背景与目标

数据质量列表中的所有质检问题统一支持两种忽略范围，避免不同问题类型由后端写死不同口径：

- 仅忽略本次：当前异常持续存在时不重复报告；异常消失后，本次忽略自动失效，后续再次发生时重新报告。
- 整体忽略：持续忽略同一监控对象的同类质检问题，直到用户主动恢复监控。

本功能在现有数据质量页面完成，不新增页面。

## 角色与权限

- 沿用现有质检修复权限；有权执行“标记正常”的用户可选择忽略范围，也可恢复监控。
- 无该权限的用户只能查看，不展示或不可执行相关操作。

## 使用入口与主流程

1. 用户在未解决的质检问题行操作中选择“标记正常”。
2. 系统弹出忽略范围选择框，默认推荐“仅忽略本次”，并解释两种范围的影响。
3. 用户确认后，当前问题转为“已忽略”，保存对应忽略规则。
4. 后续质检产生候选问题时，系统先按问题类型和监控对象匹配有效规则：
   - 仅忽略本次只抑制当前这一轮持续存在的异常。
   - 整体忽略抑制同一对象、同一问题类型的后续异常。
5. 已忽略的问题行提供“恢复监控”：
   - 对整体忽略，立即停用长期规则；若异常仍存在，重新进入待处理状态或在下一次质检时重新报告。
   - 对仅忽略本次，提前结束本次忽略；若异常仍存在，重新进入待处理状态或在下一次质检时重新报告。

## 对象与事件边界

- 监控对象优先使用问题本身的稳定业务标识，例如股票代码、板块代码。
- 源级问题没有代码时，使用问题类型和稳定来源标识作为对象。
- 名称映射类问题没有代码时，使用来源类型与原始名称共同标识对象。
- “本次”以同一对象、同一问题类型、同一问题发生标识为边界；在系统确认该异常已消失后，本次规则自动失效。

## 状态与异常处理

- 忽略与恢复操作必须幂等，重复提交不会生成重复规则或破坏状态。
- 正在修复中的问题不可忽略或恢复，避免与异步任务状态冲突。
- 无效范围、问题不存在或状态不允许时返回明确错误，页面保留当前数据并提示失败。
- 历史已忽略数据保持兼容：没有范围信息的历史记录按升级前各类型的精确/整体口径补齐，避免升级后突然重新告警。

## 验收标准

- 所有质检类型都能在同一交互中选择“仅忽略本次”或“整体忽略”。
- 本次异常持续存在时，“仅忽略本次”不会被重复生成；异常消失再复发后会重新报告。
- “整体忽略”能跨日期、跨扫描持续抑制同一对象的同类问题，恢复监控后重新生效。
- 无代码的源级和名称映射类问题也能稳定匹配，不会误伤其他对象。
- 已忽略项可以恢复监控，权限、加载态、成功和失败反馈与现有质检操作一致。
- 既有质检扫描、逐日缺口、修复、重置和批量恢复流程不回归。

## 范围分级

- 必须：通用双范围、持久化、自动失效、恢复监控、权限复用、后端与前端测试。
- 建议：列表直接显示忽略范围，便于用户理解当前规则。
- 本期不做：新增规则管理页面、批量忽略、按租户或用户隔离规则、复杂条件组合。
