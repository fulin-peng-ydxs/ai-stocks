## 1. 背景

原可配置布局系统已经把页面外壳、布局 schema、组件目录、校验器和 `LayoutHost` 跑通，但 Web 产品化能力仍不足。用户实际使用时需要的不只是“页面能按布局系统渲染”，还包括：

- 在系统管理中管理布局配置，而不是散落在单页工具里。
- 管理预设、页面默认、系统组件和开放策略。
- 页面设置抽屉统一纳入模型，且业务选项与组件配置分层清楚。
- 配置来源可解释，能看到 default、preset、page、user 各层取值。
- 新页面交给 AI 开发时有脚手架、登记校验和计划模板，避免继续随机开发。

## 2. 与原模块的关系

- 不推翻已完成的四层合并、组件目录、原型、校验器、契约测试和自适应红线。
- 严守架构红线：不造第五层运行时优先级，不开放任意 CSS，不开放任意断点，不做自由拖拽画布。
- 本期把原先“只看 / 延后 / 避免假配置”的部分补齐为真实产品入口。
- 用户确认菜单归属改为“系统管理 → 布局配置”。

## 3. 已确认决策

| 编号 | 决策 |

| D2 | `usePageSettings` 统一归为“业务偏好”，与四层 `user` 层按所在分区区分。 |
| D3 | 系统组件页支持开放策略在线编辑，但只能在代码声明的最大开放集内收放。 |
| D4 | 组件 preset 默认值主入口是预设管理页；系统组件页负责能力、预览、消费关系和开放策略。 |
| D5 | 预设管理页补齐 token 全集、预设×组件默认和响应式默认策略。 |
| D6 | 页面布局工作区采用左预览右配置，点击 slot 定位配置，设备档位联动展示重排路径。 |
| D7 | 新页面闭环补强：脚手架、登记校验、7 原型模板和页面设计闭环。 |

## 4. 功能范围

### 4.1 必须实现

1. overlay 真正纳管：业务页设置抽屉成为 `settings-drawer` slot 的统一消费方。
2. 抽屉三段重构：布局 / 组件设置 / 业务选项，业务段声明式化。
3. 系统组件页开放策略在线编辑。
4. 预设管理页丰富化，支持 token 全集与预设×组件默认编辑。
5. 页面布局工作区一体化，支持结构预览、点击即配、档位联动。
6. 来源全链路可见。
7. 菜单三级归位，系统配置收进系统管理。
8. 新页面脚手架、登记校验和 7 原型模板。

### 4.2 不做

- 第五层运行时优先级。
- 任意 CSS。
- 任意断点编辑。
- 自由拖拽画布。
- 真实组件挂载式预览。
- 业务字段后端化与四层化。
- 布局模块自建平行的多租户权限产品；布局配置统一复用现有 RBAC 与请求上下文归属。

## 5. 层级与边界

- 运行时仍只有 `default < preset < page < user`。
- 页面层由页面布局工作区编辑，表示某个页面的默认布局与组件默认值。
- 组件 preset 默认值写入 preset 层，不新增运行时层。
- 开放策略是元配置，不参与值合并。
- 用户层由各业务页面设置抽屉编辑。
- 业务偏好不进配置链路，只通过“业务选项”分区表达。

## 6. 验收标准

1. 系统组件库能显示 registry 页面消费关系，并逐 slot 展示字段自动继承、策略关闭或实例不适用状态与原因。
2. 任一业务页设置抽屉呈现固定三段，组件设置段按组件 kind 与实例适用性自动生成；管理员策略收紧后字段和值在普通页面同时失效。
3. 系统组件页可在最大开放集内收紧/放开字段开放层级并持久化。
4. 预设管理页可编辑 token 全集、预设×组件默认和响应式默认枚举。
5. 页面布局工作区左预览右配置同屏，点击 slot 后右侧定位配置项。
6. 四层配置项可见生效来源与逐层取值，业务字段统一放入“业务选项”。
7. 菜单为系统管理 → 布局配置 → 三个孙菜单。
8. `npm run scaffold-page` 能产出合规新页面骨架并自动登记，同时接入 `componentAllowedLayers`，不绕过四层字段策略。
9. 前端 `npm test` 和 `npm run build` 通过。
