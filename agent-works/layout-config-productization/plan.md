## 3. 统一边界

1. 运行时永远只有 `default < preset < page < user`，禁止新增第五层。
2. 组件 preset 默认属于 preset 层。
3. 开放策略是元配置，不参与值合并，只能在代码最大开放集内收放。
4. 页面记忆不进配置链路，UI 标注区分。
5. 预览是结构示意，不挂载真实组件；不自由拖拽；不开放任意 CSS / 任意断点。

## 4. P9：菜单 IA 归位

### 目标

形成“系统管理 → 布局配置 → 预设管理 / 页面布局 / 系统组件”三级菜单；ConfigView 收进系统管理；旧路由直接换新。

### 任务

1. `App.vue` 新增系统管理父菜单，布局配置作为子菜单。
2. `router/index.ts` 路由迁移为 `/system/config`、`/system/layout/{presets,pages,components}`。
3. 全仓搜索旧路径引用并替换。
4. 更新设计文档和页面登记口径。

### 验收

- 菜单三级结构和高亮正确。
- 新路由可达，旧路由不再作为正式入口。
- 前端测试、类型检查和构建通过。

## 5. P10：配置数据底座

### 目标

为预设管理和系统组件开放策略提供数据模型：preset 层组件默认值、开放策略持久化和前后端校验。

### 任务

1. 扩展预设配置，支持组件默认字段。
2. 新增 `layout_field_policy` 保存字段开放策略覆盖。
3. 后端 `layout_config.py` 增加开放策略读取、保存、重置和越权拒绝。
4. 前端 API 增加开放策略列表和保存方法。
5. 后端测试覆盖默认、收紧、越权、重置和 API 往返。

### DDL / 存储变更说明

- 新增表 `layout_field_policy(component_kind, field, allowed_layers_json, updated_at)`。
- 主键 `(component_kind, field)`。
- 缺行时回落代码 `COMPONENT_FIELD_DEFS` 最大开放集。
- 回滚方式：删除该表后代码回落默认策略。
- SQL 归档：`layout-field-policy.sql`。

### 验收

- 开放策略可持久化。
- 越出最大开放集被拒绝。
- 收紧后，被禁层保存被后端拒绝。

## 6. P11：预设管理页丰富化

### 目标

预设管理页从基础预设编辑升级为完整 token、预设×组件默认和响应式默认的运行时入口。

### 任务

1. 打通后端预设配置到前端运行时。
2. 支持 light/dark token 与 shared token。
3. 支持预设×组件默认字段，例如表格分页、抽屉尺寸、筛选默认展开。
4. 响应式默认只允许枚举档位。
5. 更新 `useLayoutPreset`、`useLayoutConfig` 和相关测试。

### 验收

- token 编辑后即时影响运行时外观。
- 预设×组件默认经四层合并生效。
- 非法 token、字段和值域被校验拦截。

## 7. P12：系统组件页开放策略在线编辑

### 目标

系统组件页从只读能力展示升级为可编辑开放策略，同时不与预设管理页职责重叠。

### 任务

1. 组件详情展示字段最大开放集和当前开放集。
2. 支持在最大开放集内勾选 `preset/page/user`。
3. 保存写入 P10 的策略表。
4. 恢复默认时删除覆盖，回落代码最大集。
5. 明确组件默认编辑入口在预设管理页。

### 验收

- 可收紧/放开开放层级并持久化。
- 超出最大集的层级无法选择且后端拒绝。
- 收紧后越权保存失败。

## 8. P13：overlay 纳管 + 抽屉三段重构

### 目标

业务页设置抽屉统一成为 `settings-drawer` slot；抽屉固定三段，并由 registry 自动渲染组件设置。

### 任务

1. `pageRegistry` 为业务页面补 `settings` overlay slot。
2. `PageSettingsDrawer` 固定布局 / 组件设置 / 业务选项三段。
3. `ComponentAutoSettings` 根据 slot kind 自动继承字段，再结合 slot `config` 和 `componentMeta` 渲染适用的组件配置。
4. `SettingsGroup` 支持多级折叠标题。
5. 页面只保留业务选项声明，组件设置不再手写。

### 验收

- 系统组件页能看到 `settings-drawer` 消费关系。
- 抽屉三段结构一致。
- 组件设置段自动生成列显隐、排序、分页、tabs 等控件。
- 业务选项标注页面记忆。

## 9. P14：来源全链路可见

### 目标

四层配置项统一展示生效来源与逐层取值；业务字段仅标注页面记忆。

### 任务

1. 新增 `SourceTag`。
2. `merge.ts` / `componentConfig.ts` 输出逐层值。
3. `LayoutSettingsSection`、组件设置和页面布局工作区接入来源展示。
4. 业务字段不接四层来源。

### 验收

- 布局项和组件项能看到默认/预设/页面/个人来源。
- hover 可查看逐层取值。
- 页面记忆不参与来源追踪。

## 10. P15：页面布局工作台一体化

### 目标

页面布局工作区形成左预览右配置，支持 slot 定位和设备档位联动。

### 任务

1. 左侧结构预览展示页面 slot、组件和响应式摘要。
2. 右侧按 layout、组件字段和来源分组展示可配置项。
3. 点击预览中的 slot 自动定位右侧配置。
4. 设备档位切换时展示重排/兜底路径。
5. 页面层只写 page 配置，不写 user 层。

### 验收

- 页面来自 registry。
- 预览和配置同屏联动。
- 可编辑字段来自元数据，不手写临时字段。

## 11. P16：新页面闭环

### 目标

将新页面开发流程固定为脚手架、registry、LayoutHost、设置抽屉、DESIGN 登记和测试校验。

### 任务

1. 新增 `frontend/scripts/scaffold-page.mjs`。
2. 脚手架生成页面骨架、路由、registry 条目和登记提示。
3. `pageRegistry.spec.ts` 校验页面登记完整性。
4. `page-template.md` 补齐页面设计闭环和 7 原型模板。
5. `layout-contract.spec.ts` 拦截视口硬编码高度和绕过 `LayoutHost` 的手写布局类。

### 验收

- `npm run scaffold-page` 能生成合规页面骨架。
- 漏登记、字段不一致和布局红线能被测试拦截。
- `npm test` 和 `npm run build` 通过。
