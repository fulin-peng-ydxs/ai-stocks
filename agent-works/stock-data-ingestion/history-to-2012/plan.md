# 历史股市数据扩展至 2012 年开发计划

归档状态：已归档

来源与模式：2026-11-01 会话需求“额外拉取到 2012 年，先弄计划”，用户随后批准执行，并追加批准历史更码股票池修正；普通模式。本轮按用户要求核查并重构计划，保留原 L/T/V 编号。

目标与范围：补齐完整 2012 年及之后可获取的沪深 A 股 EOD 数据，包括期间存续而后来退市的证券、真实交易日历、市场基准指数、准确逐日 ST、复权、股本和市值。

用途与归属：本文承载需求映射、任务实施结果和验收；长期契约以[采集架构](../../architecture/stock-collection.md)、[ST 架构](../../architecture/st-status.md)、[回测架构](../../architecture/backtest.md)为准。复核 SQL 归档在同目录 [verify.sql](verify.sql)，不再另建平行总结或阶段流水。

**当前结论（2026-11-01）：数据补采已执行，2012 年数据可供研究；质量与性能验收尚未全部通过。** 全库 13,331,471 条日线，净增 2,861,214 条；2012 年 566,389 条、覆盖 243 个开市日。T1/T2/T5 及追加的价格消费一致性 T6 已完成，T3/T4 因必要性能验证及复权精度决策缺口保持进行中。R1 价量异常、R2 转股重复响应已按用户追加要求修复，个股未处理台账为 0；台账为 0 不代表追加抽查的复权问题 R7 已解决。基础实现提交为 `fa58e0b9`、文档重构为 `3c37aa4f`、定向修复为 `74908b2d`。因子精度离线验证见 [V3-07 对照结果](#factor-validation)，T6 只治理消费入口和展示精度，未改变库内因子或采集算法。

## 2. 实施方案与任务

共用链路：`POST /api/data/tasks` → `async_task/stock_ingest` 参数白名单 → `IngestionService` → 来源适配器/清洗/仓储 → 统一质量复检。正式写库沿用 system-only `data-task:manage`、DuckDB 单写互斥、共享请求治理与协作取消；不在后端持锁时启动另一个 CLI 写库。

执行依赖为 T1 → T2 → T3 → T4；T5 是 T1/T3 真实更码核验中追加获批的关联修复，完成后由 T4 验证研究消费。下面各任务就地维护实际产出，不再在末尾追加实施流水。

### T1：确认 2012 年来源与历史证券范围

对应 L1/L2；输入：现有来源、基础资料和历史质量规则；依赖：无。状态：**已完成**；验收：V1-01、V2-01。

**目标与现状依据**

原日线从 2016-10-17 开始，基础资料 5,564 股，原起点前已退市的 18 股需重点补采。已有 `history_backfill/delisted_history/share_capital_history` 等入口和 `HistoryQualityService`；旧十年成果只能作实现参考，不能证明本次来源覆盖。

**实施方案**

通过现有来源适配器核对上市/退市、主板/创业板、ST、停牌及更码样本；后上市证券不得在上市前造数。原始价格、后复权和准确交易状态分别核验，空响应不能当作停牌。特殊日只接受官方事实，身份关系交 T5 单一入口维护。

**开发步骤与产出**

1. 真实取源核验：2012 年日历与中证 500 均 243 个开市日；平安银行/茅台/东方财富分别 233/240/242 条日线，与 BaoStock 正常交易日期集合一致，源因子完整；年初/年中/年末股本有返回。
2. 退市样本：000522.SZ（2013-04-26 摘牌）、600656.SH（2016-05-13 摘牌）的历史日线/ST 可取；后者 2012 年 243 个 ST 日。目标按存续期并集构造，最终退市全量目标 269 股，上市/摘牌边界由 T3/T4 对账。
3. 首个名册请求暴露 SDK 无条件请求北交所耗尽预算；修改 `backend/datasource/akshare_source.py`，分别取得沪主板/科创板/深市，仅配置包含北交所时请求北交所。未放宽尝试预算；沪深覆盖和北交所开关正反用例均通过。

**完成条件与当前结果**

关键来源具备真实试跑条件，样本覆盖和失败分类明确；本任务已满足。来源原文/响应保存在本次临时证据目录，正式全量结果在 T3，不把样本通过等同于全历史准确。
