# 个股走势关联板块性能记录

## 1. 验证范围

- 本记录覆盖纯算法全量计算路径，以及 T10 的当前冠军批量读取路径；不把两者混为同一计时口径。
- 输入规模为 5000 只股票，每股 10 个累计候选，共 50000 组候选关系；10 个板块和 1 个上证基准各自只有一份 61 点收盘序列。
- 板块与基准收益在批量编排层按唯一代码预计算，逐股计算复用同一收益映射；测试断言整次编排只调用两次批量预计算，且输入代码集合分别等于唯一板块集合和四基准集合。
- 读取基准固定准备 5000 个状态和 10000 条冠军，在同一内存 DuckDB 上分别读取 1/50/200 个代码。

## 2. 环境与方法

- 日期：2026-08-29
- 硬件：Apple M1 Pro，16 GiB 内存
- 运行时：Python 3.12.7，NumPy 1.26.4
- 算法：`stock-board-correlation-v2`，61 个收盘点、20/60 日双窗口、5%/95% 缩尾和 Pearson。
- 计时范围：5000 次单股计算，包含 50000 次候选双窗口计算；不包含夹具和预计算映射的构造。
- 内存范围：在输入夹具和共享收益映射构造后启动 `tracemalloc`，记录纯计算阶段新增 Python 分配峰值；不代表进程 RSS 或输入总占用。
- 固定种子：`20260829`。
- 可执行入口：`backend/devtools/benchmark_stock_board_correlation.py`。
- 读取入口：`backend/devtools/benchmark_stock_board_correlation_read.py`；每个规模预热 5 轮、正式 50 轮，固定断言每轮 1 条 SQL。

复现默认规模：

```bash
python -m backend.devtools.benchmark_stock_board_correlation \
  --stocks 5000 --candidates 10 --seed 20260829

python -m backend.devtools.benchmark_stock_board_correlation_read \
  --stocks 5000 --warmups 5 --rounds 50 --enforce
```

命令向标准输出写一行 JSON，包含算法版本、种子、股票数、每股候选数、候选关系总数、耗时、吞吐和纯计算新增 Python 分配峰值。固定种子保证夹具一致；耗时和内存仍会随硬件、Python/NumPy 版本及系统负载变化。

## 3. 纯算法结果

| 股票数 | 候选关系数 | 单轮耗时 | 吞吐 | 纯计算新增分配峰值 |
| ---: | ---: | ---: | ---: | ---: |
| 5000 | 50000 | 61.646693s | 811.074 candidate/s | 2.66 MiB |

结论：相同板块和基准收益不再按候选关系重复构造，新增工作内存受控；双窗口缩尾与 Pearson 仍是主要 CPU 成本。当前任务是后台可取消写任务，未设置全量计算时延验收门槛。若需进一步提速，优先评估批量向量化相关计算，同时保持共同日期、逐窗口缩尾和稳定决胜口径不变。

## 4. 当前冠军读取结果

执行日期为 2026-08-29，环境同上。每个规模预热 5 轮并正式执行 50 轮；P95 使用最近秩口径，SQL 次数由基准客户端逐轮计数。

| 代码数 | P50 | P95 | 最小值 | 最大值 | 每轮 SQL | P95 门槛 | 结果 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 1.944 ms | 2.498 ms | 1.776 ms | 13.405 ms | 1 | 10 ms | 通过 |
| 50 | 3.182 ms | 3.761 ms | 2.913 ms | 4.925 ms | 1 | 20 ms | 通过 |
| 200 | 5.574 ms | 6.293 ms | 5.239 ms | 6.543 ms | 1 | 50 ms | 通过 |

结论：三个规模均显著低于门槛，且 SQL 次数不随代码数量增长；`--enforce` 已返回成功。该基准使用确定性内存 DuckDB 隔离读路径，避免开发库数据量与并发任务干扰，不代表网络传输或页面渲染耗时。
