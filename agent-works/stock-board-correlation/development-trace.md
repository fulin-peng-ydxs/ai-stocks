# 个股走势关联板块

## 功能的详细需求

本功能为股票累计行业、概念归属建立可复用的走势相关性能力。系统只在股票已累计收录的候选板块中比较，分别选出行业冠军和概念冠军，并通过后台任务预计算，使股票列表、分组列表、每日榜单和策略筛选能够一次批量读取结果。

核心业务契约如下：

- 使用统一交易日历、后复权个股收盘、原始板块/指数收盘和固定 20/60 日窗口，不跨停牌或行情缺口桥接收益。
- 按上市板映射上证、深证成指、创业板指或科创50；映射基准目标日或样本不满足时整股回退上证，上证仍不足则任务失败。
- 行业和概念分开评选，保存综合分、双窗口相关度与样本、可信度、实际基准、回退标记、目标日、计算时间和算法版本。
- 只保存每股每类型当前冠军及每股当前状态，不保存每日快照和全部候选明细；全量或指定范围成功后原子替换，失败保留旧结果。
- 页面只有在业务日期等于结果日期时展示冠军；历史榜单、历史筛选和历史分组行不得借用最新结果。
- 普通用户沿用原页面权限；`sectors:view` 仅决定板块名称是否可跳转。任务和调度继续使用 system-only 数据管理权限。
- R11-R20 保持后续建议或暂不实现，其中包括当前有效成员时间线、历史冠军、个股详情、领先滞后、盘中计算、候选明细和人工冠军。

## 功能开发的实际结果

R1-R10 已完成，最终算法版本为 `stock-board-correlation-v2`。

- 数据层新增 `stock_board_correlation` 冠军表和 `stock_board_correlation_state` 每股状态表，均为稳定规模的 DuckDB 当前态关系；提供幂等正向 SQL、回滚 SQL 和数据目录登记。
- 后端新增累计归属、目标日期与股票池解析、固定窗口输入批量加载、纯算法计算、完整性校验、原子替换、单股/批量摘要和日期保护。
- 板块及基准收益按唯一代码预计算，避免按约五万候选关系重复构造相同收益序列。
- `stock_board_correlation` 已注册为 DuckDB 写互斥异步任务和可调度类型，支持全市场/指定股票、`force`、阶段取消、失败重试和五阶段可观测日志，不支持不完整结果续跑。
- `/api/stocks`、分组明细、`/api/board/run` 和筛选结果各在最终代码集合形成后执行一次批量摘要读取；`/api/board/compute` 和回测历史决策链路未接入。
- `RelatedBoardCell` 被股票普通表、分组表、榜单表和筛选表共同消费，统一空值、历史不匹配、悬浮指标、低可信提示和权限感知跳转。
- `StockCodeMultiSelect` 被个股采集、数据概览和相关性调度共同消费，统一远程搜索、批量粘贴、大小写规范化、去重、候选错误和竞态处理。
- 结构体检、纯算法基准、1/50/200 只读取基准、安全 E2E 夹具、三视口页面回归和完整设计门禁已落地。
- T11 第三方复审修复了两处旧 `v1` 注释和一处股票多选占位 DESIGN 偏差；未发现剩余确定性业务缺陷。

关键文件职责：

- `backend/indicators/stock_board_correlation.py`：版本化纯算法。
- `backend/services/stock_board_correlation.py`：领域编排、当前态切换和读取契约。
- `backend/services/async_task.py`、`backend/scheduler/scheduler.py`：任务、互斥、调度和日志。

- `frontend/src/views/StocksView.vue`、`BoardView.vue`、`ScreenView.vue`、`data/ScheduleView.vue`：用户读取入口和管理员配置入口。
- `backend/devtools/benchmark_stock_board_correlation*.py`、`backend/devtools/e2e_stock_board_correlation.py`：可复现性能与端到端夹具。

## 功能开发的具体实施方案

1. 数据结构先行：以 `(code, board_type)` 保存冠军，以 `code` 保存本轮处理状态；状态表能表达行业和概念都没有冠军的合法空结果，也为逐股日期保护和算法版本判断提供事实源。
2. 算法独立：纯算法模块只接收日历、价格、候选和预计算收益映射，不访问数据库。市场收益只在相邻开市日均有有效收盘时产生；股票、板块、基准三方共同日期达到 15/40 样本后才计算缩尾 Pearson。
3. 批量编排：服务一次加载目标股票、累计候选、61 日个股/板块行情和四个基准，按唯一板块和基准预计算收益；逐股计算只复用映射。结果覆盖、类型、数值、样本、日期、版本、基准和字典引用全部通过后才进入短事务。
4. 原子当前态：全量任务删除并替换两张正式表；指定范围只替换目标代码。所有删除与插入在同一事务内，异常回滚；合法空仍写状态并清理旧冠军。
5. 任务与调度：手工任务和调度保存共同使用参数规范化函数。创建时纳入全局 DuckDB 写任务互斥；阶段回调统一呈现读取候选、加载行情、批量计算、结果校验和原子切换。
6. 读取和历史隔离：摘要查询通过状态表关联冠军和板块字典，一次返回代码映射。调用方必须传实际业务日期；不匹配时不返回冠军。分组资产继续从 PG 读取，行情和摘要从 DuckDB 读取并在服务层合并。
7. 页面与复用：四个表格 slot 在 `pageRegistry` 登记两列，三个页面真实消费共享单元格。调度表单复用既有 dialog、分段控件和共享股票多选，不开放算法窗口、权重或基准参数。
8. 验证与运维：结构体检扫描当前态跨表一致性和行情支撑；性能脚本固定随机种子和数据规模；E2E 夹具使用专属代码、板块、任务前缀和 2097 年日期，并受本地环境和写开关门控。

最终实现与 `plan.md` 的 T1-T11 顺序一致。算法因基准目标日缺失问题从早期 v1 修订为 v2；性能实现补充了唯一代码收益预计算；T10 增加了分组执行的完整设计门禁。这些修订均保持 R1-R20 的业务边界不变。

## 上线部署操作

1. 发布后端代码并启动应用，让 `backend/storage/ddl.py` 的 `init_db` 幂等创建两张当前态表。若自动初始化不可用，在停止 DuckDB 写任务并确认目标数据库后执行 `agent-works/stock-board-correlation/create-stock-board-correlation.sql`。
2. DDL 生效后、前端依赖数据前，系统管理员手工执行一次全市场相关性任务；核对 `as_of_date`、目标股票数、候选数、行业/概念冠军数、空结果数、基准分布、回退数、耗时和切换状态，并运行结构体检。
3. 发布前端源码及同步构建产物，使三个业务页面、列配置和调度表单生效。旧用户列配置缺少新 key 时按现有默认机制显示，回滚前端后未知 key 会被忽略。
4. 管理员根据真实上游完成时点创建依赖调度；代码不创建默认调度，不修改已有管理员配置。
5. 本功能不新增环境变量、PostgreSQL 表、菜单、资源码、角色授权、租户数据、字典初始化或第三方平台配置。继续复用 `stocks:view`、`board:view`、`screen:run`、`sectors:view`、`data-task:manage` 和 `data-schedule:manage`。
6. 计算异常时先停用调度，保留最后成功结果；修复后使用 `force=true` 全量重算。彻底撤回时停用调度、回滚代码并执行 `rollback-stock-board-correlation.sql`；两张表是可重算派生数据，删除后不承诺恢复旧冠军。

E2E 脚本和夹具只用于 `dev|test|local`，必须显式设置 `AI_STOCKS_E2E_WRITE=1`，不得作为生产初始化数据执行。
