## 1. 背景与目标

系统已经能够采集行业、概念板块字典、累计成分关系和板块指数，但股票列表、每日榜单、策略筛选目前不能快速回答“这只股票近期主要跟随哪个行业、哪个概念”。如果在页面请求期间逐股加载行情并计算，既会产生 N+1，也无法满足高频列表场景的毫秒级响应要求。

本需求建设“个股走势关联板块”公共能力：对每只股票截至目标交易日已经收录的行业、概念候选，使用确定性日收益相关算法分别选出最相关行业和最相关概念。计算通过独立任务预先完成，页面按业务日期批量读取每只股票对应交易日的冠军快照。

业务目标：

1. 个股查询、每日榜单和策略筛选统一展示“行业走势”“概念走势”。
2. 行业与概念分别评选，结果带相关度、样本量、可信度和数据截止日期。
3. 页面查询不实时计算、不逐股补查，服务端批量读取达到可验收的毫秒级性能。
4. 任务成功按目标交易日写入当日快照，失败保留该日上次成功结果；按日保留各交易日冠军，不保存全部候选相关性。
5. 严格保护历史日期：无历史快照时不得把最新结果展示到历史行情、历史榜单或回测链路。

### 2.4 已确认业务边界

- 按交易日保存冠军与状态快照，保留各交易日结果；不保存全部候选明细。
- 不保存约五万组候选板块相关性明细，只保存每只股票每种类型的冠军。
- 暂不在个股详情展示。
- 本次接受无法严格判断成员移出时间的限制；必须排除明确晚于目标日首次观察到的未来成员。
- 计算注册为独立调度任务，执行频率动态配置。

## 3. 用户角色与使用场景

| 角色 | 权限边界 | 使用场景 |
| --- | --- | --- |
| 普通业务用户 | 沿用当前页面的 `stocks:view`、`board:view`、`screen:run` | 在个股列表、榜单或筛选结果中查看行业走势与概念走势 |
| 可查看板块用户 | 额外具有 `sectors:view` | 点击走势板块进入现有板块详情 |
| 无板块查看权限用户 | 无 `sectors:view` | 可看到当前股票行附带的板块名称，但不可进入板块详情 |
| 系统管理员 | `data-schedule:manage`、`data-task:manage` | 配置计算频率、依赖和重试，立即执行并查看日志 |

典型场景：

- 用户查看最新股票行情，快速识别股票近期更跟随哪个行业和概念。
- 用户查看最新每日榜单，在评分结果之外判断股票是否共同聚集于相同题材。
- 用户运行最新交易日策略筛选，使用走势板块摘要辅助二次判断。
- 系统管理员将相关性任务依赖于行情或板块任务成功后执行，并在失败时保留线上旧结果。

## 5. 详细功能需求

### R1 累计行业、概念归属查询

- **功能描述**：按股票代码查询 `board_member` 并关联 `board_dict`，返回累计收录的全部行业和概念。
- **输入**：单个股票代码；内部服务同时支持股票代码集合批量查询。
- **输出**：`membership_scope=cumulative`、成分数据最近成功时间，以及 `industries[]`、`concepts[]`；元素至少包含 `board_code`、`name`、`board_type`。
- **校验规则**：只返回 `board_dict` 中存在且类型合法的关系；结果按类型、名称、代码稳定排序并去重。
- **异常情况**：股票不存在或没有关系时返回空数组；不得回退 `stock_basic.industry` 冒充同花顺行业板块。
- **权限与数据范围**：复用 `stocks:view`；该关系是公共市场参考数据，不引入租户归属。
- **影响**：本次页面不展开全部归属，但接口契约为未来详情接入保留。

### R2 走势相关性计算与冠军评选

- **候选范围**：只计算 R1 累计归属中的板块；行业和概念分别评选。
- **行情截止日**：任务级目标日取不晚于 `trade_calendar` 开市日以及 `daily_bar`、`board_bar`、`index_bar` 三类数据族最新日期的共同日期；所有输入严格 `<= as_of_date`。单个股票、板块或指数的缺口按下述样本规则处理，不能把某个陈旧候选的最后日期冒充任务截止日。
- **统一窗口日历**：20/60 日都指截至 `as_of_date` 的最近 20/60 个市场开市收益区间，分别需要读取 21/61 个连续开市日收盘点。交易日序列以 `trade_calendar.is_open=true` 为事实源，不按单只股票或单个板块“最近若干条有效记录”各自取窗。
- **个股收益**：使用后复权收盘，复权因子统一 `COALESCE(adj_factor_clean, adj_factor)`；仅当相邻两个市场开市日都有有效收盘时计算该日收益。停牌、缺数或上市前空档形成缺失样本，不得跨多个开市日桥接成一条“单日收益”。
- **板块与指数收益**：使用 `board_bar`、`index_bar` 原始连续收盘，仍只计算统一市场日历上相邻两个开市日都存在时的单日收益；不得跨数据缺口桥接。
- **上市板基准映射**：市场中性基准按股票的上市板和交易所确定，不能对全市场统一使用一个基准：

  | 股票上市板识别 | 市场中性基准 | 指数代码 |
  | --- | --- | --- |
  | `stock_basic.board = 主板` 且代码后缀为 `.SH` | 上证指数 | `000001.SH` |
  | `stock_basic.board = 主板` 且代码后缀为 `.SZ` | 深证成指 | `399001.SZ` |
  | `stock_basic.board = 创业板` | 创业板指 | `399006.SZ` |
  | `stock_basic.board = 科创板` | 科创50 | `000688.SH` |
  | 上市板或交易所无法识别 | 上证指数（兜底） | `000001.SH` |

- **对应指数不可用的回退**：如果映射出的指数截至 `as_of_date` 不存在，或该指数自身在目标20日、60日窗口内的有效收益样本分别少于15、40，则该股票的行业、概念以及两个窗口全部统一改用上证指数 `000001.SH` 重新计算；不得按单个日期、单个候选或单个窗口混用两个基准。个股或某个候选行业/概念自身样本不足，只使对应股票或候选不合格，不能触发市场基准回退。若上证指数自身也不满足上述最低样本，任务完整性校验失败并保留旧结果。
- **市场中性化**：个股日收益和每个候选行业/概念板块日收益分别减去该股票最终选定基准的同日收益，再计算相关性。缺失基准日不进入共同样本。
- **窗口与样本**：短窗口为最近 20 个目标开市收益区间，至少 15 个股票、候选板块、最终基准三方同日有效样本；长窗口为最近 60 个目标开市收益区间，至少 40 个三方同日有效样本。两个窗口都达标才参与冠军评选；缺失样本只剔除对应日期，不扩大窗口向更早日期补足。
- **极值处理**：每个窗口内，个股和板块的市场中性收益序列分别按 5%/95% 分位缩尾，再计算 Pearson 相关系数。
- **综合分**：`score = 0.6 × corr_20 + 0.4 × corr_60`；保存时保持足够精度，接口展示最多四位小数。
- **稳定决胜**：综合分降序，其次 60 日相关度降序、60 日样本数降序、板块代码升序。
- **低相关处理**：只要样本达标，最高者就是该类型冠军；低相关或负相关允许成为冠军，但可信度为低，页面不得用“高度相关”等误导措辞。
- **可信度**：高＝60 日样本不少于 50、综合分不少于 0.70 且 20/60 日同号；中＝60 日样本不少于 40且综合分不少于 0.50；其他达标结果为低。
- **空结果**：没有候选、行情不足、基准不足或所有候选样本不达标时，该股票对应类型为空。
- **算法一致性**：算法版本、本次实际使用的基准代码和是否发生上证指数回退必须随结果保存，便于识别口径变化；上市板映射、窗口、权重、缩尾和样本下限是本需求固定的版本化业务契约，不允许不同调度任务各自修改后覆盖同一结果。

### R3 按交易日保存冠军与状态快照

- **保存规模**：每只股票每种类型每交易日最多一条；不保存非冠军候选结果。
- **核心字段契约**：股票代码、板块类型、冠军板块代码、综合分、20/60 日相关度、20/60 日有效样本数、可信度、实际基准代码、是否回退上证指数、行情截止日、计算时间、算法版本。
- **主键语义**：`股票代码 + 板块类型 + 行情截止日(as_of_date)` 唯一；板块名称从 `board_dict` 读取，不作为重复事实源。
- **按日快照写入**：先在非正式结果区完成计算和完整性检查，再在同一 DuckDB 事务内按目标交易日写入当日冠军与状态快照；先清除该日该批旧冠军、再按 `(code, board_type, as_of_date)` 幂等 upsert，使"该日无冠军的股票"旧冠军被移除。
- **指定范围覆盖**：传入股票代码集合时，只写该范围该交易日；其他股票和其它交易日快照保持不变。
- **失败处理**：计算、校验或事务失败均回滚；该交易日快照保持上次成功状态，不影响其它日期。
- **每日快照**：按交易日追加/更新当日快照，保留各交易日冠军；同日重跑幂等，不删除其它日期。仍不保存全部候选明细。

### R4 异步任务与动态调度

- **任务类型**：新增稳定任务类型 `stock_board_correlation`，注册到任务执行器、DuckDB 写任务互斥集合、可调度任务集合和前端中文标签。
- **参数**：`codes` 可选，空代表全市场；`force` 可选，默认无新共同交易日时跳过，`force=true` 允许同日重算。非法、重复代码规范化后拒绝未知股票或返回明确跳过统计。
- **全量股票池**：空 `codes` 只覆盖 `list_date <= as_of_date` 且 `delist_date` 为空或晚于目标日的主板、创业板、科创板 A 股，与项目“不含北交所”的范围一致；不为目标日前已退市股票制造冠军快照。显式代码若未知、尚未上市、已退市或超出板块范围，整次请求在写前拒绝并返回具体代码与原因，不静默缩小原子目标范围。
- **跳过判定**：`force=false` 只有在该目标交易日范围内每只股票都存在该日、当前算法版本一致的状态快照时才整次跳过；缺该日状态、日期未到或算法版本变化均必须计算。全量任务只要该交易日任一目标股票未就绪就执行该日全量写入，不能因部分股票已是最新而漏算其他股票。
- **调度能力**：复用现有 daily/weekly/monthly/cron、仅交易日、上游任务依赖、依赖条件、延迟、失败重试、启停和立即执行。
- **推荐默认链路**：个股行情或板块采集成功后，以依赖触发方式执行；具体频率由系统管理员配置，不在代码中创建强制覆盖用户配置的重复默认任务。
- **任务状态**：日志阶段至少包含读取候选、加载行情、批量计算、结果校验、原子切换。
- **取消与续跑**：该任务支持阶段检查点取消、切换事务开始后不再响应取消；不提供不完整结果续跑，失败、服务重启中断或人工重试都重新计算本次目标范围，前后端能力元数据必须一致。
- **任务结果**：返回目标日期、目标股票数、候选关系数、行业冠军数、概念冠军数、空结果数、跳过数、失败数、各基准使用股票数、回退上证指数股票数、计算耗时、写入耗时和是否切换成功。
- **跳过说明**：`force=false` 且该交易日快照已完整时跳过，结果 message 必须说明本次目标日、个股/板块指数/宽基指数三类数据族各自最新日期（解释"为何共同数据日期停在此日"）；若个股行情已领先于目标日，需提示"欲推进到更近日期请先补齐板块指数/指数日线"。不得只给出"已是最新"一类无日期、无原因的提示。
- **权限**：创建、调度、立即执行、启停沿用现有 system-only 数据任务和调度权限，不新增普通用户操作入口。
- **并发**：作为 DuckDB 写任务与其他写任务互斥；读页面在计算期间继续读取上次正式结果。

### R5 读取契约、日期保护与性能

- **单股摘要**：返回行业冠军、概念冠军及统一 `as_of_date`；可与 R1 全部归属组合，但页面默认只消费摘要。
- **批量摘要**：输入去重后的股票代码集合，一次返回 `code → related_boards` 映射；空集合不访问数据库。
- **列表合并**：股票、榜单、筛选服务取得页面行后，一次批量查询并按代码内存合并；禁止逐行调用接口或逐行 SQL。
- **响应结构**：

```json
{
  "related_boards": {
    "as_of_date": "2026-08-26",
    "benchmark": {
      "code": "399006.SZ",
      "name": "创业板指",
      "fallback": false
    },
    "industry": {
      "board_code": "881121",
      "name": "半导体",
      "score": 0.82,
      "corr_20": 0.86,
      "corr_60": 0.76,
      "sample_20": 20,
      "sample_60": 58,
      "confidence": "high"
    },
    "concept": null
  }
}
```

- **按业务日取快照**：调用方必须传其业务日期，只匹配该日、当前算法版本的冠军快照；缺档时由 GET 幂等登记 DuckDB 写互斥异步首次任务，但禁止同步计算或写正式结果；禁止借用其它日期或旧算法版本的结果装饰该日。
- **默认最新日**：页面未指定日期时，以其原接口实际返回的交易日作为业务日期，不以服务器自然日判断。
- **分组列表**：PG 读取用户分组资产、DuckDB 读取行情和冠军后在服务层合并，禁止跨库 JOIN；每行 `last_date` 该日无快照则该行为空。
- **性能目标**：本地预热数据库和不含公网传输条件下，单股摘要 P95 ≤10ms、50只批量 P95 ≤20ms、200只批量 P95 ≤50ms；列表增加冠军能力后不得出现随行数线性增加的数据库请求次数。
- **缓存**：DuckDB 当前结果为事实源；一期不强制引入 Redis。若实现进程内短缓存，键必须包含 `as_of_date/algorithm_version/benchmark_code/benchmark_fallback`，且结果切换后可失效。

### R6 共享展示与权限

- **复用要求**：个股查询、每日榜单、策略筛选共同使用一个走势板块展示单元，统一处理名称、可信度、空态、悬浮说明、权限和跳转。
- **展示名称**：列标题固定为“行业走势”“概念走势”，与现有 `stock_basic.industry` 的“行业”和上市市场“板块”区分。
- **单元格**：只展示一个冠军板块名称，并用小号朴素标签包裹；不得在表格中堆放全部概念。
- **说明**：悬浮内容包含综合相关度、20/60 日相关度、20/60 日样本和数据截止日；低可信度明确标注“相关性较弱”。
- **跳转**：具有 `sectors:view` 时跳转 `/sectors/:code`；否则使用不可点击文本，不弹出权限错误。
- **空态**：无冠军、该业务日期无快照、旧算法版本缺档均显示“—”；只有真实等待首次任务时显示“计算中”，不再为缺失原因增加单独标签或悬浮说明。
- **页面配置**：三个页面的 `pageRegistry.componentMeta` 必须登记新增列；列显隐使用现有组件配置和用户偏好回退机制。

### R7 个股查询接入

- **普通查询**：`/api/stocks` 返回当前分页股票的冠军摘要；`StocksView` 普通查询表新增两列。
- **分组视图**：分组明细服务在资产与行情合并后批量附加冠军；`groupTable` 同步新增两列，避免同一页面切换模式后字段消失。
- **日期**：普通查询使用响应 `trade_date`；分组行使用各自 `last_date`。不一致时不展示。
- **原有列**：现有“行业”继续表示 `stock_basic.industry`，“板块”继续表示主板/创业板/科创板；不得静默改变旧字段语义。
- **排序**：本次不增加按行业走势、概念走势或相关度服务端排序，避免扩大分页查询口径；只支持列显隐和点击。

### R8 每日榜单接入

- `/api/board/run` 在得到榜单代码后批量附加冠军摘要；前端榜单表新增两列。
- `run_date` 匹配对应交易日快照时展示；该日无快照则为空，由异步任务另行补算。
- `/api/board/compute`、回测“查看买入当日榜单”及其他历史决策链路本次不附加最新冠军，避免未来数据污染。
- 不改变评分快照、榜单排名、评分档和分项分口径；冠军摘要只作展示附加信息，不进入评分模型。

### R9 策略筛选接入

- 筛选服务在 `screen_scored` 结果形成后对命中股票批量附加冠军摘要。
- `run_date` 匹配对应交易日快照时展示；该日无快照则为空，由异步任务另行补算。
- 筛选结果表新增两列并登记到 `screen.result` 可配置列。
- CSV 导出沿用当前页面结果数据；列可见时导出“行业走势”“概念走势”，无冠军为空，不输出内部相关度字段。
- 冠军摘要不参与筛选表达式、评分和排序；需要作为筛选条件时另立需求。

### R10 可观测性、质量和测试

- 任务中心能够按中文任务名筛选并查看日志、状态、参数、重试来源和结果统计。
- 数据概览或任务结果至少有一个可见入口说明最近成功 `as_of_date`、计算时间、覆盖股票数、各基准使用数、上证指数回退数和空结果数；不要求新增独立页面。
- 结构体检覆盖结果表主键唯一、板块外键可解释、类型合法、分数有限和样本下限；个股或冠军板块未覆盖目标日但共同有效样本达标时只作提醒，基准指数目标日缺失仍判失败。
- 算法测试覆盖后复权、四类上市板基准映射、上证指数回退、市场中性化、共同日期对齐、样本不足、缩尾、稳定决胜、负相关冠军和行业/概念隔离。
- 接口测试覆盖批量合并、空集合、历史日期保护、权限和无 N+1。
- 前端测试覆盖三页面列显隐、空态、悬浮信息、权限感知跳转和历史日期退化。

## 6. 数据与接口需求

### 6.1 数据流

```text
board_member + board_dict       daily_bar + board_bar + index_bar
             \                           /
              \                         /
               stock_board_correlation 任务
                           ↓
             当前行业冠军 + 当前概念冠军
                           ↓
       股票列表 / 每日榜单 / 策略筛选批量合并
```

### 6.2 当前结果数据契约

建议以独立 DuckDB 关系承载当前结果，逻辑名称为 `stock_board_correlation`。开发计划可在不改变以下业务契约的前提下确定 DDL 细节：

| 字段语义 | 必须性 | 说明 |
| --- | --- | --- |
| 股票代码 | 必须 | 对齐 `stock_basic.code` |
| 板块类型 | 必须 | 仅 `industry | concept` |
| 冠军板块代码 | 必须 | 对齐 `board_dict.board_code` |
| 综合相关度 | 必须 | R2 固定算法 |
| 20/60 日相关度 | 必须 | 用于解释和复核 |
| 20/60 日样本数 | 必须 | 用于可信度和质量校验 |
| 可信度 | 必须 | `high | medium | low` |
| 实际基准代码 | 必须 | 记录按上市板选择或回退后实际使用的市场中性基准 |
| 基准回退标记 | 必须 | 标识是否因上市板无法识别或对应指数不可用而回退上证指数 |
| 行情截止日 | 必须 | 页面日期保护事实源 |
| 计算时间 | 必须 | 运维新鲜度 |
| 算法版本 | 必须 | 识别口径变化 |

冠军快照按交易日累积，主键语义为股票代码、板块类型与 `as_of_date`；状态快照主键为股票代码与 `as_of_date`。只保存每日冠军和状态，不保存全部候选明细。

### 6.3 接口兼容

- 现有股票、榜单、筛选响应只新增可选 `related_boards`，不得改变原字段名称、排序、分页或错误结构。
- 无结果时使用 `null`，不得用空对象、零分或虚构板块填充。
- 单股全部归属及摘要能力挂在 `stocks:view` 权限域；若新增独立路由，必须同步资源 seed、路由扫描测试和前端类型。
- 新增任务类型必须同步后端任务白名单、写任务互斥、调度白名单、前端 `TaskType`、中文标签、筛选和调度任务下拉。

### 6.4 配置闭环

- **调度配置定义者**：系统管理员。
- **保存位置**：沿用 DuckDB `scheduled_job.params`；本次不新增 PostgreSQL 表或字段。
- **读取与消费**：现有调度器加载后创建对应异步任务。
- **校验**：频率、依赖、延迟、重试和股票代码范围沿用服务端强校验；非法配置拒绝保存。
- **生效**：创建、编辑、启停后即时生效；停用取消等待事件的规则沿用现状。
- **回退**：删除或停用调度不删除冠军快照；页面继续按业务日期显示对应交易日快照及真实日期。
- **算法契约**：上市板基准映射、20/60 日窗口、0.6/0.4 权重、5%/95% 缩尾和样本下限按 R2 固定，不进入调度表单；算法调整必须更新算法版本并全量重算。映射出的指数不可用时按 R2 回退上证指数，不读取 `backtest.benchmark_main` 作为统一基准。

- **默认展示**：存在同日当前版本快照时显示；其余非等待状态统一显示“—”。
- **用户操作**：点击、列显隐、导出 CSV。
- **导出**：只导出板块名称，不导出内部代码、分数和算法字段。
- **状态变化**：重新运行筛选后整体替换结果。
- **加载状态**：沿用筛选运行 loading，不增加逐行 loading。
- **空状态**：无命中使用原结果区空态；历史日期或无冠军只让对应单元格为空。
- **错误状态**：筛选运行或导出前置数据失败保留现有可见错误和重试；相关摘要异常不允许被吞成合法空。
- **权限不足状态**：无 `screen:run` 使用现有权限态；无 `sectors:view` 只禁用跳转。
- **数据刷新**：每次成功运行整体替换结果及其相关性摘要，旧结果不与新日期混用。
- **验收标准**：见 R9 验收项。

### 7.4 页面 P4：任务调度

- **对应需求编号**：R4、R10。
- **页面类型**：更新页面。
- **页面入口**：`/data/schedule`。
- **原型文件**：不生成原型；复用既有任务类型、频率、依赖和重试表单，仅增加任务类型及其范围参数。
- **页面布局**：任务表、数据源健康区、触发记录抽屉和编辑对话框不变。
- **核心变更**：任务类型出现“个股走势关联板块”；选择后可填写可选股票代码范围和强制重算开关，不显示板块采集或个股采集专属字段。
- **数据来源**：现有 `/api/data/schedules*` 和 `/api/data/tasks*`。
- **权限与可见性**：system-only `data-schedule:manage`、`data-task:manage`。
- **配置化承载**：保存、读取、即时生效、停用、删除和重试沿用现有调度闭环。
- **关键状态**：非法代码范围阻止保存；立即执行后通过任务中心看阶段、结果和失败原因。
- **权限与异常状态**：无 system-only 权限时不展示可操作入口且后端返回 403；任务类型/参数加载失败、保存失败、执行失败分别保留可见错误和重试/纠正入口，不伪装为空配置。

#### 7.4.1 页面功能点：相关性任务配置

- **对应需求编号**：R4。
- **默认展示**：空股票范围代表全市场；仅交易日默认开启。
- **用户操作**：配置时间或依赖触发、重试、范围、启停和立即执行。
- **输入与校验**：代码去空、去重、格式校验；依赖任务不能自引用；沿用频率和延迟上限。
- **保存/取消**：沿用现有编辑对话框行为。
- **加载状态**：任务类型加载、保存和立即执行分别沿用现有 loading，避免重复提交。
- **空状态**：无调度定义使用现有任务表空态；空股票范围是“全市场”合法配置，不显示为缺失错误。
- **错误状态**：服务端校验错误不关闭对话框；执行失败不删除调度定义和旧冠军。
- **权限不足状态**：无 `data-schedule:manage` 或 `data-task:manage` 时不展示对应操作，后端仍以 system-only 守卫拒绝越权请求。
- **数据刷新**：保存、启停、删除或立即执行成功后刷新对应任务行、最近触发和结果入口。
- **验收标准**：见 R4 验收项。

### 7.5 明确不变页面：个股详情

- **对应需求编号**：R17。
- `/stocks/:code` 不新增走势板块区域、不请求全部归属、不修改 `stock-detail` 页面登记和设置。

## 8. 边界条件与异常场景

| 场景 | 处理 |
| --- | --- |
| 股票没有任何累计板块关系 | 行业、概念均为空，不算失败 |
| 全量股票在目标日尚未上市、已退市或属于北交所 | 不进入当前任务股票池；显式指定时在写前明确拒绝 |
| 只有行业或只有概念 | 有数据类型正常返回，另一类型为空 |
| 累计关系已经不是当前有效成员 | 仍参与候选；这是本次接受的已知限制，接口标记累计口径 |
| 板块字典存在但无板块指数 | 不参与冠军计算，全部归属仍可返回 |
| 个股停牌或交易日不完全一致 | 只取共同有效日；样本不达标则为空 |
| 股票对应上市板指数自身缺数据或样本不足 | 整只股票的行业、概念和20/60日窗口统一回退上证指数，禁止局部混用基准 |
| 个股或候选行业/概念自身样本不足 | 对应股票或候选不合格，不触发市场基准回退 |
| 上证指数兜底也缺数据或样本不足 | 任务完整性校验失败且不切换 |
| 相关系数为 NaN/无限值 | 该候选无效，不得写入正式结果 |
| 所有候选相关度很低或为负 | 仍选择最高且样本合格者，可信度为低 |
| 全量任务中部分股票合法空结果 | 成功覆盖，并清除这些股票旧冠军 |
| 任务执行异常或写事务失败 | 回滚并保留上次成功结果 |
| 页面业务日期晚于或早于结果日期 | 不展示冠军，不回算，不借用最新值 |
| 同日重复任务 | 成功后幂等覆盖；无 `force` 可跳过 |
| 两个调度任务同时触发 | 受 DuckDB 写任务互斥约束；按现有调度规则跳过或记录冲突，不并发写 |
| 用户无 `sectors:view` | 展示名称但不可点击 |
| 板块后续从字典消失 | 查询显示空或失效态；结构体检报告孤儿关系，任务不得返回伪造名称 |

## 9. 性能、安全与兼容性要求

### 性能

- 约5000只股票、平均10个累计板块形成约5万候选对；允许任务计算这些候选，但正式结果稳定在约1万行。
- 计算必须批量读取所需行情，避免为每个股票—板块对单独发 SQL。
- 计算只批量加载统一交易日窗口需要的 61 个收盘日及必要标识数据，不能读取五年全量行情后长期驻留；任务结束后释放 DataFrame、临时视图和索引。
- 列表接口按当前页代码一次批量读取，数据库查询次数不随股票行数线性增长。
- 达到 R5 的 P95 指标，并提供可重复的基准测试数据规模和报告。
- 临时数据和内存集合必须有明确生命周期，不保留无限增长缓存。

### 安全与权限

- 普通用户不能创建、修改或执行相关性任务。
- 股票列表、榜单和筛选继续 fail-closed；新增字段不得绕过原页面权限。
- 板块跳转按 `sectors:view` 权限感知，不以隐藏按钮代替后端保护。
- 新增独立读取路由时复用 `stocks:view` 精确守卫；由于不新增资源码、菜单或授权含义，不创建重复 `sys_resource` 行，但必须同步路由守卫扫描、401/403 和现有角色授权回归。若实施中新增新的权限语义或普通用户动作，必须另行补资源 seed、默认角色授权决策和 SQL 留痕，不能静默复用旧码。

### 兼容性

- 原接口调用方忽略新增可选字段时行为不变。
- 原列表排序、分页、评分、筛选和导出基础字段不变。
- 当前 `stock_basic.industry` 和 `stock_basic.board` 语义不变。
- 旧数据库初始化、升级和测试库都必须获得新增结果关系；升级只补缺失结构，不修改用户菜单、角色和页面配置。
- 算法版本变化后必须通过任务全量重算，不允许新旧算法结果混存但无法识别。

## 12. 建议开发顺序

### 阶段 1：算法与当前结果基础

- **覆盖需求**：R1、R2、R3。
- **目标**：先建立可重复验证的累计归属、相关算法和原子当前结果，避免页面先依赖未稳定口径。
- **前置**：板块字典、累计成分、板块指数、个股与基准行情可用。
- **里程碑**：固定夹具可计算约定冠军；连续日期覆盖不增长；失败可回滚。

### 阶段 2：任务与调度闭环

- **覆盖需求**：R4、R10 的任务部分。
- **目标**：把计算纳入现有写任务互斥、日志、动态调度、依赖和重试体系。
- **依赖**：阶段1已有可调用计算入口和明确事务边界。
- **里程碑**：系统管理员可配置并立即执行，全量及指定范围结果可观察。

### 阶段 3：通用读取与性能

- **覆盖需求**：R5、R10 的性能和接口部分。
- **目标**：形成单股/批量公共查询，完成日期保护和无 N+1 验证。
- **依赖**：阶段1正式结果稳定，阶段2可生产测试数据。
- **里程碑**：三档性能指标通过，历史日期保护测试通过。

### 阶段 4：渐进接入三个业务页面

- **覆盖需求**：R6、R7、R8、R9。
- **目标**：先落共享单元格和页面配置登记，再分别接入个股查询、每日榜单、策略筛选。
- **依赖**：阶段3提供统一响应契约。
- **页面关系**：三个页面共享展示组件，但保持各自权限和业务日期。
- **里程碑**：构建、Vitest、pageRegistry 契约和聚焦 E2E 通过；个股详情未发生改动。

### 阶段 5：第三方视角复审与事实文档同步

- **覆盖需求**：R1-R10。
- **目标**：按项目规则复查防未来函数、累计成员表述、双库边界、权限、页面复用、任务互斥、性能和异常回退。
- **里程碑**：无未修复的确定性问题；根据最终实现同步板块采集、数据管理、页面设计矩阵、数据字典等受影响事实文档，并生成同目录开发留痕和业务核查。
