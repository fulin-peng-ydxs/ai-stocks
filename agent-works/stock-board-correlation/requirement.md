> 文档版本：2026-08-27
> 上游闭环：[`requirement-closure.md`](requirement-closure.md)（已确认）
> 关联基础能力：[`concept-industry-board/requirement.md`](../concept-industry-board/requirement.md)
> 页面原型：不生成。本次只更新既有表格列和调度表单，不新增页面、不重排主要区域、不引入复杂跨区域交互。

## 1. 背景与目标

系统已经能够采集行业、概念板块字典、累计成分关系和板块指数，但股票列表、每日榜单、策略筛选目前不能快速回答“这只股票近期主要跟随哪个行业、哪个概念”。如果在页面请求期间逐股加载行情并计算，既会产生 N+1，也无法满足高频列表场景的毫秒级响应要求。

本需求建设“个股走势关联板块”公共能力：对每只股票已经累计收录的行业、概念候选，使用确定性日收益相关算法分别选出最相关行业和最相关概念。计算通过独立任务预先完成，页面只批量读取每只股票最多两条当前冠军结果。

业务目标：

1. 个股查询、每日榜单和策略筛选统一展示“走势行业”“走势概念”。
2. 行业与概念分别评选，结果带相关度、样本量、可信度和数据截止日期。
3. 页面查询不实时计算、不逐股补查，服务端批量读取达到可验收的毫秒级性能。
4. 任务成功才覆盖当前结果，失败继续使用上一次成功结果；不保留每日快照和全部候选相关性。
5. 严格保护历史日期：无历史快照时不得把最新结果展示到历史行情、历史榜单或回测链路。

## 2. 当前项目现状

### 2.1 数据基础

- [`backend/storage/ddl.py`](../../backend/storage/ddl.py) 已定义 `board_dict`、`board_member`、`board_bar`；`daily_bar` 提供个股日行情和复权因子。
- `board_dict.board_type` 已区分 `concept | industry`。
- `board_member` 主键为 `(board_code, code)`，按既有需求只进不出，表达“所有曾经进入过该板块的股票”累计关系，不表达当前有效成员时间线。
- `board_bar` 保存板块原始连续指数；个股前向收益与研究口径要求使用后复权，并统一使用 `COALESCE(adj_factor_clean, adj_factor)`。
- 行情、板块和拟新增结果均位于 DuckDB，可在同库完成批量计算；用户资产仍在 PostgreSQL，涉及分组列表时必须分别读取后在服务层按代码合并，禁止跨库 JOIN。

### 2.2 板块采集与调度基础

- [`backend/services/board_ingest.py`](../../backend/services/board_ingest.py) 已实现板块字典、累计成分、板块指数和资金流采集。
- [`backend/services/async_task.py`](../../backend/services/async_task.py) 已提供任务类型注册、DuckDB 写任务互斥、任务日志、取消/续跑和失败状态。
- [`backend/scheduler/scheduler.py`](../../backend/scheduler/scheduler.py) 已提供 daily/weekly/monthly/cron、交易日限制、依赖触发、延迟、失败重试、启停和立即执行。
- [`frontend/src/views/data/ScheduleView.vue`](../../frontend/src/views/data/ScheduleView.vue) 已有通用调度任务表单和运行入口。

### 2.3 查询与页面基础

- [`backend/api/stocks.py`](../../backend/api/stocks.py) 的 `/api/stocks` 提供可指定交易日的分页股票列表。
- [`backend/api/board.py`](../../backend/api/board.py) 的 `/api/board/run` 提供可指定 `run_date` 的每日榜单；`/api/board/compute` 被回测等历史链路使用。

- [`DESIGN.md`](../../DESIGN.md) 和 [`page-template.md`](../configurable-layout-system/page-template.md) 要求表格列、组件配置和页面登记保持统一事实源。

### 2.4 已确认业务边界

- 不保留每日相关性快照。
- 不保存约五万组候选板块相关性明细，只保存每只股票每种类型的冠军。
- 暂不在个股详情展示。
- 本次接受累计成分不能严格判断当前有效的限制。
- 计算注册为独立调度任务，执行频率动态配置。

## 3. 用户角色与使用场景

| 角色 | 权限边界 | 使用场景 |
| --- | --- | --- |
| 普通业务用户 | 沿用当前页面的 `stocks:view`、`board:view`、`screen:run` | 在个股列表、榜单或筛选结果中查看走势行业与走势概念 |
| 可查看板块用户 | 额外具有 `sectors:view` | 点击走势板块进入现有板块详情 |
| 无板块查看权限用户 | 无 `sectors:view` | 可看到当前股票行附带的板块名称，但不可进入板块详情 |
| 系统管理员 | `data-schedule:manage`、`data-task:manage` | 配置计算频率、依赖和重试，立即执行并查看日志 |

典型场景：

- 用户查看最新股票行情，快速识别股票近期更跟随哪个行业和概念。
- 用户查看最新每日榜单，在评分结果之外判断股票是否共同聚集于相同题材。
- 用户运行最新交易日策略筛选，使用走势板块摘要辅助二次判断。
- 系统管理员将相关性任务依赖于行情或板块任务成功后执行，并在失败时保留线上旧结果。

## 5. 详细功能需求

### R1 累计行业、概念归属查询

- **功能描述**：按股票代码查询 `board_member` 并关联 `board_dict`，返回累计收录的全部行业和概念。
- **输入**：单个股票代码；内部服务同时支持股票代码集合批量查询。
- **输出**：`membership_scope=cumulative`、成分数据最近成功时间，以及 `industries[]`、`concepts[]`；元素至少包含 `board_code`、`name`、`board_type`。
- **校验规则**：只返回 `board_dict` 中存在且类型合法的关系；结果按类型、名称、代码稳定排序并去重。
- **异常情况**：股票不存在或没有关系时返回空数组；不得回退 `stock_basic.industry` 冒充同花顺行业板块。
- **权限与数据范围**：复用 `stocks:view`；该关系是公共市场参考数据，不引入租户归属。
- **影响**：本次页面不展开全部归属，但接口契约为未来详情接入保留。

### R2 走势相关性计算与冠军评选

- **候选范围**：只计算 R1 累计归属中的板块；行业和概念分别评选。
- **行情截止日**：目标日不得晚于 `daily_bar`、`board_bar` 和市场基准均有有效数据的共同最新交易日；所有输入严格 `<= as_of_date`。
- **个股收益**：使用后复权收盘，复权因子统一 `COALESCE(adj_factor_clean, adj_factor)`，计算相邻有效交易日收益率。
- **板块收益**：使用 `board_bar` 原始连续收盘计算相邻交易日收益率。
- **市场中性化**：个股、板块日收益分别减去同日系统主基准收益；基准沿用 `backtest.benchmark_main`，当前默认 `000905.SH`。缺失基准日不进入共同样本。
- **窗口与样本**：短窗口为最近 20 个目标交易日，至少 15 个共同有效样本；长窗口为最近 60 个目标交易日，至少 40 个共同有效样本。两个窗口都达标才参与冠军评选。
- **极值处理**：每个窗口内，个股和板块的市场中性收益序列分别按 5%/95% 分位缩尾，再计算 Pearson 相关系数。
- **综合分**：`score = 0.6 × corr_20 + 0.4 × corr_60`；保存时保持足够精度，接口展示最多四位小数。
- **稳定决胜**：综合分降序，其次 60 日相关度降序、60 日样本数降序、板块代码升序。
- **低相关处理**：只要样本达标，最高者就是该类型冠军；低相关或负相关允许成为冠军，但可信度为低，页面不得用“高度相关”等误导措辞。
- **可信度**：高＝60 日样本不少于 50、综合分不少于 0.70 且 20/60 日同号；中＝60 日样本不少于 40且综合分不少于 0.50；其他达标结果为低。
- **空结果**：没有候选、行情不足、基准不足或所有候选样本不达标时，该股票对应类型为空。
- **算法一致性**：算法版本和本次实际使用的基准代码必须随结果保存，便于识别口径变化；窗口、权重、缩尾和样本下限是本需求固定的版本化业务契约，不允许不同调度任务各自修改后覆盖同一结果。

### R3 当前冠军结果与原子覆盖

- **保存规模**：每只股票每种类型最多一条，5000只股票上限约10000条；不保存非冠军候选结果。
- **核心字段契约**：股票代码、板块类型、冠军板块代码、综合分、20/60 日相关度、20/60 日有效样本数、可信度、基准代码、行情截止日、计算时间、算法版本。
- **主键语义**：`股票代码 + 板块类型` 唯一；板块名称从 `board_dict` 读取，不作为重复事实源。
- **全量覆盖**：先在非正式结果区完成计算和完整性检查，再在同一 DuckDB 事务内替换正式结果。成功结果中的合法空值必须删除该股票对应的旧冠军，不能继续显示已失效旧结果。
- **指定范围覆盖**：传入股票代码集合时，只替换该范围；该范围全部计算完成后一次提交，其他股票保持不变。
- **失败处理**：计算、校验或事务失败均回滚；正式结果和 `as_of_date` 保持上次成功状态。
- **无快照**：同一或不同交易日成功后都覆盖当前结果，不按日期追加；不承诺恢复任一历史日冠军。

### R4 异步任务与动态调度

- **任务类型**：新增稳定任务类型 `stock_board_correlation`，注册到任务执行器、DuckDB 写任务互斥集合、可调度任务集合和前端中文标签。
- **参数**：`codes` 可选，空代表全市场；`force` 可选，默认无新共同交易日时跳过，`force=true` 允许同日重算。非法、重复代码规范化后拒绝未知股票或返回明确跳过统计。
- **调度能力**：复用现有 daily/weekly/monthly/cron、仅交易日、上游任务依赖、依赖条件、延迟、失败重试、启停和立即执行。
- **推荐默认链路**：个股行情或板块采集成功后，以依赖触发方式执行；具体频率由系统管理员配置，不在代码中创建强制覆盖用户配置的重复默认任务。
- **任务状态**：日志阶段至少包含读取候选、加载行情、批量计算、结果校验、原子切换。
- **任务结果**：返回目标日期、目标股票数、候选关系数、行业冠军数、概念冠军数、空结果数、跳过数、失败数、计算耗时、写入耗时和是否切换成功。
- **权限**：创建、调度、立即执行、启停沿用现有 system-only 数据任务和调度权限，不新增普通用户操作入口。
- **并发**：作为 DuckDB 写任务与其他写任务互斥；读页面在计算期间继续读取上次正式结果。

### R5 读取契约、日期保护与性能

- **单股摘要**：返回行业冠军、概念冠军及统一 `as_of_date`；可与 R1 全部归属组合，但页面默认只消费摘要。
- **批量摘要**：输入去重后的股票代码集合，一次返回 `code → related_boards` 映射；空集合不访问数据库。
- **列表合并**：股票、榜单、筛选服务取得页面行后，一次批量查询并按代码内存合并；禁止逐行调用接口或逐行 SQL。
- **响应结构**：

```json
{
  "related_boards": {
    "as_of_date": "2026-08-26",
    "industry": {
      "board_code": "881121",
      "name": "半导体",
      "score": 0.82,
      "corr_20": 0.86,
      "corr_60": 0.76,
      "sample_20": 20,
      "sample_60": 58,
      "confidence": "high"
    },
    "concept": null
  }
}
```

- **日期保护**：调用方必须传其业务日期。只有业务日期等于冠军 `as_of_date` 时才合并冠军；日期不一致返回 `related_boards` 但冠军为空，并可带 `unavailable_reason=as_of_mismatch`。禁止用最新结果装饰历史股票行。
- **默认最新日**：页面未指定日期时，以其原接口实际返回的交易日作为业务日期，不以服务器自然日判断。
- **分组列表**：PG 读取用户分组资产、DuckDB 读取行情和冠军后在服务层合并，禁止跨库 JOIN；每行 `last_date` 与冠军日期不一致时该行为空。
- **性能目标**：本地预热数据库和不含公网传输条件下，单股摘要 P95 ≤10ms、50只批量 P95 ≤20ms、200只批量 P95 ≤50ms；列表增加冠军能力后不得出现随行数线性增加的数据库请求次数。
- **缓存**：DuckDB 当前结果为事实源；一期不强制引入 Redis。若实现进程内短缓存，键必须包含 `as_of_date/algorithm_version/benchmark_code`，且结果切换后可失效。

### R6 共享展示与权限

- **复用要求**：个股查询、每日榜单、策略筛选共同使用一个走势板块展示单元，统一处理名称、可信度、空态、悬浮说明、权限和跳转。
- **展示名称**：列标题固定为“走势行业”“走势概念”，与现有 `stock_basic.industry` 的“行业”和上市市场“板块”区分。
- **单元格**：只展示一个冠军板块名称；不得在表格中堆放全部概念。
- **说明**：悬浮内容包含综合相关度、20/60 日相关度、20/60 日样本和数据截止日；低可信度明确标注“相关性较弱”。
- **跳转**：具有 `sectors:view` 时跳转 `/sectors/:code`；否则使用不可点击文本，不弹出权限错误。
- **空态**：无冠军或日期不匹配显示“—”；日期不匹配的悬浮说明为“未保留该历史日期的相关性结果”。
- **页面配置**：三个页面的 `pageRegistry.componentMeta` 必须登记新增列；列显隐使用现有组件配置和用户偏好回退机制。

### R7 个股查询接入

- **普通查询**：`/api/stocks` 返回当前分页股票的冠军摘要；`StocksView` 普通查询表新增两列。
- **分组视图**：分组明细服务在资产与行情合并后批量附加冠军；`groupTable` 同步新增两列，避免同一页面切换模式后字段消失。
- **日期**：普通查询使用响应 `trade_date`；分组行使用各自 `last_date`。不一致时不展示。
- **原有列**：现有“行业”继续表示 `stock_basic.industry`，“板块”继续表示主板/创业板/科创板；不得静默改变旧字段语义。
- **排序**：本次不增加按走势行业、走势概念或相关度服务端排序，避免扩大分页查询口径；只支持列显隐和点击。

### R8 每日榜单接入

- `/api/board/run` 在得到榜单代码后批量附加冠军摘要；前端榜单表新增两列。
- `run_date == as_of_date` 时展示，否则为空。
- `/api/board/compute`、回测“查看买入当日榜单”及其他历史决策链路本次不附加最新冠军，避免未来数据污染。
- 不改变评分快照、榜单排名、评分档和分项分口径；冠军摘要只作展示附加信息，不进入评分模型。

### R9 策略筛选接入

- 筛选服务在 `screen_scored` 结果形成后对命中股票批量附加冠军摘要。
- `run_date == as_of_date` 时展示，否则为空。
- 筛选结果表新增两列并登记到 `screen.result` 可配置列。
- CSV 导出沿用当前页面结果数据；列可见时导出“走势行业”“走势概念”，无冠军为空，不输出内部相关度字段。
- 冠军摘要不参与筛选表达式、评分和排序；需要作为筛选条件时另立需求。

### R10 可观测性、质量和测试

- 任务中心能够按中文任务名筛选并查看日志、状态、参数、重试来源和结果统计。
- 数据概览或任务结果至少有一个可见入口说明最近成功 `as_of_date`、计算时间、覆盖股票数和空结果数；不要求新增独立页面。
- 结构体检覆盖结果表主键唯一、板块外键可解释、类型合法、分数有限、样本下限、日期不晚于各数据源最新日。
- 算法测试覆盖后复权、市场中性化、共同日期对齐、样本不足、缩尾、稳定决胜、负相关冠军和行业/概念隔离。
- 接口测试覆盖批量合并、空集合、历史日期保护、权限和无 N+1。
- 前端测试覆盖三页面列显隐、空态、悬浮信息、权限感知跳转和历史日期退化。

## 6. 数据与接口需求

### 6.1 数据流

```text
board_member + board_dict       daily_bar + board_bar + index_bar
             \                           /
              \                         /
               stock_board_correlation 任务
                           ↓
             当前行业冠军 + 当前概念冠军
                           ↓
       股票列表 / 每日榜单 / 策略筛选批量合并
```

### 6.2 当前结果数据契约

建议以独立 DuckDB 关系承载当前结果，逻辑名称为 `stock_board_correlation`。开发计划可在不改变以下业务契约的前提下确定 DDL 细节：

| 字段语义 | 必须性 | 说明 |
| --- | --- | --- |
| 股票代码 | 必须 | 对齐 `stock_basic.code` |
| 板块类型 | 必须 | 仅 `industry | concept` |
| 冠军板块代码 | 必须 | 对齐 `board_dict.board_code` |
| 综合相关度 | 必须 | R2 固定算法 |
| 20/60 日相关度 | 必须 | 用于解释和复核 |
| 20/60 日样本数 | 必须 | 用于可信度和质量校验 |
| 可信度 | 必须 | `high | medium | low` |
| 基准代码 | 必须 | 记录本次市场中性基准 |
| 行情截止日 | 必须 | 页面日期保护事实源 |
| 计算时间 | 必须 | 运维新鲜度 |
| 算法版本 | 必须 | 识别口径变化 |

关系规模不得随交易日累积，主键语义为股票代码与板块类型。

### 6.3 接口兼容

- 现有股票、榜单、筛选响应只新增可选 `related_boards`，不得改变原字段名称、排序、分页或错误结构。
- 无结果时使用 `null`，不得用空对象、零分或虚构板块填充。
- 单股全部归属及摘要能力挂在 `stocks:view` 权限域；若新增独立路由，必须同步资源 seed、路由扫描测试和前端类型。
- 新增任务类型必须同步后端任务白名单、写任务互斥、调度白名单、前端 `TaskType`、中文标签、筛选和调度任务下拉。

### 6.4 配置闭环

- **调度配置定义者**：系统管理员。
- **保存位置**：沿用 PostgreSQL `scheduled_job`。
- **读取与消费**：现有调度器加载后创建对应异步任务。
- **校验**：频率、依赖、延迟、重试和股票代码范围沿用服务端强校验；非法配置拒绝保存。
- **生效**：创建、编辑、启停后即时生效；停用取消等待事件的规则沿用现状。
- **回退**：删除或停用调度不删除当前冠军结果；页面继续显示最后成功结果及真实日期。
- **算法契约**：20/60 日窗口、0.6/0.4 权重、5%/95% 缩尾和样本下限按 R2 固定，不进入调度表单；算法调整必须更新算法版本并全量重算。市场中性基准运行时读取现有 `backtest.benchmark_main`，基准代码非法或行情不可用时任务失败且不切换正式结果。

## 8. 边界条件与异常场景

| 场景 | 处理 |
| --- | --- |
| 股票没有任何累计板块关系 | 行业、概念均为空，不算失败 |
| 只有行业或只有概念 | 有数据类型正常返回，另一类型为空 |
| 累计关系已经不是当前有效成员 | 仍参与候选；这是本次接受的已知限制，接口标记累计口径 |
| 板块字典存在但无板块指数 | 不参与冠军计算，全部归属仍可返回 |
| 个股停牌或交易日不完全一致 | 只取共同有效日；样本不达标则为空 |
| 基准指数缺数据 | 缺失日剔除；样本不足为空；整体基准不可用则任务失败不切换 |
| 相关系数为 NaN/无限值 | 该候选无效，不得写入正式结果 |
| 所有候选相关度很低或为负 | 仍选择最高且样本合格者，可信度为低 |
| 全量任务中部分股票合法空结果 | 成功覆盖，并清除这些股票旧冠军 |
| 任务执行异常或写事务失败 | 回滚并保留上次成功结果 |
| 页面业务日期晚于或早于结果日期 | 不展示冠军，不回算，不借用最新值 |
| 同日重复任务 | 成功后幂等覆盖；无 `force` 可跳过 |
| 两个调度任务同时触发 | 受 DuckDB 写任务互斥约束；按现有调度规则跳过或记录冲突，不并发写 |
| 用户无 `sectors:view` | 展示名称但不可点击 |
| 板块后续从字典消失 | 查询显示空或失效态；结构体检报告孤儿关系，任务不得返回伪造名称 |

## 9. 性能、安全与兼容性要求

### 性能

- 约5000只股票、平均10个累计板块形成约5万候选对；允许任务计算这些候选，但正式结果稳定在约1万行。
- 计算必须批量读取所需行情，避免为每个股票—板块对单独发 SQL。
- 列表接口按当前页代码一次批量读取，数据库查询次数不随股票行数线性增长。
- 达到 R5 的 P95 指标，并提供可重复的基准测试数据规模和报告。
- 临时数据和内存集合必须有明确生命周期，不保留无限增长缓存。

### 安全与权限

- 普通用户不能创建、修改或执行相关性任务。
- 股票列表、榜单和筛选继续 fail-closed；新增字段不得绕过原页面权限。
- 板块跳转按 `sectors:view` 权限感知，不以隐藏按钮代替后端保护。
- 新增接口或任务端点若改变路由集合，必须同步 `sys_resource` seed、默认角色授权决策和路由扫描测试。

### 兼容性

- 原接口调用方忽略新增可选字段时行为不变。
- 原列表排序、分页、评分、筛选和导出基础字段不变。
- 当前 `stock_basic.industry` 和 `stock_basic.board` 语义不变。
- 旧数据库初始化、升级和测试库都必须获得新增结果关系；升级只补缺失结构，不修改用户菜单、角色和页面配置。
- 算法版本变化后必须通过任务全量重算，不允许新旧算法结果混存但无法识别。

## 11. 验收标准

| 需求编号 | 验收标准 | 验证方式 |
| --- | --- | --- |
| R1 | 给定含行业、概念和孤儿关系的股票，只返回合法去重的累计行业/概念，并明确 `membership_scope=cumulative` | 服务单测、接口测试 |
| R2 | 固定行情夹具下，后复权、市场中性、20/60窗口、缩尾、权重、样本下限和稳定决胜结果与人工计算一致 | 领域单测 |
| R2 | 行业与概念分别评选；负相关但最高的合格候选可返回且可信度为低 | 领域边界单测 |
| R3 | 全量成功后每股每类型至多一行；连续多日执行结果行数不按日期增长 | DDL/服务集成测试 |
| R3 | 任务中途异常或提交失败后，原正式结果、日期和行数完全不变 | 事务失败测试 |
| R3 | 新一轮合法空结果会清除对应旧冠军，不产生陈旧残留 | 服务集成测试 |
| R4 | 调度页面可创建、编辑、启停、立即执行和重试 `stock_board_correlation`；任务日志及结果统计完整 | API、Vitest、聚焦浏览器自动化 |
| R4 | 全量和指定代码范围均能原子替换；与其他 DuckDB 写任务并发时遵守互斥 | 任务集成测试 |
| R5 | 50只、200只批量读取无 N+1，并达到10/20/50ms P95目标 | SQL 调用计数测试、性能基准 |
| R5 | 业务日期与结果日期不一致时冠军为空；历史榜单和历史筛选不出现最新冠军 | API回归测试 |
| R6 | 三页面使用统一单元格，悬浮字段、低可信提示、空态和权限感知跳转一致 | 共享组件 Vitest |
| R7 | 个股查询普通与分组模式都可显示/隐藏两列；旧行业和板块语义不变 | StocksView Vitest、接口测试 |
| R8 | 最新每日榜单显示冠军；历史 `/board/run` 为空，`/board/compute` 不注入最新结果 | Board API与页面测试 |
| R9 | 最新筛选显示并可导出名称；历史筛选为空且不即时计算 | Screen API、Vitest |
| R10 | 结构体检能发现非法类型、重复键、非有限分数、样本不足、未来日期和失效板块引用 | 结构体检测试 |
| R10 | 修改前端源码后构建通过，相关 pageRegistry 字段契约测试通过，关键点击链路通过专用端口 E2E | `npm run build`、Vitest、Playwright |

## 12. 建议开发顺序

### 阶段 1：算法与当前结果基础

- **覆盖需求**：R1、R2、R3。
- **目标**：先建立可重复验证的累计归属、相关算法和原子当前结果，避免页面先依赖未稳定口径。
- **前置**：板块字典、累计成分、板块指数、个股与基准行情可用。
- **里程碑**：固定夹具可计算约定冠军；连续日期覆盖不增长；失败可回滚。

### 阶段 2：任务与调度闭环

- **覆盖需求**：R4、R10 的任务部分。
- **目标**：把计算纳入现有写任务互斥、日志、动态调度、依赖和重试体系。
- **依赖**：阶段1已有可调用计算入口和明确事务边界。
- **里程碑**：系统管理员可配置并立即执行，全量及指定范围结果可观察。

### 阶段 3：通用读取与性能

- **覆盖需求**：R5、R10 的性能和接口部分。
- **目标**：形成单股/批量公共查询，完成日期保护和无 N+1 验证。
- **依赖**：阶段1正式结果稳定，阶段2可生产测试数据。
- **里程碑**：三档性能指标通过，历史日期保护测试通过。

### 阶段 4：渐进接入三个业务页面

- **覆盖需求**：R6、R7、R8、R9。
- **目标**：先落共享单元格和页面配置登记，再分别接入个股查询、每日榜单、策略筛选。
- **依赖**：阶段3提供统一响应契约。
- **页面关系**：三个页面共享展示组件，但保持各自权限和业务日期。
- **里程碑**：构建、Vitest、pageRegistry 契约和聚焦 E2E 通过；个股详情未发生改动。

### 阶段 5：第三方视角复审与事实文档同步

- **覆盖需求**：R1-R10。
- **目标**：按项目规则复查防未来函数、累计成员表述、双库边界、权限、页面复用、任务互斥、性能和异常回退。
- **里程碑**：无未修复的确定性问题；根据最终实现同步板块采集、数据管理、页面设计矩阵、数据字典等受影响事实文档，并生成同目录开发留痕和业务核查。
