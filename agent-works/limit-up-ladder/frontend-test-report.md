## 8. T16 轮询恢复增量验收

- 新增天梯领域轮询策略：以交易日和 PG command 组成稳定任务标识，task_id 变化不重置周期；间隔按 1.5/3/6/12 秒指数退避并封顶 12 秒，最后一档按剩余时间截断。页面使用单调时钟和独立 120 秒截止定时器，使到期时尚未返回的慢请求失效；无快照显示可重试错误，有旧快照则保留旧结果并在过期提示中说明超时。
- 轮询策略、天梯组件与页面共 20 项 Vitest 通过。4 项页面假时钟/deferred Promise 用例直接验证：120000ms deadline 写入超时且停止后续请求；在途慢响应随后 resolve 不能覆盖超时；相同 command_id、不同 task_id 不重置周期；新 command_id 从切换时重新获得 120 秒周期。纯策略用例继续覆盖退避上限、稳定命令键、119999ms 只等待 1ms、全部定时器累计恰为 120000ms 和到期不再续发决策；`npm run build` 通过并同步 `frontend/dist`。
- 5181 Playwright 对 `limit-ladder.spec.ts` 与 `limit-ladder-analysis.spec.ts` 使用真实 `debug_system` 登录、`--workers=1` 执行，6 项通过、6 项按视口约束跳过；首次计算态自动收敛到正常数据态，既有筛选、CSV、详情和响应式无回归。
