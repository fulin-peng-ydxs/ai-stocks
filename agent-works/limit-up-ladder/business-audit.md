## 模块与业务功能说明

本次核查覆盖点时涨停规则与 ST 治理、完整性门禁与不可变快照、三来源单日重算、热点/筛选/CSV 查询、页面与分析详情、个人偏好、任务中心、RBAC 和部署回滚。历史相关性快照已作为上游能力按日消费；其余后续项未提前开发。

## 本次改动对应的业务链路

### 1. 入口

- 登录用户通过菜单与 `/limit-ladder` 路由进入页面；读取接口统一要求 `limit-ladder:view`。
- 首次读取、失效刷新和 system-only 管理员重算进入同一个日期任务协调器。
- 日线采集、基础信息/ST/板块归属变更按受影响日期标记快照失效。

### 2. 核心处理

- 完整性门禁闭合后，计算器按统一市场涨停规则和点时 ST 状态批量计算；连续板回溯不受 60 日展示窗口截断。
- DuckDB 以不可变版本写入快照明细、概念和聚合，最后原子切换日期状态指针；失败不删除最后成功版本。
- PG 日期账本协调自动首算、失效刷新和管理员重算，审计 outbox 将冻结的权威主体与请求信息幂等投递到 `audit_log`。

### 3. 对外输出或下游联动

- 查询、摘要、热点、筛选和 CSV 共享同一天梯快照及选中交易日同日走势相关行业/概念口径。
- 页面复用统一主从工作台、股票分析、详情返回上下文和用户偏好骨架；低高度桌面把摘要、热点和梯级置于同一成长滚动区，窄屏继续使用页面内全屏抽屉。
- DuckDB `async_task/task_log` 继续作为任务中心执行事实；PG 只保存跨来源协调与可靠审计事实，两库不跨库 JOIN。

### 4. 异常或补偿路径

- 未完整、非交易日、计算中、失败、过期旧结果、合法空、筛选空和 403 均有独立业务码与页面状态；403 使用无重试 permission 反馈。
- 同日活动任务由 PG 部分唯一索引和协调器复用；重启后先收敛 DuckDB 残留任务，再对账 PG 活动态与 outbox。
- 发布回滚对未投递审计、账本外授权、额外子节点和共享字段复用 fail-closed；DuckDB 历史默认保留。

## 核查结论

- 结论等级：通过本地开发验收；生产上线仍受正式数据副本演练门禁约束。
- 证据强度：confirmed。
- 结论说明：数据、任务、权限和部署闭环均通过本地验收；专项 SQL 与应用初始化可把带旧行、既有日期索引的 T16 快照表升级到与新库一致的关键列契约。T18 已进一步关闭低高度主体不可见、卡片按钮语义、无效焦点、长文本、403 重试入口及排版/按钮/间距契约问题，没有改变后端接口、权限码或数据结构。
- 剩余盲区：尚未在正式生产数据副本执行迁移与首日计算；生产历史 ST 近似数据比例、正式备份恢复时长和实际资源峰值需上线演练确认。

## 已确认问题

无本地开发范围内未关闭项。T17 关闭历史依赖传播、失效失败静默成功、空上市日股票池偏差、过期快照窗口指标混用和存量库升级分叉；T18 关闭低高度主体不可见、卡片交互语义、403 权限态及设计契约问题。

### 本次部署缺口根因

- 计划并非完全没有要求：T2 完成标准已写“新库和存量库可安全升级”，因此实现交付时只验证新库，首先是执行和自审遗漏。
- T17 增加 `window_metadata_json` 时，阶段验证清单只写了 DDL 幂等和新库九表演练，没有把“上一版本真实表结构 + 既有索引 + 旧行 + 两条升级入口约束一致”拆成强制用例；这属于计划细化不足，使遗漏没有被门禁及时发现。
- 后续稳定规则：任何存量表新增列或修改约束，均同时验证新库 DDL、应用启动迁移、专项 SQL、旧行回填、依赖索引、二次执行和最终 `information_schema` 契约，不能再以空库 `CREATE TABLE IF NOT EXISTS` 代替版本升级证明。

## 待业务确认的问题

无。历史概念归属按 `first_seen_date IS NULL OR first_seen_date <= T` 生成并固化；该规则兼容存量数据并排除明确未来成员，但仍不虚构成员移出时间线。
